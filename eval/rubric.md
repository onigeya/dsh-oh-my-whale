# 盲判口径

> 这份文件是 `epics.md:1069-1082`（Story 4.4 的 AC）与 `acceptance.md:15`（SM-2）要求的判定规则。
> 它必须回答两个问题：**判什么**、**多少分算过**。凡是不落到数字或封闭取值上的措辞，都不算口径。

## 零、这份口径管两件事

| 编号 | 判什么 | 判定对象 | 及格线 | 谁判 |
| --- | --- | --- | --- | --- |
| **A**（SM-2） | 20 条治理三问的答案**齐不齐、读不读得懂** | `test/fixtures/governance-20.jsonl` | 机械 20/20；人工逐条无「读不懂」 | 机械部分由脚本判，人工部分由盲判者判 |
| **B**（SM-1） | 50 条抽样记忆**该不该记** | `eval/golden-l1.jsonl`（Story 4.4 交付） | 加权准确率 ≥ 0.80 | 盲判者 |

两件事必须写在同一份口径里，因为它们是同一套盲判协议的两个用途：A 判「答得出吗」，B 判「该记吗」。
分开写会出现两套不一致的防泄露规则，而这两件事的失效方式恰好一样——**判定人提前知道答案**。

**本文件不做什么**：不定义抽取提示词（那是实现），不定义样本怎么抽（那是 Story 4.4 的 spec），
不承诺「大部分通过就算过」（见第七节）。

## 一、A 的机械判据：齐不齐

脚本逐条执行 `/omw-explain <mem_key>`，一条同时满足下面九项才算通过。缺一项即该条失败，**不许部分得分**。

| # | 判据 | 怎么验 |
| --- | --- | --- |
| M1 | 三个答案同时出现，不是分三次命令拼出来的 | 一次调用的输出里三问都在 |
| M2 | **谁改的**：`actor` + `ts` 都在，且 `actor ∈ {user, model, seed, system}` | 与 fixture 的 `expected.who` 逐字段相等 |
| M3 | **依据什么**：`session_id`、`seq_from`、`seq_to`、`quote` 都在，且 `quote` ≤200 字符 | 与 `expected.basis` 逐字段相等 |
| M4 | **为什么**：`kind`、`reason` 都在；`kind` 落在封闭六值内 | 与 `expected.why` 相等 |
| M5 | 结构性四键齐：`op_id`、`affected[]`、`target_mem_key`、`contract_version` | 对齐 `DecisionView`（`src/core/decisions.ts:165-183`） |
| M6 | `expected.decision_keys` 里列的每个键都出现；未列出的可选键**不冒充**必填 | 见 `eval/README.md` 第三节 |
| M7 | 自曝标记不被吞：`quote_truncated`、`deidentified`、`expired` 为真时必须显式出现 | G20-13 / 14 / 16 专测 |
| M8 | 单条从执行到看到三问 ≤30 秒 | 见 `eval/governance-20.md` 第二节的计时口径 |
| M9 | **零写入**：本轮前后库内节点字节一致、审计无新增写行 | `Story 3.1` AC⑦、`FR-4` |

20 条全过 = **20/20**。允许的失败数：**0**。

## 二、A 的人工判据：读不读得懂

SM-2 原话是「人工只判答案读得懂，不判查得到」（`acceptance.md:15`）——所以人工这一栏**不给分，只给通过/不通过**，
因为「读懂」不是连续量，把它折成百分比只会造出一个假精度。

判定人看到的材料，只有两样：

1. 查询命令（一行，如 `/omw-explain assertion:Elliott:works_at`）；
2. 机器输出（原样，不加工、不排序、不美化）。

**判定人不能看到**：`pins`、`expected`（含 `decision_keys`、`sample_answer`）、fixture 之间的分组与设计意图。
为什么连 `sample_answer` 都不给——它本身是「标准答案的写法」，看过它再判「读不读得懂」等于判自己。详见第五节。

判定时逐条回答四个封闭问题，四个都是「是」才算**读得懂**：

| # | 问题 | 典型的不通过长相 |
| --- | --- | --- |
| R1 | 三个答案是不是都能读出来，而不需要我再执行一遍别的命令去凑？ | 「为什么」一栏只写 `supersede`，其余留白 |
| R2 | 每一句话是不是都能指向库里一个真实字段，而不是解释性措辞？ | 「系统认为这样更合理」——没有任何字段支撑 |
| R3 | 有没有出现节点 id 或其它只在库内成立的内部标识？（`op_id` 例外，它是 AC 要求的一部分） | 输出里出现 `node:7f3a…` |
| R4 | 有没有「大概 / 看起来 / 应该」这类无依据的软措辞？ | 「这条大概是用户改的」 |

任一条判 R3 或 R4 不通过，该条**同时**计为机械通过、人工不通过——**这两栏分开记，不许合并成一个总分**。

## 三、B 的口径：该不该记

### 3.1 判定类别（二值，外加一个不进分的子类）

每条样本只能落进下列之一：

| 判定 | 含义 |
| --- | --- |
| **该记**（positive） | 这条内容值得进记忆层：它是稳定的、以后会用到的事实或偏好 |
| **不该记**（negative） | 不该进：一次性的、临时的、可从别处推回的信息，或私密到不该落盘 |
| **该记但形态错**（子类，不进 FP/FN 矩阵） | 值得记，但 kind / 归一化 / 证据指针错了 |

第三个子类**不参与及格线计算**，但必须单独计数并出现在报告里。理由：把「记对了但记成另一种样子」算成假阳性，
会让一个本来答得对的系统看起来更差；而直接丢掉这个信号，又会让形态错误永远不被发现。两头都不对，所以单列。

### 3.2 假阳性与假阴性分开统计（这是硬要求）

记系统实际写入为「落」，判定人的结论为「应落」：

| | 应落 | 不应落 |
| --- | --- | --- |
| **落** | TP | **FP**（错记） |
| **不落** | **FN**（漏记） | TN |

`epics.md:1026` 要求「假阳性与假阴性分开计数」——两份数不许先加总再报。

### 3.3 及格线：按假阳性加权，且是数字

```text
加权准确率 = (TP + TN − 2 × FP) / N        及格线 ≥ 0.80      N = 50
原始准确率 = (TP + TN) / N                 同时报，不单独作及格判据
```

一条错记的代价按两条漏记计（`SM-1` 原话：「错记比漏记更贵」）。取 2 倍是本文件首次定值的系数——
上游只说了「按假阳性加权」，没给权值；Story 4.4 若有异议，改这里并同时改本节的算例。

**算例**（N=50，剔除不可判样本后不足 50 条时按实际 N 重算，并在报告里写明 N）：

| 情形 | TP | TN | FP | FN | 加权 | 原始 | 判定 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 全对 | 40 | 10 | 0 | 0 | 1.00 | 1.00 | 过 |
| 错记 3 条 | 40 | 7 | 3 | 0 | 0.82 | 0.94 | 过 |
| 错记 4 条 | 40 | 6 | 4 | 0 | 0.76 | 0.92 | **不过** |
| 漏记 5 条 | 35 | 10 | 0 | 5 | 0.90 | 0.90 | 过 |

这张表说明这条线的真实严厉程度：**最多 3 条错记**。它同时是「为什么原始准确率不能当及格线」的证据——
第 3 行原始 0.92 看着漂亮，加权 0.76 已经不及格。

### 3.4 五十个样本的分辨力，必须写在报告里

N=50 时 95% 置信区间约 **±11 个百分点**（`SM-1` 原文）。所以报告必须同时给出：

- Wilson 置信区间（不要用正态近似：样本量小、比例接近 1 时正态区间会越界）；
- 「离 0.80 多远」的具体差值。

只报「过线」的措辞不算合格报告：0.81 与 0.99 在 N=50 下并不是两件事。

### 3.5 抽样必须预注册

50 条按时间分层：近 7 天 20 条 / 7–30 天 20 条 / 30 天以上 10 条（`SM-1`、`epics.md:1066`）。
抽样种子写进 `eval/golden-l1.jsonl` 的文件头；样本集**冻结后不许替换**。
换一次样本集等于换一次测量，报告里必须写「第几次测量」，不能与上一次直接比。

## 四、单人情境：盲判做不成时的替代条款

这个产品只有一个验收人，第二评判人造不出来。`SM-1` 已经把这条写成可见的局限而不是假装做到了，口径照抄：

| 项 | 要求 |
| --- | --- |
| 重判间隔 | **≥7 天**（两次判定之间不允许看到上一次的结论） |
| 一致性阈值 | 两次判定逐条比对，一致率 **≥90%** 才算「判定稳定」 |
| 报告义务 | 必须逐字注明「**非独立盲判**」，并写出两次判定相隔几天 |

一致率 <90% 时，**不是**取两次的平均值交差，而是判这次测量无效：口径本身不够清楚，先改口径再审。

## 五、防泄露的盲判协议

盲判失效几乎从不发生在判的人身上，而是发生在**材料发给他的那一刻**。所以协议管的是材料，不是判者。

| 步 | 做什么 | 为什么 |
| --- | --- | --- |
| 1 | 从库/输出里**原样导出**待判记录的 `mem_key` 与三问字段，另存为独立文件 | 判者只看这一份，不打开 fixture 文件 |
| 2 | 导出时**剔除** `pins`、`expected.*`、分组标号与设计注释 | 这些字段里有预设结论 |
| 3 | 判者先判完、写下结论，**再看**对照答案 | 顺序反了就不是盲判，是核对 |
| 4 | 判定记录与导出材料一起落盘，日期与判定人写清 | 可复现；不落盘的判定等于没判 |
| 5 | 重判时**不提供**上一次的记录 | 见第四节的 ≥7 天条款 |

一个可以自查的信号：如果判者看完材料就能说出「这条是想测截断」，说明第 2 步没做到。

## 六、判定记录要长什么样

每条一条记录，字段固定。缺字段的记录不计入统计（宁可不计入，也不要事后补一个看起来合理的值）：

| 字段 | 取值 |
| --- | --- |
| `fixture_id` | `G20-01`…`G20-20`（A 用）或 `L1-001`…`L1-050`（B 用） |
| `judge` | 判定人标识 |
| `judged_at` | ISO-8601，含时分 |
| `readable` | `pass` / `fail`（A 用）+ 命中的 R1–R4 编号 |
| `verdict` | `should` / `should_not` / `should_but_wrong_shape`（B 用） |
| `reason` | 一句话，必须指向具体字段或具体措辞 |
| `measurement_round` | 第几次测量（换样本集即 +1） |

## 七、本口径不接受的写法

下面六句都能写进报告，但都不构成一次判定。看到它们，这次测量按未执行处理：

1. 「整体看起来还行」——没有数字。
2. 「大部分都能答出来」——「大部分」不是阈值。
3. 「和上次差不多」——没有哪一次测量。
4. 「人工判断通过」——人工判的是哪一条、哪个 R 问题。
5. 「2 条失败，但属于边缘情况」——失败就是失败，边缘情况写进报告，不抵扣。
6. 「已经明显比 v1 好」——基准换了，不可比。

一句话收口：**这份口径只认两种结论——数字过线，或明确写出为什么这次不算数。**
