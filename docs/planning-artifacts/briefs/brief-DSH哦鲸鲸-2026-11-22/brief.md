# 产品简报：哦鲸鲸

## 一句话定位

一个跑在 DeepSeek Harness 里的数字助理插件。第一版只解决一件事：**让它记住的东西靠得住——记得进、改得动、忘得掉、查得到。**

不是“记得更多”。九家对标里记得更多的都做完了，记得住的一个没有。

## 问题

**宿主层面的三个硬事实（已实测）**

1. DSH 的会话日志是 append-only 的唯一日志（跨进程单写者租约，活跃会话由生命周期 owner 持有，他人写会抛 `SessionAlreadyOwnedError`）。同进程内我们其实写得了（`Session.append()` 是公开 API）；**不写是架构自选**，不是宿主强制。记忆因此落在插件自有存储。
2. 上下文压缩是“遮蔽”而不是删除——原始事件仍在日志里，但**核心 compaction 没有反压缩 API**，反压缩是外部插件 billion-context 的能力。所以“压缩完就找不回来”不是宿主的必然，是当前没人接住。
3. 机器上已经装了 `dsh-mnemon`：每轮注入 USER.md / MEMORY.md + 按需召回。**“记不住”不再是空白点**——只做“注入更勤”的插件没有存在理由。

**行业层面的四个共性缺陷（9 家对标，逐条有 digest 与行号）**

1. **只增不减**：Mem0 的 OSS 版没有 decay（平台版才有）；TencentDB 全仓无 halfLife；nmem 全仓 grep `half-life` 无结果。
2. **遗忘不可撤销**：nmem 的所谓遗忘是**静默硬删**，用户在 issue #882 里当 bug 报，零删除事件、不可恢复。
3. **召回即写入**：CerebroCortex 每次 recall 给 top-k 记 access 并升 stability、无最低分阈值；elo-memory 的 `_retrieval_count` 只加不减。结果是记忆被检索次数多的条目占据，而不是真正重要的条目。
4. **冲突无处裁决**：nmem 只标记（Flags）不提议；Mem0 干脆不裁决（只 ADD）；TencentDB 让 LLM 裁决但没有回滚。**三者兼得的一家都没有。**

## 方案

第一版是一个**分层记忆栈 + 离线固化 + 治理面**。每一层都标明抄自谁、搬的时候改了什么——没有一条是凭想象来的。

**分层**（抄结构，不抄复杂度）
- L0 原始层：宿主会话日志本身（append-only、我们不复制），永不进上下文，只存 `{session_id, seq 区间, ≤200 字短引文}` 指针。
- L1 原子记忆：一句话事实/偏好/决策 + 类型 + 重要度 + 来源指针（session id + seq 区间）+ 有效期。
- L2 场景/主题：`episode` + `scene` 节点，由 dream 生成；按需召回，永不常驻。
- L3 画像：`assets/persona.md` 身份文件（字节稳定、随插件发布）+ 可治理的 `pref` 节点。不整篇重写——整篇重写每轮击穿前缀缓存，且单条偏好失去来源。
- 存储：单文件 TriviumDB（图 + 全文 + 向量同库），不设存储适配层；向量由外部 embedding 异步补写，写入不等向量。

**写入**（抄补丁表，不抄全量重灌）
- 三个入口：agent 显式工具、用户命令、会话结束的去抖抽取。
- 抽取：把已有记忆连同稳定 id 交给模型，**一次调用产出一张 insert / update / supersede 补丁表**（没有 delete op——删除就是打 `superseded_at`）；写回前比对内容是否真变（LangMem）。
- 裁决：三级（自动 / 提案挂起 / 人工解除），只有自动档会改数据。符号可判的（同一谓词、有效区间重叠、归一化值不同）直接落成「新版本 + 旧版本打 `superseded_at` + 一条 `contradicts` 边 + 已解决的 flag」，理由是整条操作可撤销；其余一律只**提议**、挂起待人确认（nmem 的 Flag、elo-memory 的软删除、TencentDB 的 LLM 判决，三者各取一项）。

**固化（dream）**（抄阶段与预算，不抄模型堆叠）
- 触发：夜间窗口优先，宿主不在线则下次启动补跑当天一次；幂等靠「周期标记已存在即完成」，错过不补历史多天（OpenReverie）。
- 八步：确定性结算 → 重放抽样 → 模式提取 → 场景抽象 → What-If（v1 默认关闭）→ 剪枝归档（可回滚）→ 跨主题重组（产出必须能解析到真实记忆 id，否则丢弃）→ 策略提炼。① 结算、② 抽样、⑥ 剪枝、⑦ 重组不调用模型。
- 模型分工：③④⑤⑧ 一律「先提炼（Qwen/Qwen3.5-9B）后核验（deepseek-ai/DeepSeek-R1-0528-Qwen3-8B）」，核验不过则该步不提交、整体停在段边界；② 召回重排的 System One 用 `SemIf` 打 score 分，剪枝按阈值与 top-k 确定性执行。
- 每轮 LLM 调用硬上限并按阶段切分；逐阶段写日志，可断点续跑（CerebroCortex）。
- 种子写进产物，`--dry-run` 可只跑选择阶段——**事后能回答“为什么挑了这条”**。

**衰减与晋升**（抄阈值，不抄双套理论）
- 晋升与归档：不靠热度写回。热度只作读时排序因子（不落库、不改存储位置）；晋升与归档是 dream 的确定性步骤，结果写进 `dream_log`。
- 衰减：幂律 + 对数 rehearsal 作为排序因子，不改变存储位置（elo-memory）；FSRS/ACT-R 留到 v2。
- **检索只读**：召回不写回任何计数。

**治理**（这一版的主张，三件套）
- **版本链**：每条记忆可回溯它替换了什么、被谁改过、哪版 prompt 生成。
- **Flag**：矛盾 / 过期 / 无据断言三类，机器主动标记并提议处理方式，人可 dismiss / acknowledge / link。
- **软删除**：删除与归档一律留 tombstone，拒绝静默硬删，可完整回滚。

**检索**（有界即纪律）：混合召回（向量 + 图 + 全文），三段预算 250 + 600 + 20ms、合计硬上限 1000ms；默认 5 条、硬上限 8，重排每问至多一次，禁止 offset 循环，宁可报“证据不足”。全部可导出为纯文本 markdown，可读、可 diff、可退出。

## 凭什么不同

**不是“我们也能记”，而是“我们敢让你查账”。**

1. **可撤销的遗忘**：0/9 做到。软删除 + tombstone + 版本链，任何一次“它怎么忘了这个”都能追到具体那次决策。
2. **LLM 提议、人裁决**：0/9 兼得。机器不擅自改你的记忆，只把矛盾和过期写成待办。
3. **召回只读**：修掉样本里最普遍的富者愈富，代价是排序质量必须靠真信号而不是靠访问次数堆出来。
4. **生成式固化而非参数式**：样本里声称做参数式的那家，代码里根本没接上。我们不吹做不到的事。
5. **本地纯文本可导出**：退出成本为零——这在记忆类产品里是被验证过的信任来源（AGENTS.md、Letta MemFS 都走这条路）。

## 服务对象

**第一用户是 Elliott 自己**（2026-11-23 确认：SM-1 盲判口径定为「承认就是单人、隔 ≥7 天重判」，即验收人就是使用者本人；不再是推断）。判断标准很朴素：三个月后回来看，能不能说清“它记住了什么、为什么记、我怎么改”。

**次级用户**：DSH 上其他需要长期上下文的用户——v1 不为他们做多租户、权限、团队共享。

## 成功标准

四条全要，但**分阶段**。对标项目的数字全部不可复现（Mem0 的 92.5 是厂商自测平台口径、MemoryOS 的 F1 +49.11% 无人复现），所以指标自建、口径写死（细则见 `addendum.md`）。

| # | 标准 | 阶段 | 达标线 |
|---|---|---|---|
| 1 | 记忆准确率：抽 50 条 L1 人工盲判“该不该记” | v1 建评测集与口径 / v1.5 验收 | ≥80% |
| 2 | 可治理性：任一条记忆答清“哪来、谁改、为何还在” | v1 末 | 20/20 在 30 秒内答清 |
| 3 | 遗忘可回滚：归档/删除可完整撤销 | v1 末 | 10/10 零残留 |
| 4 | 注入成本受控：常驻注入 token 与缓存命中率 | v1 建监控与基线 / v2 起设线 | token 增长受对数约束，命中率下降 < 10% |

**顺序**：v1 先兑现 2 和 3——治理是差异化，也是最快能被外部检验的；1 的评测集在 v1 内建起来；4 只建监控，因为样本里没有一家给过可信的注入成本数据。

## 范围

**v1 内**：L0–L3 分层、写入补丁表、八步 dream（① 结算 / ② 抽样 / ⑥ 剪枝 / ⑦ 重组不调模型，⑤ What-If 默认关闭）、归档与晋升、治理三件套、三段有界检索、纯文本导出。

**v1 外**：参数式 dream（训练回路）、多租户与团队共享、跨设备同步、图谱推理问答、独立 App。

## 愿景

如果它成了：记忆变成一份**你可以审计的资产**，而不是一个你只能祈祷它别忘了的黑箱。下一步才谈“助理的人格”和“主动帮忙”——在没有可信记忆之前，那些都是表演。
