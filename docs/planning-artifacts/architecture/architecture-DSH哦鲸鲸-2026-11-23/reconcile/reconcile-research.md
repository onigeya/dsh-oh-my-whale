## F1 [high] 主动搭话的 Deferred 建立在与研究相反的宿主判断上

**骨架位置**：`ARCHITECTURE-SPINE.md:256`（Deferred 行）；对照 `:7`（scope 已声明不含主动搭话）。

**源文稿位置**
- `research/technical-anthropomorphic-companion-agent-persona-2026-11-22/research.md:83`：宿主级 Schedule 持久任务，七种时序，支持「复用会话 / 新建会话 / 每次新建」；`:90`："「主动」不是能力问题而是节流问题：Schedule 现成，难的是决定何时**不发**"；`:280-282`（C3）：默认值应是"低频 + 强门控 + 可配置静默"；`:328`（P0-#3）：主动消息门控链 + 硬退避，理由"没有门控就是骚扰"。
- `research/technical-output-humanization-anti-slop-voice-laye-2026-11-22/research.md:116-117`：[38] schedule 三种目标、每任务 ≥60s、Host 必须常驻、宕机只补最近一次——即"投递"语义存在，只是有代价。
- 设计稿已经把这条排进里程碑：`plugin-design-triviumdb-v2.md:158`（门控链 + 硬退避，连续未回复降频两级后暂停）、`fusion-design-v1.md:80`、`:90`（S4 人格验收含"连续未回复时确实降频"）。

**冲突**：骨架把延后归因为"需要宿主的「投递」语义；定时唤醒会与会话生命周期冲突"，而源文稿的实测结论正相反——投递能力在（三种目标），难点是节流与打扰成本；且"不发"（门控 + 硬退避）被两条研究线同时列为 P0/"不做就会出事故"。按骨架实现，v1 不会留下任何"何时不发"的纪律位；重启条件"投递可用"也永远不会被触发，因为投递已经可用。

**建议**：把该行的"为什么可以等"改成真实理由（v1 无可靠关系状态与打扰成本模型；且人格必须先有可信记忆），并把"概率×情绪×沉默 → 日上限 → 安静时段 → 事件直通 → 连续未回复降频至暂停"作为重启时必须满足的门控不变量写进 Deferred 或单列一条 AD。

## F2 [high] AD-10 的"统一提交"使断点续跑不可能，"8 步"也从未被定义

**骨架位置**：`ARCHITECTURE-SPINE.md:101`（AD-10 Rule）。

**源文稿位置**
- `memory research.md:110-112`（洞察 6）：桌面插件里 dream 最容易出的不是效果不好，而是**重复跑、跑一半、跑完不知道改了啥**；分别由 CerebroCortex 的逐阶段 `dream_log` 断点续跑、OpenReverie 的"产物即完成 + 种子可重放"各解一半。
- `memory research.md:156-157`：逐阶段写 `dream_log`，可断点续跑；种子写进产物 frontmatter，`--dry-run` 只跑选择阶段。
- `dreaming research.md:132-134`：种子写进产物、"为什么挑了这条"可事后回答、幂等靠周期标记、错过不补做、dry-run 只跑锚点采样与候选生成。
- `addendum.md:47`（断点续跑 ← CerebroCortex `dream.py:230-257, 921-938`）、`:63`（确定性种子 + 产物即完成标记 ← OpenReverie）。
- 设计稿已按此实现口径写死：`plugin-design-triviumdb-v2.md:129-144`（八步：①确定性结算 ②候选选取 ③模式提取 ④场景抽象 ⑤What-If ⑥剪枝归档 ⑦跨主题重组 ⑧策略提炼；"每阶段写 `dream_log` 节点，可断点续跑；种子写进产物 `payload.seed`"）、`fusion-design-v1.md:69, 108`。

**冲突**：三重。
1. "每步产出 diff 后统一提交"与"逐阶段 dream_log 可断点续跑"在机制上互斥——只有最后一次性提交，中途崩溃就丢失全部已完成步骤，正是源文稿点名的"跑一半"。
2. AD-10 说"8 步顺序固定"，却只枚举了前 3 步（合并、收敛、失效结算），其余 5 步在骨架里不存在；而设计稿的八步是"①确定性结算 ②候选选取"，与骨架的前 3 步既不同名也不同序——这条 Rule 既不可实现也不可校验。
3. 抽样种子与"dry-run 只跑选择阶段"（可复现性的全部内容）在骨架里无任何落点，`dry-run` 被降格成"只出 diff"。

**建议**：AD-10 改为"每步产出 diff 并在该步结束时以独立事务提交（`dream_log` 节点记录阶段、输入摘要、种子、diff 与结果），支持从最后一个完整阶段续跑；统一汇总只用于对外报告"，并显式列出 8 步名称与顺序（与设计稿对齐）。

## F3 [high] "治理 20/20 可答"的落点缺决策层溯源，AD-5 + AD-9 答不出"谁改、为何还在"

**骨架位置**：`ARCHITECTURE-SPINE.md:249`（成功标准落点："治理 20/20 可答 → AD-5 + AD-9"）；`:95`（AD-9 Rule）；`:232`（flag 只 `about` 断言，无 actor/理由）；`:161`（AD-20 审计只覆盖注入、召回、dream 汇总）。

**源文稿位置**
- `ontology research.md:148`（判读）："溯源要分两层——**证据层**（从哪来）与**决策层**（谁在何时基于什么把它升/降/合并）。多数项目只做前者，Utopia 把后者也做了，这正是'知识是演化信念'最需要的部分"；`:145`：决策账本 + 先例式裁决，缓存键含先例，"人被裁一笔，旧答案自动作废"；`:194`（L4 双账本）。
- `memory research.md:170-173`：Flags 三类（矛盾/过期/无据断言）可 dismiss / acknowledge / link；版本链要能回溯"它替换了什么、被谁改过、**哪版 prompt 生成**"。
- `brief.md:89`（成功标准 2）："任一条记忆答清'哪来、谁改、为何还在'，20/20 在 30 秒内答清"；`:61`（Flag 三类 + 人工三操作）。

**冲突**：AD-6 给了证据层（指针 + flag），AD-5 给了时间戳（何时失效），AD-9 给了"符号自动 + 人工"两档——但没有一条要求记录**决策主体与理由**（actor、依据、先例、生成它的合同/prompt 版本）。更关键的是 AD-9 规定"人工档是解除挂起态的唯一路径"，那么每次冲突都要人重新裁一遍：没有"人裁一次即成为先例"的机制，判例缓存被结构性地排除了。结果 `:249` 宣称的 20/20 可答无法用 AD-5 + AD-9 兑现——"谁改"没有字段，"为何还在"没有理由。

**建议**：加一条 AD（或在 AD-9 内）要求每次状态变更写一条决策记录 `{ts, actor, kind, from, to, reason, precedent_id?, contract_version?}`，并允许"已有人工判例 + 同形态冲突"复用先例自动处置（先例可撤销）。

## F5 [medium] "技能自演进"的 Deferred 把可行路线与不可行路线说反了

**骨架位置**：`ARCHITECTURE-SPINE.md:257`（"DSH 无 logprobs/logit_bias/n，只能多采样重排"）、`:260`（参数化学习："JitRL 类做法只能做候选重排"）。

**建议**：改为"DSH 无 logprobs/logit_bias/n，候选重排不可用；可行路线是版本化的文本策略对象 + `systemPrompt.context` 注入 + 同验证集闸门（z-score + margin，通过才原子替换，失败保留原版）"，并把"门控"定义为该接受闸门而非边界闸门。

## F6 [medium] whatif 的 Deferred 用一条源文稿已经回答过的担忧关掉了 v1 该做的事

**骨架位置**：`ARCHITECTURE-SPINE.md:258`（"v1 只建表与结算字段，生成默认关闭；争议是「推演污染事实」"）；`:231`（节点图 `whatif →derived_from→ assertion`）。

**源文稿位置**
- `dreaming research.md:120`：挂载点是"场景抽象之后、剪枝之前"，不新增第六阶段；`:175-177`（R1/R2）：**v1 把 What-If 做成离线批式、插在剪枝之前**；假想单列 whatif 表带结算字段，**永不进 L1**——这两条正是对"污染"的回答；`:125-130`（七条约束）：K≤2 且默认 K=1（WebDreamer H=1 最优、H≥2 因模拟内动作幻觉下降；ITP fixed-k 先升后降）、一锚点一分叉、动作必须在枚举可执行集内、**先剪候选再开模拟**、打分离散档、预算按 token 计。
- `fusion-design-v1.md:13`、`plugin-design-triviumdb-v2.md:138, 144`（⑤ What-If 深度≤2、先剪候选、永不进 L1）。

**冲突**：第一，"推演污染事实"的担忧在源文稿里已有机制性答案（符号可判的 W1/W3 + 单列 + 永不进 L1），不是待解争议；以此为由默认关闭，等于放弃 v1 唯一能证明"可结算性"的闭环。第二，即便接受延后，三条用实测换来的硬约束（K≤2/默认 K=1、一锚点一分叉、先剪候选）在骨架里没有任何落点——重启时没有任何规则阻止"想深一点"的多步自由生成，而那正是 WebDreamer 报告失效的区间。

## F7 [medium] AD-8 没有排序与阈值规则，衰减/热度也没有计算位置

**骨架位置**：`ARCHITECTURE-SPINE.md:89`（AD-8 Rule）；全文件无"衰减 / 热度 / half-life"字段或 AD。

**源文稿位置**

- `memory research.md:126-127`（R3）、`:161`：衰减用幂律 + 对数 rehearsal 起步，**作为排序因子，不改变存储位置**；`:162`：检索只读，召回不写回任何计数。
- `ontology research.md:127`：三种路线（衰减存储值 / 读时投影 / 检索打分），"读时投影"最可审计；`:186`（L2：存证据，读时算 confidence_band）。

## F8 [medium-low] 三轴数据模型只暴露一个查询参数，答不了"那时系统持有什么"

**骨架位置**：`ARCHITECTURE-SPINE.md:71`（AD-5："历史查询必须显式传 `knownAsOf`"）。

**源文稿位置**：`ontology research.md:76`（Utopia 把两条时间轴暴露成两个参数：`at` 读世界时间"那时什么是真的"，`as_of` 读记录时间"那时系统持有什么"）；`:82`（最小可用集 = 四字段 + 区间逻辑 + 默认只返回 `superseded_at IS NULL` 的硬规则）；`:198`（查询层硬规则，直接照抄两个参数语义）。

**冲突**：骨架的数据模型是三轴（`valid_from/valid_to`、`recorded_at`、`superseded_at`），但对外只给一个 `knownAsOf`。这足以做"当时为真的事实"，却做不了"当时的信念状态"——而后者正是治理要回答"为何还在 / 何时改的"时必须的能力（审计要重建"那天系统相信什么"，不是"那天世界如何"）。Graphiti 默认不过滤的教训解决了"默认要过滤"，没解决"两条轴要分开表达"。

**建议**：AD-5 改成显式两个参数 `at`（世界时间，按 `valid_from/valid_to` 过滤）与 `asOf`（记录时间，按 `recorded_at/superseded_at` 过滤），默认两者皆空时只返回 `superseded_at IS NULL`。
