## 一、能力切分（initiative altitude）

用户裁定的五个能力（第一轮）：memory / dream / governance / persona / ops。能力内部再分职责，但不新增顶层能力。

### CAP-1 记忆（memory）
- **职责**：把一轮对话结算成「断言 + 证据 + 实体 + 场景」；把记忆按三档注回上下文；为每条断言留可回溯的证据指针。
- **边界**：不做人格语气，不做离线固化，不做删除策略（那是 governance）。
- **不变量**：写入是补丁式且全有或全无；记忆库不存第二份对话原文；召回不产生写入。

### CAP-2 固化（dream）
- **职责**：离线把碎片断言收敛成场景/画像；执行无需模型的确定性结算；生成候选 whatif 但不入库。
- **边界**：不参数化学习（不改权重、不训模型）；不物理删除任何断言。
- **不变量**：确定性步骤先于模型步骤；周期标记保证幂等；预算耗尽停在阶段边界。

### CAP-3 治理（governance）
- **职责**：版本链、软删除与回溯、冲突 flag、审计视图、导出。
- **边界**：不产生新记忆内容；不替用户做不可回滚的判断。
- **不变量**：任何路径都不物理删除断言；每条推断都能被后来的事实判对错（可结算性）。

### CAP-4 人格（persona）
- **职责**：稳定身份（`persona.md`）+ 可变关系状态（`persona_state`）+ 四维关系数值 + 边界硬拦截。
- **边界**：不改写已生成的助手消息；不靠 prompt 措辞兜底边界。
- **不变量**：身份文件字节稳定、且不依赖数据库可用性；关系状态缺席时整段省略而非填默认值。

### CAP-5 运维（ops）
- **职责**：单文件库的生命周期（建库/快照/迁移/校验）、降级开关、注入与调用的记账、可观测。
- **边界**：不碰宿主工作区文件；不做跨进程协调。
- **不变量**：底座故障时整体 no-op；mnemon 迁移幂等且可回滚。

### 明确暂缓（Deferred，非能力）
- **Voice（L4 表达层）**：DSH 禁止后置改写（助手消息不可变、`agent/turn-stopping` 只能 steer、`llm/stream` 只读），只剩「预生成契约 + 生成后记账」。重启条件：CAP-2 固化完成且 CAP-3 治理可用。
- **主动搭话（proactive）**：重启条件：记忆层稳定，且宿主提供「投递」而非定时唤醒。
- **技能自演进（skills）**：复用「可版本回滚的文本门控」，不引入参数化学习。

## 二、候选 AD（按家族分组）

### A. 形态与边界
- AD-A1 [定] 纯 DSH 插件形态：单进程、无 IPC、无第二个部署单元。
- AD-A2 [定] 直接绑定 TriviumDB，业务代码写 TQL，不设存储适配层。
- AD-A3 [定] 单包分层 `src/{core,store,dream,persona,seams,gui}`，依赖方向由 eslint 规则强制。
- AD-A4 [推导] 插件不写会话日志：`Session.append()` 虽公开，但日志是宿主真相源，写入权不共享。
- AD-A5 [推导] 工具可缺席：记忆工具未注册时，人格与注入仍工作。
- AD-A6 [推导] 边界硬拦截落在工具层预检，不写在 prompt 里。

### B. 数据与写入
- AD-B1 [定] 断言身份按谓词基数：TBox 声明 `single`/`multi`，键分别为 `(subj,pred)` 与 `(subj,pred,obj_norm)`。
- AD-B2 [定] 双时态 + supersede 链；默认查询 `superseded_at IS NULL`；无物理删除。
- AD-B3 [定] 证据 = 只读日志指针 + ≤200 字短引文（截断标注、脱敏）；不复制原文。
- AD-B4 [定] 写入走补丁表（insert/update/supersede）+ 一次 `commitTransaction`。
- AD-B5 [推导] 向量外部供给（bge-m3），维度建库即锁死，写入不等向量（`vec_state:pending` + 异步补写）。
- AD-B6 [推导] 写入前有校验层，被拒不静默：落 `rejected` 记录并附原因。

### C. 读取与注入
- AD-C1 [定] TQL 只允许出现在查询模板模块；CI 对 `templates/` 之外出现 `FIND`/`SEARCH` 直接失败。
- AD-C2 [定] 三档注入：身份段（字节稳定）、状态尾巴（cache-safe 位置）、按需召回（工具）。
- AD-C3 [待] 注入拼装权与常驻预算（第四轮 Q1/Q2）。
- AD-C4 [推导] 召回有硬预算：条数上限 + 超时即返回空，不重试不扩窗。
- AD-C5 [推导] 召回是只读的：不得因被召回而修改热度、稳定性或计数。

### D. 固化与治理
- AD-D1 [推导] dream 8 步，确定性结算先行，模型步骤在后。
- AD-D2 [待] dream 触发与预算（第四轮 Q3）。
- AD-D3 [定] 三级裁决；自动裁决仅限符号可判且可回滚（同键、区间重叠、值不同 → 后者胜 + superseded + 自动 flag）。
- AD-D4 [定] whatif 在 v1 只建表与结算字段，生成默认关闭。
- AD-D5 [推导] 可结算性是可验收的：每条推断记录「由什么判定、何时判定、判定结果」。

### E. 运维
- AD-E1 [推导] 故障降级：整体 no-op，DSH 回到原生形态。
- AD-E2 [待] 备份/快照纪律（第四轮 Q5）。
- AD-E3 [推导] mnemon 替换而非共存：迁移幂等（`uuid5(file,linehash)`）、不删源文件、留回滚开关。
