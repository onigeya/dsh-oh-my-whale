# Digest — ontology governance & validation (assistant onto-gov, round 1)

Topic: TrustGraph, Ontofelia, ontology-worlds, clawra-engine
Accessed: 2026-11-22.

## Findings

1. **TrustGraph (3205★, push 2026-11-22) — clearest layered engineering model; claims largely hold.** Ontology comes from BYOO (Bring Your Own Ontology: user uploads an OWL domain schema). OWL acts at **extraction (write) time**: extracted triples are checked against the ontology's domain/range/subclass and violating triples are rejected (README: "Triples that break the rules are rejected"); the project says it is "not a full OWL reasoner" — no query-time inference. SHACL (a SHACL-AF variant, not standard validation) runs at **query time** as per-node policy filtering (tri-state Allowed/Filtered/Violation); policies live in the `urn:graph:policy` named graph and cover REST/SPARQL/GraphRAG. Provenance is PROV-O in named graphs (`urn:graph:source` extraction lineage + `urn:graph:retrieval` inference trace), SPARQL-queryable — the most direct reference for provenance design. **No per-triple evidence/confidence field**; confidence appears only in "Decision Scoring" (Laya ONNX ~35ms) and Cloze classifiers (DistilBERT), not on the graph. Deployment is heavy: docker-compose + Cassandra + Pulsar/RabbitMQ + Qdrant + S3 + Docling.
2. **Ontofelia (34★, v0.0.1, push 2026-11-17) — neuro-symbolic is real inference but limited; unusually honest.** Repo calls itself a "vibe coding" experiment generated by Claude Code/Codex/Gemini, not production-grade. Inference is **OWL 2 RL materialisation** (Reasonable, Rust N-API addon), explicitly "not an OWL-DL reasoner, no full consistency checking"; disjoint-class conflicts are caught by a separate SPARQL check that writes a conflict record. **"SHACL" does not appear in README at all** — its governance is write-time KnowledgeEngine (entity/property resolution + ABox insert) + OWL RL materialisation + disjoint-class SPARQL marking, not SHACL shape validation; reads are SPARQL 1.1. Provenance: every triple records when/where/how it was learned. Self-reported benchmarks (H6 forgetting 1.00 vs RAG 0.54, H3 contradiction detection 0.93 vs 0.20) are pilot-scale, not human-adjudicated, explicitly not a comparison against Hermes/OpenClaw — medium confidence, but more honest than most.
3. **ontology-worlds (6★, push 2026-05-16, v0.3.0) — "no assertions outside the ontology" is real post-hoc interception, but a soft constraint.** Three layers (CLAUDE.md architecture): (1) system prompt injects legal entities/predicates; (2) PreToolUse hook validates entity/triple and exits 2 to block; (3) post-generation Stop/PostToolUse hook runs `domain_validator.py` to compute an in-domain coverage score and below threshold (default 0.5, configurable) blocks + rewords, self-correction ≤3 rounds, then marks `out_of_scope`; additionally `grammar_builder.py` compiles the graph into a JSON Schema with enum constraints to force structured decoding. **Key judgement**: coverage is heuristic (are entities/predicates in the graph), so "legal but novel" phrasing gets killed and wording games can evade; JSON Schema is hard but only for structured output, not free text. Repo ~335KB, zero forks, single author — readable as a "hallucination boundary" prototype, not a reusable engine, and it depends on live Wikidata SPARQL.
4. **clawra-engine (2★, v4.2.0-alpha, push 2026-07-10) — marketing far outruns maturity.** Structure and dependencies confirmed in code: `src/clawra/core/{reasoner,knowledge_graph,retriever}.py` and `evolution/{evolution_loop,self_memory,meta_learner}.py` all exist (35–75KB), deps rdflib/owlrl/owlready2/networkx/chromadb/openai/mem0ai; **Neo4j is only optional-deps**, and `self_memory.py` persists to local JSON files by default (storage_dir + `_preferences_path`); README's "Neo4j graph storage" is an optional sync. GraphRAG exists (retriever.py) but the internals of "metacognitive introspection" were not opened (budget), the classifier claims Apache while LICENSE is MIT, and v4.2.0-alpha self-describes as Beta — low engineering rigour. **Conclusion: rule engine / GraphRAG / evolution loop are real code, but this is a single-person alpha; its "feeling-preference-rule" chain is probably LLM-prompt-driven rather than a provable symbolic mechanism (unverified).**
5. **Common pattern — where to intercept and what it costs.** All three interception points have real instances here: **write-time validation** (TrustGraph rejects triples at extraction; Ontofelia routes writes through the knowledge engine + RL materialisation) — cost: depends on extraction quality and ontology completeness, a missing class leaks; **retrieval-time filtering** (TrustGraph SHACL-AF tri-state per query) — cost: a wrong policy systematically over- or under-blocks, needs audit events; **post-generation validation** (ontology-worlds coverage scoring + rewrite) — cost: hard constraint only for structured output (tool_use/JSON), free text relies on heuristics, both false kills and leaks. Practical lesson: TrustGraph models every validation failure as an explicit state (Violation / rejected / out_of_scope) rather than silently retrying — the design most worth copying; ontology-worlds' "mark out_of_scope instead of forcing a rewrite" is a good false-kill mitigation.

## Hype vs implementation

- TrustGraph: small gap — "SHACL" is a custom SHACL-AF policy engine, not a standard validator; README itself admits no OWL reasoner.
- Ontofelia: gap is the scope of "reasoning" — RL materialisation ≠ logical reasoning; the README says so honestly; "governed" has weak hard constraints (no write-time shape validation).
- ontology-worlds: "no hallucination — only facts in the graph" is marketing; the implementation is coverage heuristics + rewrite loops, bypassable and false-kill prone.
- clawra: biggest gap — "enterprise private deployment / multi-tenant / microservices" vs single-person alpha; Neo4j downgraded to optional sync; license metadata contradictory (Apache classifier vs MIT LICENSE).
