# technical research: Dreaming 阶段的批量 What-If 反事实推演

**Decision this research serves:** Dreaming 阶段是否以及如何加入批量 What-If 反事实推演，作为持续学习/自我演化的一环

## 执行摘要

**结论先说：加，但不是加在"在线决策"上，而是加在 Dreaming 的剪枝之前，做成离线批式、深度不超过 2 步、每条推演锚定一条真实记忆记录的"可结算赌注"。七个研究对象里没有一个的完整实现能直接搬——能搬的只有骨架、候选裁剪纪律、离散投票打分与不确定性折扣这四件。**

> 读前需知的两个词：**Dreaming** 指本插件的离线固化阶段（重放抽样 → 模式提取 → 场景抽象 → 剪枝归档 → 跨主题重组）；**L1** 指一句话事实/偏好/决策 + 类型 + 重要度 + 来源指针（session id + seq 区间）+ 有效期的原子记忆层，L2 是主题场景、L3 是画像。下文不再重复。

**三条驱动结论的发现**

1. **这批系统的"模拟"比宣传的弱得多，而弱的那部分恰好是我们需要的。** WebDreamer 不是 MCTS——全文 "MCTS" 精确命中 0 次，代码是"每候选 3 条轨迹 × 深度 1 × 每条 10 次投票"的蒙特卡洛平均 [1][2]；WebDreamer 与 ITP 的想象都是**单链**（ITP 甚至 do_sample=False，同一输入永远同一条想象）[2][4]；WebATLAS 没有模拟器，模拟就是查记忆表 [6]。所谓"批量反事实分支"在这些开源实现里并不存在，它是我们必须自己造的部分。

2. **"假想不入库"是这批系统共同的防污染线，而且没人给出正例。** WebATLAS 只写经 memory agent 策展的转移摘要，Memento 只写真实执行的 (s,a,r)，PGR 的探针从不入库 [6][7][8]。想在记忆库上叠 What-If，第一个要自创的不是推演算法，而是**假想记录的生命周期**：单列存放、带结算字段、永不混入 L1。

3. **深度加不上去，这是实测而不是理论。** WebDreamer 在 GPT-4o 上实测 H=1 最优，H=2/3 因"模拟内动作提议幻觉"而下降 [1]；ITP 固定步长时成功率同样先升后降 [3]。**任何"想深一点会更准"的直觉，在这两篇的实验里都是错的。**

**最大警示**：七个研究对象里，能读到实现细节的五个（WebDreamer、ITP、Memento、Dreamer 4、Dreamer V3）全部在**有真值、可回放、回合制**的环境里做推演（网页、ALFWorld、HalfCheetah）；另外两个（SimuRA、WebATLAS）只有论文、无仓库可核。没有任何一篇在"个人记忆"这种无环境、无 episode、无即时奖励的场景做过实验。我们不是把他们的结论搬过来，而是把他们的骨架搬过来，然后用两种他们没有的真值填空：**符号一致性检查**（来源指针、冲突计数）与**下次真实对话的回填**。

**给本项目的取舍**：v1 只做 W1（一致性反事实）与 W3（剪枝后悔预演），因为这两类的对错可以完全由符号检查判定，不依赖 LLM 自评；W2（可答性预演）作为检索探针的副产品顺带产出，但要等结算链路建好再谈收益；W4（真值敏感性）留到 v2。**先建结算链路，再扩推演规模——先能证明"猜得准"，再谈"猜得多"。**

## 维度一：模拟器骨架——四个实现，一套骨架，两种"模拟"

**结论先说：这四个项目共享同一副骨架（观测 → 状态摘要 → 候选动作 → 前向模拟 → 打分 → 选一个执行），但"模拟"有两种截然不同的实现：一种让 LLM 预测未来，另一种干脆查表。只有后者能在记忆图谱上成立。**

骨架本身没有分歧，差异全在"转移函数"由谁提供：

| 维度 | WebDreamer [1][2] | SimuRA [5] | ITP [3][4] | WebATLAS [6] |
|---|---|---|---|---|
| 状态表示 | 截图 + "动作造成的界面变化"自然语言增量 | 自然语言摘要序列（token 级分解） | 文本观测 s_t；想象态 ŝ 另立 | 原始观测 + 认知地图三元组 (o,a,o') + 站点规则 |
| 模拟器实现 | LLM 预测状态变化 | LLM 预测下一步摘要 | LLM（训练过的 Qwen3-8B） | 记忆检索查表，不生成 |
| 候选来源 | top-k 采样 + LLM 过滤 | policy 采样 20 个抽象意图后聚类 | policy 直接采下一个（单链） | Actor 产 N 个（正文无值） |
| 分支 × 深度 | 每动作 3 条 × 深度 1（实验固定 H=1） | 20 × 20 采样，深度 1 | 1 条 × K_t（≤5） | N × D 步 beam（无值） |
| 打分 | LLM 三档 1/0.5/0 + 多层平均 | critic 终端价值 + 折扣回报 | 无标量 critic，Reflect 文本反馈 | 五维价值 × 转移置信度 ∏(1−U) |
| 搜索算法 | MPC/argmax，**无树** | 声称 DFS/MCTS，实为深度 1 枚举 | 无搜索，单链 | beam over 记忆图 |

**第一处必须纠正的常识：WebDreamer 不是 MCTS。** 全文检索 "MCTS" 精确命中 0 次 [1]；它做的是 MPC 式 argmax score(sim(o_t,a))——候选动作先 top-k 采样、再由一次 LLM 调用过滤掉不该模拟的（controller.py:44-136，system prompt 明说"你的角色不是选最佳动作，而是过滤掉明显无关的"）[2]，然后对每个候选跑 num_of_sim=3 条独立轨迹、深度 steps=1、每条轨迹内再用 n=10 次 LLM 采样投票（simulation_scoring.py:416-492）[2]。所谓"MCTS 式评估"在代码里是**固定小预算的蒙特卡洛投票**：没有树展开、没有回溯、没有价值回传。

**第二处：想象是单链，不是分支。** WebDreamer 的 multiple_step_change_prediction 先预测首步状态变化，再循环 k 次"在想象世界里提一个动作 → 预测该动作的状态变化"，遇 stop 提前 break（world_model.py:193-229）[2]。ITP 更彻底：orchestrator 每步只调一次 world_model.imagine(k)，得到**一条**链、一次反思、一个动作（orchestrator.py:27-40）[4]；而且那次生成 temperature=0.7 但 do_sample=False（world_model.py:62-68）[4]——温度不生效，同一输入永远同一条想象。**"批量反事实分支"在这两个项目里都不存在，它是要我们自己补的东西，不是能照抄的现成件。**

**第三处：WebATLAS 的"三环"实际是四模块，Simulator 是记忆检索。** 它没有独立模拟器：模拟即查认知地图 ô=M(o_t,a_t)，未命中返回通用占位观测 [6]；打分是五维 LLM 价值（goal alignment、state viability、action coherence、plan consistency、outcome risk）再乘轨迹级不确定性折扣 ∏(1−U(s,a))。这对我们是好消息也是坏消息：好消息是它证明"记忆即世界模型"在结构上可行，转移函数可以是查表而非生成；坏消息是它的三元组来自真实站点探索，覆盖极稀疏，未命中就退化成占位符——而个人记忆库的编辑历史只会更稀疏。

**为什么具体实现搬不过来（三条硬伤）**

1. **没有 o_{t+1} 真值。** 前三个项目都靠"能真的执行、真的回放"来定义状态转移；记忆库里"假设我合并这两条冲突偏好"之后世界变成什么样，既不能截图验证，也没有环境 reward。
2. **动作空间组合爆炸。** 网页上十几个可点元素；记忆图的编辑操作（插入/合并/改写/失效化 L1、重划 L2、重写 L3）是组合空间，没有廉价沙箱执行。
3. **没有 episode 目标函数。** 0/0.5/1 表达的是"任务完成进度"；Dreaming 是离线固化，没有 task success，同一段推演对"该不该保留这条记忆"的价值无法用完成度表达。

**能留下来的只有两样：骨架，和可插拔的打分接口。** 转移函数与打分器必须为符号层重写——这不是妥协，这是唯一有证据支持的路径。

## 维度二：算力经济学——没有"值不值得模拟"的评估器，只有"先模拟完再打分"

**结论先说：四篇里没有一篇实现"模拟收益评估器"。它们都是先模拟、再打分，成本控制靠事后剪枝与固定小预算。想在 Dreaming 里"按需触发推演"，机制得自建，但边界条件论文给得很清楚。**

**边界一：深度不能加。** ITP 固定步长时成功率"先升后降"（arxiv-2601.08955:934）[3]；WebDreamer 用 GPT-4o 在 horizon 1/2/3 上实测，H=1 最好，H=2、3 开始下降，原因是**模拟内的动作提议幻觉**——模拟里提出的动作在预测出的页面上其实不可用，深度越大，不同候选的轨迹越"看起来都对"、越不可区分 [1]。原文："when the planning horizon extends to 2 and 3 steps, the effectiveness begins to diminish"（arxiv-2411.06559:637-640）。实验实际设定是 H=1（:487）。

**边界二：成本随深度单调上升，而且很贵。** WebDreamer 墙钟（Shopping 域）reactive 87.7s、tree search 785.7s、WebDreamer 179.4s——比树搜索省 4–5 倍，但按同表三个域（Classifieds 68.3/183.6、Reddit 83.5/233.7、Shopping 87.7/179.4）算，仍比反应式慢约 2.0–2.8 倍 [1]。ITP 部署延迟 p50/p95/p99 = 14.2/31.8/44.7 秒，其中想象占 7.8/18.9/28.5 秒（比策略本身还贵），吞吐 11.8 episodes/hour，VRAM 31.0/38.4 GB [3]。

**边界三："模拟导致更差"有原文，但只在特定条件下。** WebDreamer 说"直接模拟所有动作会引入额外噪声、负面影响性能"（:625），但上下文是**去掉 self-refine 候选过滤之后**——即模拟的收益依赖前面的候选裁剪。工程纪律由此而来：**先剪候选，再开模拟；不剪就模拟全部，会亏。**

**ITP 的"自适应"到底怎么做的**：不是不确定性驱动，也不是预测误差驱动，而是"朝最终目标的进度估计"。两条路径：ITP_I 让 LLM 读指令+状态直接吐一个整数 K（prompt 就一句"output a single integer K in [0,{kmax}]"）；ITP_R 把 K 变成可学习分布，伪标签是 argmax_k[log p(a*|s,τ̂(k)) − λ_K·k]，在线奖励 r_env − λ_K·K_t − λ_step，用 A2C 联合优化 [3]。

**代码里的"自适应"比论文弱得多**：decide_k 是一次 temperature=0.8 的采样取首个整数，解析失败静默回退 K=1，再 clamp 到 [0,max_k]（policy.py:48-69）[4]；K_head 只出现在训练脚本（train_adaptive_k.py:224），推理路径根本不用它；K_max 代码写死 5，论文正文只说"见附录 C" [4]。**所以"自适应 horizon"在开源实现里约等于"让 LLM 拍一个 0–5 的整数"——它便宜（decide_k 的 max_new_tokens=32，policy.py:58 [4]），但不可靠。这正是可以照抄的那一半：成本低、可审计；不值得照抄的是训练 K_head，因为我们没有专家动作可用。**

## 维度三：模拟 ↔ 记忆的闭环——三篇里没有一篇把假想写回记忆

**结论先说：这是本次研究最重要的一条否定性发现。WebATLAS、Memento、PGR 三个"记忆 + 推演"的系统，没有一个把想象产物当事实写回长期记忆。它们都用某种闸门把假想挡在库外。没有任何论文给出"如何区分假想与真实"的正例——只有"干脆不写"的负例。**

三道闸门，三种口径：

- **WebATLAS**：模拟期间允许更新记忆，但写入必须过 memory agent 的 retain/update/forget 三选一；真正落库的是**策展过的转移摘要**，不是想象轨迹本身 [6]。
- **Memento**：只写真实执行的 (s_t,a_t,r_t)，且只把每条轨迹的最终步写库以保持紧凑（Eq.12 是集合并）[8]。它的"反事实分支"实际形态是**检索到的成功+失败 case 并列**，不是分支树——用户表格里"自带反事实分支评估"的描述应更正为"案例插值"。
- **PGR**：想象出来的未来步骤只当检索探针用，从不入库 [7]。

**Memento 还有一个值得单独拎出来的教训**：case bank 只增不删，而论文自己报告 K 增大后性能 plateau 甚至略降，结论是"小而高质量的记忆更优"（:1165-1166）[8]。这与本项目 brief 里"只增不减是九家共性缺陷"互为印证——**在一个已经会膨胀的记忆库上再叠加"批量假想轨迹"，如果不设淘汰，就是二次膨胀。**

**唯一可直接借用的数学形式：不确定性折扣。** WebATLAS 用 Ṽ(τ̂)=V(τ̂)·∏(1−U(s,a)) 给想象轨迹打折，并在 ‖o_obs−ô_exp‖>ε 时触发重规划 [6]。U(s,a) 的具体定义正文没给（未找到证据），这反而留出空间——在符号层，U 可以由**已有的治理信号**合成：无来源指针、来源陈旧、处于 disputed 状态、与既有断言冲突数。**我们不需要 LLM 自信度，我们有比它更硬的东西。**

**代码与论文不一致（Memento）**：论文说 parametric 版在 Write 时"further online updates a Q-function"，Read 由学到的 Q 驱动（:512-513）[8]；代码里是**离线训练好的成对分类器**，加载权重后对 (query, case) 打分取 softmax[:,1]，case bank 里没有任何 Q 字段（memory/parametric_memory.py:10-45）[9]。代价从"库内元数据"变成"一个需要 GPU 推理的外挂模型"。**任何把"价值分数"塞进记忆库的设计，都要先问：它是字段，还是要一个模型？**

## 维度四：可靠性边界——LLM 世界模型什么时候不可信

**结论先说：唯一做了显式校准的是 WebATLAS，而它校准的方式是"别让 LLM 预测，去查真实观测"。其余三篇承认幻觉，但没有给出可操作的止损信号。**

三篇的自我诊断（细节见维度二"边界一"与维度一"三处纠正"）：WebATLAS 直言 LLM 未被训练成世界模型、凭想象预测"prone to hallucination"，因此改用真实观测查表 [6]；WebDreamer 把 horizon 增益消失归为"模拟内的动作提议幻觉" [1]；ITP 在动机段就写"过度 rollout 会放大模型误差并浪费算力" [3]。**共同点是：诊断清楚，但都没有给出运行时可用的止损信号**——没有"这条想象不可信，丢弃"的判定器。

**对 Dreaming 的直接推论（推断，非论文实测，必须标明）**：没有任何论文在"陪伴/个人助理"场景做过反事实推演实验。但从上面三条能推出一条硬边界——**有 ground truth 可校验的推演可以做，无真值的自由多步生成不要做**。前者如"若把两条冲突偏好按方案 A 合并，哪些既有记忆会失去来源支撑"，答案可以用符号检查验证；后者如"用户下周情绪会怎样"，既无真值也无止损信号，正是 WebDreamer 报告失效的区间。

## 维度五：落地映射——What-If 挂进 Dreaming 五阶段的哪一格

这一维没有对应论文，是把前四维的证据压到本项目结构上的设计推导。**每条都标证据来源，推断的都写明是推断。**

**先定性：Dreaming 里的 What-If 不是"下一步做什么"，而是"这批记忆换个处置会怎样"。** 前四个项目的推演服务于在线决策（选哪个动作），我们的推演服务于离线固化（选哪种理解/处置）——这是根本差异，也是打分器必须换的原因。

**四类可校验的 What-If（按可验证性排序）**

| 类型 | 问法 | 谁来判对错 | 证据支撑 |
|---|---|---|---|
| W1 一致性反事实 | 若按方案 X 合并/改写这两条，库中哪些断言会失去来源支撑或变成矛盾？ | 符号检查（来源指针 + 冲突计数），无需 LLM 裁决 | WebDreamer 的状态变化预测骨架 [1]；WebATLAS 的 ∏(1−U) [6] |
| W2 可答性预演 | 若用户下次问起主题 T，仅凭现有 L1 能答到什么程度？缺口在哪？ | 下次真实对话回填（有真值） | PGR 的想象引导检索 [7] |
| W3 剪枝后悔预演 | 若现在归档这批低频记忆，会丢掉哪些"当时没用、将来会问"的东西？ | 归档后命中率回填 | Memento 的 K 增大反而变差 [8]；Dreamer 4 的"每 context 一条 rollout" [10] |
| W4 真值敏感性 | 若这条新事实为假，哪些下游结论会塌？ | 后续真实交互证伪 | Memento 的成功/失败 case 并列 [8] |

**挂载点：不新增第六阶段，而是插进第三与第四阶段之间，作为"剪枝归档"的前置校验。** 理由：剪枝是唯一不可逆（虽可回滚）且最容易后悔的动作；而 W1/W3 恰好能用符号检查判对错。放在"场景抽象之后、剪枝之前"，推演产出的就是剪枝决策的证据，而不是又一份没人读的文本。

**七条设计约束，每条对应一条证据**

1. **锚定真实记录，一锚点一分叉。** 每条 What-If 必须挂一条真实 L1/L2 的 id 作起点，不允许凭空起头。依据：Dreamer 4 的想象 rollout 必须从真实数据 context 起步、且一个 context 只开一条 rollout [10]；这同时解决"假想无据"与"批量爆炸"。
2. **深度硬上限 K≤2，默认 K=1。** 依据：WebDreamer H=1 最优、H≥2 因模拟内动作幻觉下降 [1]；ITP fixed-k 先升后降 [3]。**不要做多步自由生成。**
3. **动作必须在可执行集合内。** 候选编辑操作只能从枚举表里出（insert / merge / rewrite / expire / promote），生成后先校验再模拟，不合法直接丢弃。依据：ITP 的 validate_action 校验动作 ∈ admissible_commands，否则回退（policy.py:13-37）[4]。
4. **先剪候选，再开模拟。** 依据：WebDreamer 去掉 self-refine 后"直接模拟所有动作会引入噪声、负面影响性能"（:625）[1]。
5. **打分用离散档 + 多次投票，不用连续置信。** 依据：WebDreamer 三档 1/0.5/0 + 多层平均 [1][2]；LLM 自评的连续分数没有校准证据，离散档至少可复现。
6. **假想记录独立存放，永不进 L1。** 依据：三篇一致把假想挡在库外 [6][7][8]；brief 里 L1 是"一句话事实 + 来源指针"，假想没有来源指针，天然不属于 L1。建议单列 whatif 表（anchor_id、edit_op、predicted_delta、score、predicted_at、verified_at、outcome）。
7. **预算按 token 计，不按调用数计。** 依据：ITP 的成本口径是 episode token 总和、NB(k) 归一到 [0,1] [3]。调用数会掩盖 prompt 长度差异。

**这一维最值得写进设计的一条：把"推演"变成"可结算的赌注"。** 三篇里"想象必须被真实信号校正"在 Dreamer 里是 loss 项 [12]，在 WebATLAS 里是 replan 触发器 [6]；而在记忆插件里，它可以是**一条在下次真实对话中自动结算的预测记录**：W2 说"用户会问 T、现有记忆答不全"，下次会话真的问了 T 就算命中，没问就算落空。命中率就是模拟器的校准曲线，也是"自我演化"唯一诚实的度量——**不是模型变强了，是它的猜测越来越准，而且你能查账。** 三篇论文都没做这件事（未找到证据），这是可以占的位置。

**批量调度（回应用户的"批量"）**：每个 Dreaming 周期固定配额——锚点数 N_a、每锚定编辑数 N_e、总 rollout 数 N_a×N_e 硬上限；按 (anchor_id, edit_op) 哈希去重，已推演且未结算的跳过；dry-run 只跑锚点采样与候选生成（对应 brief 里"只跑选择阶段"）；种子写进产物，事后能回答"为什么挑了这条"。幂等靠周期标记，错过不补做——与 brief 现有约定一致。

## 维度六：近邻方法——Dreamer 系列的边界，以及能借的三件事

**结论先说：Dreamer 的"想象"之所以有用，是因为想象轨迹能回传梯度去更新 policy/value/世界模型。符号记忆层没有可微潜空间、没有梯度，"在想象中训练"这条路直接封死，只能取"想象用于排序/检索"。**

不可迁移的四件：RSSM 隐状态 {h,z} 与 KL/重建损失、diffusion + shortcut forcing 的连续潜空间、tokenizer 的量化潜变量、value/reward head 的 TD/λ-return 梯度学习 [10][12]。另一个常见误读要纠正：**Dreamer V3 推理时不做 lookahead**，正文明确"select actions by sampling from the actor network without lookahead planning"（:265）[12]——它的想象发生在训练时。所以它对应的只能是"离线 Dreaming"，不是"在线决策"。

可迁移的三件：

1. **回放采样策略**：想象 rollout 从真实数据 context 起步，一个 context 只开一条 rollout 以保多样性、省内存 [10]；开源实现里这一循环的入口就是 train_agent_in_imagination（train_halfcheetah_imagination_rl.py:746）[11]；replay ratio 越高越稳 [12]。符号层对应：一锚点一分叉。
2. **想象的用途**：训练（Dreamer）vs 决策打分（WebDreamer/WebATLAS）。符号层只能取后者。
3. **真实信号钉住想象**：V3 把 critic loss 同时加在 replay 的真实起点上（β_repval=0.3）[12]。符号层的等价物是"每条假想必须挂真实来源指针 + 执行后回填结果"。

**顺带一个交叉印证**：Dreamer 4 的"每 context 一条 rollout"与 Memento 的"每轨迹只存最终步"，是同一种去冗余直觉——可作为 Dreaming 重放抽样的一条硬约束候选。

## 交叉洞察

**只有把六个维度叠起来才看得见的三件事**

1. **"没有真值"是本项目与它们的分水岭，同时是最大风险与最大机会。** 网页智能体敢多步模拟，是因为模拟完可以真的点一下、看对不对；我们没有"点一下"的沙箱 [1][6]。但记忆库有两种它们没有的硬真值——**符号自洽**（是否有来源支撑、是否与其它断言矛盾）与**未来对话**（用户下次到底问不问）。前四维所有"不可迁移"判断都指向同一结论：打分器必须换成这两种真值的组合，而不是 LLM 自评。

2. **三个"记忆 + 推演"系统都用闸门挡住假想，但闸门的方向相反。** WebATLAS 是"策展后写入"（记忆是模拟器的先验，也是产物），Memento 是"只写真实执行"，PGR 是"只读不写"。三者合起来给出一条对本项目最有用的分工：**假想只用于生成检索探针与剪枝证据，不用于生成记忆条目。** 这也解释了为什么"继续学习"在它们那里都停留在案例库层面——一旦允许假想入库，"学到的"就再也分不清真假。

3. 由此推出规模判断：WebATLAS 的查表模拟在真实站点上可用，靠的是海量探索三元组 [6]；记忆库的编辑历史稀疏几个数量级，未命中就退化成占位符。**所以 What-If 只能是"少量、锚定、可结算"，不是"批量、自由、常开"——"批量"应理解为"每个周期一批、每批有配额"。**

## 建议

**R1｜v1 把 What-If 做成离线批式、插在剪枝之前，不做在线推演。** 置信基础：high（深度证据 [1][3] + 本项目无沙箱执行的事实）。落点：Dreaming 五阶段的"场景抽象"与"剪枝归档"之间。

**R2｜假想记录单列 whatif 表，带结算字段，永不进 L1。** 置信基础：high（三篇一致的"假想不入库"实践 [6][7][8]）。字段清单见维度五约束 6。落点：治理面的可导出与可审计要求。

**R3｜打分器以符号检查为主，LLM 只补残余判断，且用离散档 + 多次投票。** 置信基础：medium（"符号检查优先"是我们的推断，论文无对应；"离散档 + 投票"有 WebDreamer 代码为证 [1][2]）。落点：W1/W3 的判定逻辑。

**R4｜不确定性折扣 U 由已有治理信号合成，不用 LLM 自信度。** 置信基础：medium（WebATLAS 提供了 ∏(1−U) 的形式，但 U 的定义缺失 [6]，合成方式是推断）。可用信号：无来源指针、来源陈旧、disputed 状态、冲突计数。

**R5｜预算按 token 计、按周期配额、幂等 + dry-run + 种子。** 置信基础：high（ITP 的 token 口径 [3] + 本项目既有的幂等与 dry-run 约定）。落点：Dreaming 的预算与可复现性条款。

**R6｜先做结算链路，再扩规模；W2 的检索探针是最先能量化收益的切入点。** 置信基础：medium-high（PGR 证明想象可提升召回 [7]，但结算机制无人实现）。落点：v1.5 的评测集。

## 开放问题

1. **U(s,a) 怎么定义？** 论文把符号留在正文外（WebATLAS 未给定义）。我们要自定义，但没有证据说哪种合成最好——只能靠结算曲线事后验证。
2. **没有专家动作，K 怎么选？** ITP 的 K_head 需要专家动作作监督；LLM 提炼式（decide_k）成本低但不可靠。备选是纯启发式（按冲突密度定 K），无证据支持，需实测。
3. **结算窗口多长？** "下次会话"太短（可能几小时），"30 天"太长（反馈稀疏）。没有任何论文给过这个数——这是纯设计选择。
4. **whatif 表怎么淘汰？** Memento 的教训是 K 增大反而变差 [8]；假想表若只增不删会重演。淘汰策略需与结算率挂钩，但阈值无据。
5. **符号检查能覆盖多少比例的 What-If？** 若大部分推演的结论无法被符号检查判定，R3 就退化成 LLM 自评，整条设计的基础动摇。这个比例必须先测。
6. **陪伴场景的真空。** 七个项目无一在个人助理/陪伴场景做过实验；"情绪与人际推演不可做"是我们的推断，不是实测结论。
