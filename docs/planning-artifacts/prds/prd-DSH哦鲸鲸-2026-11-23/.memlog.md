- (decision by lead) [scope] 范围锁定为 v1 五件事（记忆写入/召回注入、固化、治理、人格、运维）+ 迁移；Voice、主动搭话、技能自演进、What-If 生成、治理 GUI、多用户/同步全部划为范围外并写明重启条件，不让 PRD 变成愿望清单。
- (decision by lead) [fr-numbering] 功能需求用全局 FR-1…FR-21 编号并按能力分组（4.1 记忆 / 4.2 固化 / 4.3 治理 / 4.4 人格 / 4.5 运维 / 4.6 迁移），每条 FR 只写「要什么 + 可测结果」，机制与数值下沉 addendum 并引 AD 编号——这样 epics/stories 能直接引 FR-n 而不与架构重复表述。
- (decision by lead) [non-goals] 明确不做的七条写在 §5，其中「不是要记得更多」「不是检索型问答产品」「不重写人格」三条是对标产品最容易滑坡的方向，属于防止范围蔓延的护栏，不是谦辞。
- (decision by lead) [metrics] 四条指标沿用 brief 并标注阶段：SM-1/SM-2/SM-3 为 v1 验收（可测），SM-4 只建监控与基线（v2 起设线）；另立三条反指标 SM-C1/C2/C3，防止用召回条数、自动裁决占比、固化产出量这些好刷的数字替代真实质量。
- (decision by lead) [open-questions] 只保留五个真正阻塞实现的未决项（自动挖料边界、embedding 维度、压缩后 seq 可达性、落盘 root 与配额、旧记忆文件结构），每条写明影响面；架构侧已裁定的（含 design/ 两稿的 13 处分歧）不再列为未决。
- (decision by lead) [traceability] PRD 不复述架构内容：正文只引 AD 编号与 HTML 面板，技术选型、配置默认值、错误码、M0 六门全部落在 addendum.md，避免出现第三份「事实的来源」。
- (event by lead) PRD finalized：两轮独立评审（rubric pass-with-fixes / adversary 不通过）逐条 triage 后定稿；新增 FR-22/23/24 补齐指标承接，读取边界与固化触发定案，§7.1 出口判据落盘。处置记录见 reviews/triage.md。
