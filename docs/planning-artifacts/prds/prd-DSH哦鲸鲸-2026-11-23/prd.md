# PRD：哦鲸鲸（oh-my-whale）

*工作组：v1 只做五件事——记得进、改得动、忘得掉、查得到、坏得起。*

## 1. 愿景

哦鲸鲸是跑在 DeepSeek Harness 里的一个插件，让「助理记得住」第一次变得**可结算**：每条记忆都能追到它从哪句话来、被谁改过、为什么还在；每次「它怎么忘了这个」都能反悔。

市面上记得多的产品很多，敢让你查账的一个没有。九家对标里，静默硬删、召回即写入、冲突无人裁决是通病——不是技术做不到，是没人把「可撤销」当作第一性要求来设计。哦鲸鲸把这条当宪法：**全仓禁止物理删除，撤销是一个原子操作**。

v1 不追求聪明，追求可靠。人格层只做一件事：库坏了，人设还在。

**这条愿景牺牲了什么**：为了可撤销，v1 放弃「自动更省事」的路线——符号可判的冲突才自动裁决，其余一律挂起等人（§4.3 说明这是对简报的反转，以及为什么敢反转）；为了前缀缓存可用，人格从「整篇重写」改成「字节稳定的身份文件 + 可治理的偏好节点」（§5）。

## 2. 目标用户

### 2.1 要做的事（JTBD：功能 / 情感 / 情境）

- **功能**：我不想每次开新会话都重新交代一遍背景；我希望上周说过的偏好、定过的方案，这周还在。
- **功能**：我记错了、或者它记错了，我要能一键退回去，而不是整库回滚。
- **情感**：我不想把记忆交给一个我只能祈祷它别忘了的黑箱；我要能翻账本。
- **情境**：我在本地跑、单用户、没有服务端；它不能拖慢我每一轮对话。

### 2.2 v1 的非用户

- 多用户、团队共享、跨设备同步的用户——v1 不做多租户与鉴权。
- 想要「主动找我说话」的用户——主动搭话在 v1 之外（§6.2）。
- 想在 DSH 之外使用记忆能力的用户——它是 DSH 插件，不是独立 App 或 API 服务。

### 2.3 关键用户旅程

- **UJ-1. Elliott 说了一句偏好，两周后它还知道为什么。**
  - **人物与情境**：Elliott，晚上在 Web GUI 里跟鲸鲸改一段脚本，顺口说了句「以后别用 tabs」。
  - **进入状态**：DSH 已开、插件已启用、当前会话有历史。
  - **路径**：说完 → 回合结束 → 后台抽取把「偏好：缩进用空格」写成一条断言 → 两周后新会话里 Elliott 让它改另一段代码 → 召回按需取回这条偏好 → 注入状态尾巴只留一行。
  - **高潮**：它没问第二遍缩进风格；Elliott 点开这条记忆，看见来源是两周前那句话、生成它的提示词版本、以及谁写的。
  - **收束**：这条偏好现在是可治理对象：能改、能撤、能导出。
  - **边界情况**：那次抽取失败了——记忆不存在，但它不会编造一条「用户可能喜欢空格」的推断；缺口就是缺口（FR-22）。

- **UJ-2. 记错了，撤一次操作就回到操作前。**
  - **人物与情境**：Elliott 发现它把「周五交付」记成了「周四交付」，且这条已经覆盖了旧版本。
  - **进入状态**：插件可用；这条断言处于未失效状态且已被新版本取代过一次。
  - **路径**：用治理命令查到这条的版本链与那次操作的 `op_id` → 执行撤销 → 系统按 `op_id` 反向补丁，一个事务内把旧版本恢复为未失效、回收新断言与它带来的标记和边。
  - **高潮**：撤销后默认查询与召回结果**逐条等于操作前**——不是「差不多」，是逐条比对通过。
  - **收束**：账本里多一条「撤销」记录，被撤的操作仍留在历史里，只是不再生效。
  - **边界情况**：这次操作还顺带废弃了一个场景——场景的级联也必须在同一闭包内复原，不留下半截状态。

- **UJ-3. 30 秒答清「这条谁改的、依据什么、为什么」。**
  - **人物与情境**：Elliott 三个月后回来看，怀疑某条记忆已经过时。
  - **进入状态**：库可用；他知道大概内容，但不记得是哪次会话、哪次固化写进来的。
  - **路径**：按 `mem_key` 或关键词查这条 → 一条命令同时返回版本链、决策账本与证据指针（FR-23）→ 三个问题各有字段回答（谁改的 / 依据什么 / 为什么）。
  - **高潮**：三个问题在一次查询里答清，不用翻日志、不用问模型、不用打开第二个工具。
  - **收束**：他能据此判断这条该保留、改写还是撤销。
  - **边界情况**：这条是模型推断——它必须带可判错的预言与结算状态，否则根本不该入库（FR-14）。

- **UJ-4. 库坏了，人设还在。**
  - **人物与情境**：Elliott 早上开工，单文件库被另一个进程占用，插件打开失败。
  - **进入状态**：DSH 正常启动，插件加载出错。
  - **路径**：插件启动 → 打开库失败 → 不注入记忆、不注册写工具、不排固化 → 但身份段照常注入，状态尾巴整段省略。
  - **高潮**：鲸鲸还是鲸鲸，只是这一轮不记得细节；日志里有一行固定错误码，不是静默降级。
  - **收束**：他要么关掉占用进程重载插件，要么接受本轮无记忆继续干活。
  - **边界情况**：只是向量路径坏了（凭据 401/402 或维度不符）——文本与图召回照常，不整体停摆。

- **UJ-5. 长会话翻到第 40 轮，它还认得两周前那条偏好。**
  - **人物与情境**：Elliott 在一个已经聊了很久的会话里（第 40 轮，几十个工具调用把历史撑到窗口边缘），让鲸鲸按两周前的那个偏好改脚本。
  - **进入状态**：DSH 已开、插件可用；本会话历史已被折叠阶梯处理过——部分工具输出被折成带坐标的块，若干轮散文被压成带出处的摘要。
  - **路径**：折叠接管在窗口接近满时自动触发（第 0 级先折工具输出，第 1 级再把散文压成摘要）→ 那条偏好本身作为 L1 断言仍在库里 → 召回按需取回 → 注入。
  - **高潮**：它没问第二遍；并且 Elliott 能用 `/omw` 查清「刚才被折掉的是什么」——折叠块保留可展开的坐标，不是黑箱摘要。
  - **收束**：上下文变短了，但**密度不降**——折叠前后 `focus_ratio` 可复算且不下降；折叠若让焦点散了，这次折叠回滚。
  - **边界情况**：两半替换失败（宿主压缩器摘不掉、或散文压不下去）——按 §7.1 的 G-E8-0 判「替换未成立」，回滚到宿主压缩器并重开 CAP-7，不半开硬撑。

## 3. 词汇表

- **断言（assertion）**——一条可判真假的陈述，带证据与有效期。是「记忆」的最小单位。
- **可结算**——一条推断能被判定对错：带可执行的判别式与结算状态（未定 / 已确认 / 已证伪）。
- **证据指针（evidence）**——指回宿主会话日志的 `{session_id, seq 区间, 短引文}`，不是原文副本。
- **补丁表**——一次业务写入的完整变更清单；它要么整张成功，要么整张失败。
- **rejected**——被拒收的写入留下的记录（含原因与原始补丁），不是静默丢弃。
- **场景（scene）**／**片段（episode）**——多轮对话归纳出的情境与它的片段，由固化生成，永不常驻注入。
- **偏好（pref）**——可治理的稳定偏好，与身份文件分离。
- **身份段**——随插件发布、字节稳定的人格文本，不依赖库。
- **状态尾巴**——每轮可能变化的一小段状态（关系四维与档位、一条已确认偏好、一条待处理标记），有硬预算。
- **关系四维**——`temperature / trust / intimacy / understanding`，各 0–100，用于描述关系状态。
- **越界**——四维取值超出 0–100，或单次事件步长超出上限；由工具层拦截，返回拒绝。
- **按需召回**——模型在需要时发起的检索，不是每轮固定动作。
- **决策账本（decision）**——只增不改不删的操作记录，回答「谁改的、依据什么、为什么」。
- **操作单元（op_id）**——一次业务操作的身份；撤销以它为单位，不以字段为单位。
- **标记（flag）**——待处理的矛盾、过期或无据断言；它是节点，不是边。
- **固化（dream）**——夜间八步离线处理，确定性步骤先行。
- **L0–L3**——记忆的四个层次：L0 宿主会话日志（只作指针）、L1 断言 + 证据、L2 片段 + 场景、L3 身份文件 + 偏好节点。
- **未失效**——没有被 `superseded_at` 标记的版本；默认查询只看未失效。
- **降级**——记忆安装位是**两档**（整体 no-op / 只关向量路径，不存在半开，FR-18）；上下文治理安装位是**五档**（`full` / `fold-only` / `ledger-only` / `readonly` / `recovering`，FR-50）。两者不是同一个东西：**「降级两档」只指记忆位**，凡说「五档」必指折叠接管（AD-36）。
- **注入档位**——身份段 / 状态尾巴 / 按需召回三档，各有预算与退路。
- **档位（三种别混）**——①**注入档位**：上面那三档；②**降级档**：记忆位两档、折叠接管五档（见「降级」）；③**人格强度档位**：`persona.strengthMax`（默认 5）内的表达强度。文中单说「档位」时按上下文只可能是这三者之一，涉及范围歧义处一律写全名。
- **折叠阶梯**——上下文治理的四级处理强度（第 0 级 0-LLM 观测折叠 / 第 1 级模型摘要 / 第 2 级 v2 / 第 3 级 应急截断），见 AD-35。**注意勿与「L0–L3」混淆**：`L0–L3` 专指记忆分层，折叠阶梯一律写「第 n 级」，不用 L 记号。
- **密度**——与当前任务步相关的估算 token 占注入总估算 token 的比例（AD-42）。本 PRD 里它有一个**纯结构量的替身 `focus_ratio`**：分子只数身份段、状态尾巴、未折叠的近期原文，不数「相关性」这种要人来判的东西。凡说「按密度删」「密度下限」「密度不降」，判定一律以 `focus_ratio` 复算，不靠人工感觉。
- **`focus_ratio`**——密度的可复算形式：`(身份段 + 状态尾巴 + 未折叠的近期原文) 的估算 token / 注入总估算 token`，每轮记一条（FR-53）；折叠后不得下降（NFR-14）。
- **`req_ledger`**——要求账本：从用户消息里确定性抽取的硬约束清单，折叠必须逐字保住它（FR-47）。它是账本记录，不是记忆节点（AD-37）。
- **`UNRELIABLE`**——响应级结论态：本查询邻域一致性检查不通过时整批不给答案（FR-41）。与逐条三态 `CERTAIN` / `REFUTED` / `POSSIBLE`（FR-42）**不在同一层**，四者构成封闭集合，不得新增第五种。
- **`prompt_version`**——提示词契约的版本号，写进每一次模型调用的审计行与产物（FR-76）；改提示词必须同时改版本号。
- **`stageHistory`**——关系阶段的迁移历史，每次迁移追加 `{ts, from, to, cause}`（FR-66）。
- **`copy_confirm`**——本插件自产文案触及已批准固定措辞时的显式确认入参，不确认即拒绝提交（FR-77）。
- **`noise_removed`**——低干扰清理的审计标记：某条待办 / flag 从哪一轮起不再进注入与检查点选区（FR-54）。
- **`low_yield`**——折叠经济性审计标记：`breakeven_turns` 超过上限（默认 20）的那次折叠（FR-51）。

## 4. 功能

每条 FR 后的括号是它受约束的 AD；完整映射见 `addendum.md` §9。

**两组 FR 的关系**：§4.1–§4.6 是 v1 的交付面（Epic 1–7，已分解）。§4.8–§4.15 是 2026-11-25 依据 `docs/planning-artifacts/research/` 六条研究线补入的扩展组，§4.16 是它们碰到已交付契约时的变更登记。每条新 FR 的标题括号里都标了归属 Epic：标「Epic 3–7 增量」的补既有能力面的缺口；标「Epic 8」的是 2026-11-25 新开的上下文治理 epic（属 v1，替换宿主压缩器的两半同批交付）；标「Epic 9」的是人格保真的新能力面（不属 v1）。

**「不改既有 FR」的准确含义（避免被读成「完全没碰」）：** 不改变既有 FR 的**验收线**——`epics.md` 里已交付 story 的 AC 一条不动；但新增条目确实带进了**新的返回值字段与新的成本口径**（如 FR-41/42/43/58 扩展召回返回体、FR-62 引入图版计入成本）。这些扩展按 §4.16 的三条规则处理：原有语义归还既有 epic、新增项自带检查、且必须可缺席（缺省时旧契约逐字节不变）。**Epic 1 与 Epic 2 的验收标准不因本次修订改动任何一条**——新 FR 一律排在 Epic 3 及以后。

### 4.1 记忆：写入只有一条路（AD-1 / AD-2 / AD-3 / AD-4 / AD-5 / AD-6 / AD-21）

**描述：** 记忆从三个入口进来——agent 显式调用、用户显式命令、回合结束后的去抖抽取——但都汇到同一条写路径：一张补丁表、一次事务、一份决策账本。被拒的写入不静默丢弃，落一条 `rejected` 记录并挂标记。身份用业务键表达，节点 id 是存储局部量，不出现在导出、配置、日志里。实现 UJ-1。

**读取边界（v1 定案）**：抽取只读「显式写入 + 当前会话自上次游标以来的新增 seq」，不回溯、不外扩（AD-4）；不回填宿主历史日志。固化时的 ② 重放抽样只重放**库内已有证据指针**（经宿主可选查询能力回读短引文与 seq 区间），lookback 上限 30 天；任何路径都不把宿主消息全文写进库。

**功能需求：**

#### FR-1：一条记忆可以被写进来并追到来源（AD-1、AD-4、AD-6、AD-21）

**可测结果：**
- 写入后能按业务键查回该条，并取回 `{session_id, seq 区间, 短引文}`；短引文 ≤200 字符，超长时标截断。
- 命中手机号 / 身份证 / 邮箱 / 银行卡正则时，引文自动脱敏并标 `deidentified`。
- 导出默认排除已脱敏引文，需显式开关才包含。
- 来源不可解析时（宿主查询能力缺席），该条仍返回但标 `evidence-unresolvable`，绝不伪造原文（AD-6）。

#### FR-2：写入要么全成，要么全不成（AD-4、AD-5）

**可测结果：**
- 补丁表里任一 op 失败，整次写入不留下任何节点、边或账本条目。
- 被拒的写入留下一条 `rejected` 记录（含原因与原始补丁），且不可被普通查询当成记忆读到。
- 同一业务键不会同时存在两条未失效版本。

#### FR-3：改写会留下旧版本，而不是覆盖（AD-3、AD-5、AD-21）

**可测结果：**
- 改写后旧版本默认查询不再返回，历史查询能取回。
- 每次改写写一条决策账本条目，含操作者、操作单元、受影响对象清单。
- 业务数据（节点、边、账本）没有物理删除路径；仅三个具名豁免：快照目录清理、审计与日志轮转、卸载前导出后删除（AD-5）。
- 其余 `delete` / `unlink` 由静态门禁（AD-15 的 grep/AST 检查）阻断：故意在业务代码里写一次 `delete(`，CI 必须失败。

#### FR-4：召回只读、有界（AD-8、AD-12）

**可测结果：**
- 召回路径不产生任何写调用（含更新 payload 与刷盘）。
- 默认返回 5 条，硬上限 8 条；不提供翻页 / offset 循环。
- 默认只返回未失效版本。
- 召回结果可解释：命中哪些、耗时多少、是否降级、降级原因（取值封闭）。
- 模型只给分数，不给「删哪条」的许可：排序与剪枝按分数 + 阈值 + top-k 由代码决定，同一批分数重跑得到同一批结果。

#### FR-5：召回分三段，每段有退路（AD-8、AD-19、AD-23）

**可测结果：**
- ① 候选段超时（默认 250ms）才算「没有细节」；② 重排段（默认 600ms，经 System One 打分：`POST /systemone` 的 score 任务 + `SemIf`）超时只跳过排序、按候选顺序照常注入并标 `rerank_unavailable`；③ 注入段（默认 20ms）取不满就少给，不凑数。
- 三段合计硬上限 1000ms，到点交候选，**不返回空**。
- 同一回合至多重排一次；命中缓存不重复付费（缓存口径见 addendum §3）。
- 连续 3 次重排超时熔断 10 分钟，期间只走 ①③。
- 重排默认开启、可关闭；关闭后不得报警或计入降级。

#### FR-6：注入只有一个出口，且带预算表（AD-7、AD-11、AD-20）

**可测结果：**
- 身份段 ≤1200 字符，字节稳定：文本不变则不重写。
- 状态尾巴 ≤30 token：关系四维与档位、至多一条已确认偏好、至多一条待处理标记。
- 场景永不常驻。
- 超预算按 身份 > 状态 > 召回 顺序裁剪，并记一行审计。
- 注入路径不查库：缺值整段省略，不填默认值。

#### FR-7：每次注入与召回都可核（AD-7、AD-8、AD-20）

**可测结果：**
- 每次注入与每次召回各留一行审计：档位、条目、是否截断、耗时、是否降级、降级原因。
- 审计可按天回溯 30 天；不落库、不参与召回。
- 注入组装 p95 ≤30ms（其中 `compose()` 同步段 ≤20ms，AD-20）；召回 p95 ≤900ms；写事务 p95 ≤10ms。
- 看数有命令：按时间窗口输出 p50/p95 与降级计数。

#### FR-22：什么值得记、什么禁止记（AD-6、AD-17、AD-25）

**描述：** 承重缺口——SM-1 测的「该不该记」必须由一条功能需求约束，否则准确率无从谈起。

**可测结果：**
- 抽取的输入是会话片段 + 已有记忆的稳定身份，输出只有一张补丁表；禁止逐条流式写库。
- 用户显式说出的偏好 / 决定 / 纠正必须落断言；纯寒暄、纯执行性对话必须不落（两类各有 ≥20 条标注样本可判）。
- 证据缺失（拿不到会话原文）时该条只能标 `evidence-unresolvable`，不得凭印象写出引文。
- 模型给出的「推断」若无合法判别式，只能落成场景描述文本，不得进断言层（AD-17）。
- 单次抽取失败不重试超过一次；失败留 `rejected` 与错误码，不写半截。
- 越界读取 = 0：测试断言抽取与固化只碰「本轮新增 seq」与「库内已有证据指针」；每次回读都记 `session_id` 与 seq 范围，可审计复算。
- 回读 lookback ≤30 天，超出范围的证据标 `evidence-expired`，不回读原文。
- v1 的抽取阈值**偏 precision**：不确定即不落；漏记由 `remember` 工具与用户显式命令兜底，不计为缺陷。
- 评测时假阳性（错记）与假阴性（漏记）分开统计，**及格线按假阳性加权**——错记比漏记更贵：漏记可补，错记只能靠治理清账。

### 4.2 固化：夜里做确定性的事（AD-10、AD-14、AD-15、AD-25）

**描述：** 固化在夜间窗口（本地 02:00–05:00）优先执行；宿主不在线则在下次启动补跑当天一次；长会话跨过安静时段时改由**空闲触发**接管——最后一次交互后 30 分钟无新事件即跑一次，当天已固化则跳过（护栏见 FR-10）。八步固定顺序：确定性结算 → 重放抽样 → 模式提取 → 场景抽象 → What-If（v1 默认关闭）→ 剪枝归档 → 跨主题重组 → 策略提炼。①②⑥⑦ 不调用模型；③④⑤⑧ 一律「先提炼、后核验」：提炼用 Qwen/Qwen3.5-9B（G0-8 实测：原定 Qwen3.5-4B 不可用），核验用 deepseek-ai/DeepSeek-R1-0528-Qwen3-8B 检查证据是否齐全、结论是否与证据矛盾，核验不过则该步不提交、整体停在段边界。每步单独落一条固化日志，可断点续跑。

**功能需求：**

#### FR-8：八步顺序固定，且确定性步骤不碰模型（AD-10、AD-14、AD-17）

**可测结果：**
- ①②⑥⑦ 的依赖对象里不含模型客户端——由测试断言，不靠代码评审。
- ③④⑤⑧ 的产物带提示词版本与周期标识。
- ③④⑤⑧ 每个模型步骤都留下「提炼产物 + 核验结论」两段记录；核验不通过的步骤不得提交，后续步骤按缺步处理，不得带病继续。
- 核验模型对一条刻意删掉证据指针的产物必须判「不通过」——这条作为 G0-8 的验收样例。
- ⑤ 默认关闭；开启时有硬约束（深度 ≤2、默认一条、单锚点一分叉），且产物永不进断言层。

#### FR-9：每一步独立提交，能从断点续跑（AD-10、AD-15、AD-21）

**可测结果：**
- 进程在第 ④ 步被杀，重启从 ④ 续跑，不重跑 ①②③。
- 每条固化日志记录阶段、种子、diff 摘要、消耗的 token。
- 确定性步骤（①②⑥⑦）与 ② 的抽样可复现（种子由日期与阶段决定）；③④⑤⑧ 只要求固化日志记录提示词版本、种子、输入锚点集与输出摘要，**不承诺逐字节一致**。
- 一天最多一个周期标记。

#### FR-10：预算三层取最小，超了停在段边界（AD-10、AD-25）

**可测结果：**
- 阶段预算、日 token 上限、provider 配额三者取最小。
- 一次固化至少发生 6 次模型调用（③④⑧ 各一次提炼 + 一次核验），日调用上限必须覆盖这个下限并留重试余量。
- 命中即停在阶段边界并记一条截断记录，不半途写入。
- `--dry-run` 只跑 ①②，出 diff 不写库。
- 错过**不补历史多天，只补当天一次**：启动时若当天周期标记不存在且不在安静时段，排一次；连续 3 天在 02:00–05:00 离线、第 4 天 09:00 启动，恰好跑 1 个 cycle，固化日志有记录。
- 空闲触发：最后一次交互后 30 分钟无新事件，且当天 `dream_cycle:<date>` 不存在、无进行中轮次、无排队写入时开始一次固化，日志标 `idle_triggered`；同一天连续空闲 10 次仍只产生 1 个 cycle。
- 触发途中用户发起新交互，只在**段边界**让路（当前步提交完再停，可从断点续跑），不打断写事务、不占下一轮首 token 路径。
- 审计里能看到最近一次固化的日期与结果——「从未运行」是可见状态，不是沉默。

### 4.3 治理：能查账、能反悔（AD-9、AD-21、AD-22、AD-24）

**描述：** 治理面回答三个问题：谁改的、依据什么、为什么。冲突分三级：自动档（符号可判，唯一会改数据的档）、提案挂起档、人工解除档。撤销以操作单元为单位。

**关于「自动」的取舍（对简报的反转）：** 简报主张「落库一律待人确认」，v1 允许符号可判的自动裁决。唯一的理由是**整条操作可撤销**（AD-22），不是「自动更省事」——自动档成立条件严格到只覆盖同一谓词同一主体的取值冲突，其余一律挂起。

**功能需求：**

#### FR-11：每条记忆都答得出「谁改的、依据什么、为什么」（AD-21）

**可测结果：**
- 三个问题分别由决策账本（操作者与时间）、证据指针（来源与 seq 区间）、决策账本（类型、理由、提示词版本、引用先例）回答。
- 账本只增不改不删。
- 一次查询即可返回版本链 + 账本 + 证据，不需要多步翻找（由 FR-23 提供命令）。

#### FR-12：冲突分三级，只有自动档改数据且必须可撤销（AD-9、AD-22）

**可测结果：**
- 自动档成立条件严格：同一谓词的单个取值、同主体同谓词、有效区间重叠、归一化值不同。
- 自动档结果 = 旧版本置失效 + 新断言 + 一条已解决的标记 + 一条矛盾边，全在同一事务内。
- 其余冲突只能「提案 + 挂起」，不得改动既有断言；人工解除是唯一的解除路径。
- 标记有完整生命周期：创建 → 挂起 / 已解决 / 已证伪 / 已撤销；可被查询按状态过滤（AD-12）。
- 自动档的每次裁决都能按操作单元整体撤销。

#### FR-13：撤销是一个操作单元（AD-5、AD-22）

**可测结果：**
- 每个操作带操作单元标识与受影响对象清单；清单只含状态类对象与边，不含账本类对象。
- 撤销在单事务内反向执行，并追加一条「撤销」账本条目。
- 复合操作要么整体撤销、要么整体不动。
- 判据（比较域写死）：固定 20 条 fixture 查询、关闭重排（或固定缓存键），只比较 `{mem_key, active_version, flag_status, edge_label}` 的集合；不比顺序、耗时与审计字段；账本类对象不参与比较。

#### FR-14：推断必须可结算（AD-17）

**可测结果：**
- 推断类断言必须带可执行的判别式（操作符限于 `eq/ne/gt/lt/gte/lte/exists/count_gte`，字段限于白名单）与结算状态（未定/已确认/已证伪）。
- 缺判别式或字段不在白名单 → 拒收，该推断只能落成场景描述文本。
- 证伪不删除，改为置失效 + 一条已证伪标记。

#### FR-23：治理查询是 v1 的聊天内命令交付物（AD-21、AD-24）

**描述：** SM-2（30 秒答清三问）需要一个真实入口；治理界面在 v1 之后，命令必须在 v1 交付。

**命令面形态（2026-11-25 用户裁定）：** 「不要任何 CLI，只保留 command」。本项目不提供任何进程外可执行入口——不留 `bin` 字段、不留面向用户的 `scripts/` 命令、不 spawn 子进程（与 AD-1 单进程纯插件一致，子进程边界的唯一例外见 NFR-13——该条在 v1 休眠、无消费者）。`scripts/` 只保留开发期工具（构建、测试、lint、层依赖检查、评测驱动），它们不是交付给用户的命令面。

**可测结果：**
- 命令面为**十条平铺注册**（2026-11-26 P0-3 裁定，取代本节最初「四条只读命令」的写法）：`/omw-explain <mem_key|关键词>`（版本链 + 账本 + 证据，一次调用）、`/omw-flag-queue [--status open]`、`/omw-export [--include-quotes]` 三条本 FR 新增；`/omw-doctor`、`/omw-pred-promote`、`/omw-evidence`、`/omw-history`、`/omw-ledger`、`/omw-stats`、`/omw-brief` 七条沿用既有裁定。全部走同一注册路径（`ctx.commands.register`），**没有裸 `/omw` 子命令分派**；字段名与 AD-24 的治理投影 DTO 对齐。
- 结果以消息文本返回，**没有退出码语义**：未命中时返回明确的空结果并带标记（`NOT_FOUND` / 对应 `OMW_*` 码），不打印调用栈、不返回交互式分页。
- 输出为结构化 JSON 与人类可读两种；字段名与导出格式一致。
- 任取一条记忆，从执行命令到看到三个答案 ≤30 秒（含人工阅读）。
- 本 FR 的三条命令只读：不产生任何写入、不更新热度。

### 4.4 人格：不依赖库（AD-11、AD-12、AD-13）

**描述：** 身份是随插件发布的文件，字节稳定；状态是可缺席的一小段。

**常驻预算的收窄：** 早期设计稿给的是「≤120 token 常驻档（含当前场景与活跃任务）」；v1 收到 30 token，场景常驻为 0，多出来的偏好走按需召回——这是有意的取舍，理由是每轮多占的 token 永久留在历史里且击穿前缀缓存。

**功能需求：**

#### FR-15：身份段不依赖库（AD-11、AD-13）

**可测结果：**
- 库打不开时，身份段照常注入。
- 身份段文本哈希不变则不重写，保持前缀缓存可用。
- 身份段不承载任何逐轮变化的内容。

#### FR-16：状态可缺席，但不许编造（AD-7、AD-12、AD-20）

**可测结果：**
- 状态字段缺失或库不可用时整段省略，不填默认值。
- 四维初值 50、单次正向步长 ≤3×强度（负向 ≤2×强度）、三档阈值 45 / 70 可从配置读出并解释档位归属。
- 越界（四维超出 0–100 或步长超限）在工具执行前返回拒绝，不靠提示词提醒。

### 4.5 运维：坏了要看得见（AD-13、AD-18、AD-24、AD-25、AD-26）

**描述：** 装、看、坏、修四件事。降级只有两档。

**功能需求：**

#### FR-17：启用是可验证的三步，不是一步（AD-26）

**可测结果：**
- 依赖声明、宿主补丁配置、重启验证三步缺一不可；改错文件（改生成物而非补丁文件）必须能被文档与体检识别。
- 启用后有体检命令（聊天内 `/omw doctor`），检查五项：库能开、快照校验过、维度匹配、凭据可用、注入段已注册。
- 对五种错误配置（无库、快照损坏、维度不符、凭据失效、注入段未注册），体检各判为该单项 fail，并在消息里点名失败项、配置键名与对应错误码（无退出码语义）。

#### FR-18：降级只有两档（AD-13、AD-18、AD-19、AD-23）

**可测结果：**
- 库打不开、快照校验失败、配置维度与库不符、契约版本不符 → 整体 no-op：不注入记忆、不注册写工具、不排固化、不写任何节点，只记一行原因。
- 仅向量路径故障（凭据 401/402、embedding 返回维度不符）→ 只关向量路径，文本与图召回照常。
- 不存在中间态：不写一半、不注入半段；注入与工具各自独立降级，不互相回滚（AD-18）。
- 错误码封闭为**十一个**（`OMW_DB_OPEN` / `OMW_SNAPSHOT_VERIFY` / `OMW_DIM_MISMATCH` / `OMW_EMBED_AUTH` / `OMW_EMBED_QUOTA` / `OMW_EMBED_TIMEOUT` / `OMW_EXTRACT_FAIL` / `OMW_DREAM_BUDGET`，加 CAP-9 的 `OMW_ROUTE_LOAD` / `OMW_ROUTE_DISPATCH` / `OMW_ROUTE_MISMATCH`），新增或改名都算破坏兼容。（2026-11-25 修订，原为八个）
- 恢复需要重载插件，不在进程内自愈重试。

#### FR-19：备份与恢复可预期（AD-14、AD-24）

**可测结果：**
- 每次启动检查「今天有没有已校验快照」，缺则补做；重复运行最多多一份，不视为错误。
- 迁移前强制快照；保留最近 7 份。
- 恢复必须先停库再恢复（Windows 句柄锁）。
- 迁移先 dry-run。

#### FR-20：成本有上限且可看（AD-25、AD-26）

**可测结果：**
- 四类日上限各自可配：抽取调用、向量调用、重排调用、固化 token。
- 命中后各自降级而非报错：抽取只记不抽、向量停止补写、重排降级为候选顺序、固化停在段边界。
- 审计报告可按时间窗口输出 p50/p95 与降级计数。

#### FR-24：全量数据可导出（纯文本 + JSONL）（AD-3、AD-5）

**可测结果：**
- 一条命令导出全部断言（含版本链关系）、偏好、场景摘要与账本；默认不含已脱敏引文与节点 id。
- 导出格式为纯文本 + JSONL，可直接归档；不需要本产品即可读懂。
- 导出是卸载的前置条件：未导出不允许卸载（AD-5）。

### 4.6 从 mnemon 迁移（AD-16、AD-24）

**描述：** 替代而非共存：一次性把旧文件转成断言与偏好，不删源文件，留回滚开关。

#### FR-21：迁移幂等且可回退（AD-2、AD-3、AD-5、AD-16）

**可测结果：**
- 重复运行不产生重复节点（以迁移标识判定「这行迁过」）。
- 迁移用业务身份，不用行哈希冒充身份。
- 迁移完成后，一次会话的注入快照里 mnemon 段落出现次数 = 0，身份段唯一；两套插件同时安装时仍只有一条注入路径。
- 迁移前必须先禁用或卸载 dsh-mnemon（否则报错退出，不半途迁）。
- 迁移的产物是一份**迁移报告**：迁入 N 条 / 跳过 M 条（逐条原因）/ 去重合并 K 条 / 失败 0 条，落 `migrations/<ts>-report.md`；用户第一眼看到的是它，而不是一个空荡荡的会话。
- 迁移前先落一份**迁移前快照**（`snapshots/pre-migration-<ts>`）；迁移失败自动回滚到该快照——失败不改变任何东西：不留半迁节点、不删源文件、不改配置。对用户的承诺是「失败不改变任何东西，可重跑不会重复」。
- 回滚与重跑是同一件事：回滚后再跑一次，结果与首次成功迁移逐条等价；报告追加而非覆盖。
- 回滚开关打开并重启后只恢复本插件的 legacy 注入行为，不自动重新启用 mnemon；迁移节点按「置失效 + 导出后卸载清理」处理（见 FR-3 的豁免）。

### 4.7 横切非功能要求

这些是上文的约束面，不是额外功能；编号与 epics 文件一致。与 FR 同理，NFR-11、NFR-12 属 CAP-9「入口与路由」（派发中的路由约束），写在 `entry-routing.md`，不在此重列；NFR-13…NFR-16 是 §4.8 起扩展组带来的新增约束。

- **NFR-1** 注入组装 p95 ≤30ms（`compose()` 同步段 ≤20ms）。
- **NFR-2** 召回 p95 ≤900ms（含重排）；重排不可用比例 <5%；候选真空比例 <1%。
- **NFR-3** 写事务 p95 ≤10ms。
- **NFR-4** 任一降级路径不得产生幽灵状态（注入了却不写、工具半可用）。
- **NFR-5** 不复制宿主消息全文；引文 ≤200 字符且可脱敏；导出默认不含敏感引文。
- **NFR-6** 全量数据可导出为纯文本 + JSONL，且不含节点 id。
- **NFR-7** 注入、召回、固化、写入各留审计行；按天切分、保留 30 天、只落文件。
- **NFR-8** 单进程插件形态：不监听端口、不起后台服务、不常驻任何进程；子进程边界按 NFR-13 收敛（默认禁止，仅本地量测一类的短命子进程例外）。
- **NFR-9** 常驻注入预算按 FR-53 的注意力池比例分配（`govern.attentionPoolRatio`，默认 0.6），身份段 ≤1200 字符与状态尾巴 ≤30 token 是**池内**上限、不是各自独立的配额；召回 ≤5 条属按需通道，不计入常驻池。
- **NFR-10** Windows 单文件库的句柄锁语义：恢复必须先停库；快照目录创建撞名属预期分支。
- **NFR-13** 子进程边界（2026-11-25 放宽原「不 spawn 子进程」）：允许一次性短命子进程（本地量测工具一类），必须带超时（默认 120 秒）、退出即回收句柄与临时文件；不常驻、不监听端口、不以后台服务形式存在；失败只降级为「不成账」，不阻断主流程。
- **NFR-13 的 v1 状态：休眠，无消费者**（2026-11-25 裁定保留作铺垫）。v1 唯一会用到它的 FR-61 已随视频组整组 Deferred（§4.12），因此 v1 交付物里**不应出现任何子进程调用**——若代码里出现，按违反 NFR-8 处理，不按本条豁免。本条的价值是：等视频组重启时不必重新裁定一次边界。它与 AD-15「`child_process` 全仓禁止」的冲突，已在架构侧登记豁免并生效（登记位置：`ARCHITECTURE-SPINE.md` AD-15 的「NFR-13 具名豁免」段，2026-11-25）。
- **NFR-14** 折叠不得降低 `focus_ratio`；每折一行审计，`breakeven_turns` 与折叠前后密度可由审计复算。
- **NFR-15** 人格文本字节稳定：折叠、库不可用、降级三种情形下 `sha256(personaText)` 不变。
- **NFR-16** 三值结论（`CERTAIN` / `REFUTED` / `POSSIBLE`）与证明链必须可复算：同一库快照 + 同一查询重跑，结论与 `justification_id` 链逐条相同，不依赖模型打分。

### 4.8 记忆卫生：记重了、记了等于没记（AD-3 / AD-5 / AD-8 / AD-17）

**描述：** FR-22 规定了「该不该记」，FR-3 规定了「改写留版本」，但都没规定「同一件事记了两遍」和「改写后内容一模一样」。这一组补的是写入侧的两道过滤——精度过滤（不记重）与放大过滤（不变不写）。二者都不改既有 FR 的语义，只在既有写路径上加前置判定。研究依据：九家实现里只有 LangMem 有「真变才写」的硬机制，而 mem0 的去重窗口只覆盖 top-10 旧条——**去重窗口本身就是设计变量**，不写清等于默认漏检。

**功能需求：**

#### FR-34：写入前先过一道去重，精确命中的不落新条（Epic 4；AD-3、AD-4、AD-6）

**可测结果：**
- 写入前按业务键 + 归一化值算指纹；与库内任一未失效版本完全相同时，不新建断言节点、不改其内容、不写账本，返回旧条业务键并标 `duplicate_exact`。
- **但重复命中要留一次「又见到过」的痕迹**（2026-11-25 裁定）：追加一条指向本次 `source seq` 的 `evidence` 边，不改断言节点本身。理由是 FR-45 的置信带与 FR-69 的偏好晋升都要问「这件事被独立见到过几次」——若重复命中什么都不留下，这两条就永远数到 1，「重复陈述 10 次净增 1 条」也就成了恒真的空话。
- **不存计数器**：需要「出现过几次」的地方一律按 `evidence` 边计数（去重规则见 FR-45 的 `source_independence`），库内不存在可变的计数字段——与 FR-36「热度只算不写回」同向。
- **重复命中同样留审计行**（与 FR-35 的 `noop_unchanged` 对称，两者不能一个有观测一个没有）：记 `duplicate_exact` 标记、命中的旧业务键、本次的 `source seq`、耗时。配合上面的 evidence 边，SM-5 的「重复陈述 10 次」可以两头核：断言节点净增 1，而该断言的 `evidence` 边净增 10（同源去重后按实际来源数）。
- 去重命中的判定在事务开始前完成，与 FR-35 同一位置；两者互斥：指纹相同走本条，指纹不同但内容一致走 FR-35（理论上后者不发生，若发生记 `dedup_conflict` 并按 FR-35 处理）。
- 近重复（指纹不同但归一化文本相似度达阈值）**不自动合并**：落一条 `flag`（`kind=possible_duplicate`，带两条业务键与相似度），断言照常写入，两条都保持可召回。
- 去重窗口是「全库同谓词同主体」的历史版本，不是仅取 top-k 召回结果；窗口大小写进配置并可读出。
- 相似度阈值标**待标定**（§8.2 的 D1）：v1 以 0.9 为起点，但要先用一份**专门的近重复语料**（`eval/duplicate-pairs.jsonl`，人工标注重复/非重复对各 ≥100 对）实测出误合并率后回填——`eval/golden-l1.jsonl` 是「该不该记」的样本，里面没有近重复对，扫不出这个阈值。未标定前只产出 flag，不做任何自动合并。
- 合并动作只来自治理路径（FR-12、FR-38）且可撤销；去重本身从不删任何一条。

#### FR-35：内容没变就不写版本（Epic 4；AD-3、AD-5、AD-21）

**可测结果：**
- 补丁在事务开始前与同业务键当前未失效版本逐字段比对 `kind` 与 `content`；完全一致时不新增版本、不写账本行，返回当前版本并标 `noop_unchanged`。
- 比对是**整条内容**比对，不是「补丁里传了哪些字段」比对：补丁按全量字段提交，缺字段以当前值补齐后再比。
- 与 FR-3 的边界：`kind` 或 `content` 任一不同就必须留旧版本；本条只豁免「完全相同」这一种情形。
- `noop_unchanged` 只记审计行（业务键、耗时），不计入 FR-20 的日上限用量。
- **与 FR-34 的分工写死，避免两条被读成同一件事**：FR-34 是「同一条断言被**再次观测**」（新 `seq`，追加 `evidence` 边）；本条是「**同一次观测被重提**」（补丁重放，没有新 `seq`，因此不追加边）。判据只看有没有新 `seq`，不看内容像不像。

#### FR-36：热度只算不写回（Epic 5；AD-8、AD-20）

**描述：** AD-8 只有一句定性规则（幂律 + 对数 rehearsal 作排序因子），没有公式也没有字段——原则存在、实现不存在。本条把它落成可复算的读时投影。

**可测结果：**
- 热度分 = 幂律激活 × 对数 rehearsal 因子，两个系数入配置（`recall.decayExponent`、`recall.rehearsalScale`）并可读出；默认值标**待标定**（§8.2 的 T1）。
- rehearsal 次数**取自决策账本**（AD-21 的 `decision` 节点，字段 `kind` 与 `affected[]` 已够用），不在断言节点上增加可变计数字段；测试断言一次召回前后库内容逐字节不变。
- **不取审计行作为主来源**：审计按天切分、只留 30 天（NFR-7），而快照恢复后审计不随库回滚，用它算热度会让「同一条记忆在恢复后突然变冷」——这是评审指出的真实缺陷。审计行只作旁证（对账时核对账本条数），不进公式输入。
- 同一库快照 + 同一时间基准重跑，排序逐条相同（注入固定 `now` 断言）。
- 热度分只进排序，不进相关性下限判定，也不出现在注入文本里。
- 提供开/关对照脚本：关闭时纯按相关性排序，两组排序差异可输出——未测出收益前不设为默认开。

#### FR-37：长期不提的只归档，不删（Epic 6；AD-5、AD-10、AD-21）

**可测结果：**
- 固化第 ⑥ 步（剪枝归档）按阈值把长期未命中且未被账本引用的断言置 `valid_to` 并记归档状态；不物理删除，历史查询可取回。
- 命中断言晋升只改权重，不改 `content`、不改证据指针；晋升与归档都写 `dream_log` 与决策账本。
- 归档后默认查询与召回不再返回；`/omw explain` 仍可读到它与归档理由。
- 归档可按 `op_id` 整批撤销，撤销后检索结果逐条等于归档前。

#### FR-38：同一实体的不同写法并成一条（Epic 6；AD-3、AD-9、AD-17）

**描述：** 谓词已有显式 `aliases` 合并，实体只有 `aliases[]` 字段却没有归并路径——`上海` 与 `上海市` 会分裂成两条互不相关的链。这是既有缺口的同类延伸。

**可测结果：**
- 固化第 ⑦ 步（跨主题重组）按**确定性规则**把归一化后相同的别名并入同一实体，账本记被合并的实体键。
- 只允许确定性规则（去空白、大小写、全半角、常见行政后缀）；判不上的不合并，只挂 `flag`（`kind=possible_alias_merge`）。
- 误并必须可逆：撤销该 `op_id` 后两实体恢复独立，各自断言与边逐条还原。
- 归并前后断言数、边数守恒；节点总数只减不增（合并实体使节点减少，断言一条不丢）。

#### FR-39：每日一份只读简报，只落文件不推送（Epic 3；AD-5、AD-24）

**可测结果：**
- `/omw brief [--date YYYY-MM-DD]` 生成当日简报文件（未决 flag、在办任务、当日固化摘要），落在审计目录旁；不进注入、不进召回、不落库。
- 只读：不产生任何写入、不更新热度、不触发固化。
- **不主动推送**：无定时投递、无消息通知、无后台任务；用户不执行命令就没有文件。
- 同一日期重复执行覆盖同一文件（幂等），内容与当时库状态一致。

### 4.9 证明式召回：不确定性可判定（AD-8 / AD-9 / AD-17 / AD-21）

**描述：** 现有召回只回答「命中了什么」，不回答「凭什么」和「能不能被反驳」。这一组把不确定性做成**可判定的三态**，并让每次推导留下可追溯的证明坐标——不是引入本体推理器，也不是做世界模型预测。其中 FR-40 是唯一「现在不做以后做不了」的项：推导事实不存历史，事后补 `rule_id` 意味着**全部历史推导无法溯源**。

**功能需求：**

#### FR-40：每条推导都留下证明坐标（Epic 3；AD-17、AD-21）

**可测结果：**
- 推导产生的断言/边必须带四列：`derivation`（推导方式）、`rule_id`（用了哪条规则）、`justification_id`（支撑前提集合的稳定 id）、`depth`（推导深度）。
- **四列里的第一列叫 `derivation` 而不是 `origin`**，因为 `origin` 已被 `data-model.md:32` 占用为二值枚举 `observed | inference`，AD-17 据它挂「`origin=inference` 必带 `falsifier` 与 `settle_state`」的闸门（`ARCHITECTURE-SPINE.md:154`）。两者不可混写：`derivation ∈ {rule, dream} ⇒ origin = inference`，即任何带推导的条目都同时触发 AD-17 的可证伪要求。
- 四列写入时落定，之后不可改写；缺任一列的推导写入直接拒收（落 `rejected` 并带原因码）。
- `justification_id` 由前提集合的内容哈希算出，**不含节点 id**——重建库后同一前提集合仍得同一 id。
- 无推导来源的存量断言四列可取空值，但必须显式标 `origin=observed`（与既有枚举一致）且 `derivation` 空，不留空混淆。
- `/omw explain` 能列出给定断言的 `rule_id` 与深度；`depth > 1` 时逐层可列。

#### FR-41：本查询邻域不一致时先说不一致，不给答案（Epic 3；AD-9、AD-12）

**可测结果：**
- 提交冲突裁决前与执行召回前各做一次一致性检查；检出不一致（同主体同谓词同区间存在两个未失效且归一化值不同的断言，且不满足 FR-12 自动档条件）时返回 `UNRELIABLE` 并列出冲突对。
- `UNRELIABLE` 是**响应级状态**，与 FR-42 的逐条三态不在同一层：逐条结论仍只有 `CERTAIN` / `REFUTED` / `POSSIBLE`，而 `UNRELIABLE` 表示「这次整批不回答」。四者构成封闭集合，不得新增第五种。
- `UNRELIABLE` **不得降级成空结果**——空结果表示确实没有，`UNRELIABLE` 表示有但不该用。
- **检查范围就是本查询邻域**（标题里的「邻域」是限定不是修饰）：只查本次查询涉及的主体与谓词的一跳邻域，**不做全库求值**。邻域规模上限入配置并标待标定（§8.2 的 D2），但邻域检查预算 ≤50ms 是硬约束不是待标定。
- **邻域检查的预算是硬约束，不是待标定项**：单次检查 ≤50ms，超过即放弃检查、按 `POSSIBLE` 返回并在响应里标 `consistency_skipped`。理由：召回全链路 p95 预算只有 900ms（NFR-2），起初 `addendum.md` 给的 `consistency.checkTimeoutMs` 默认 5000ms 会让这一条单独吃穿整个预算——那是错的，5000ms 只适用于下面那条独立命令。
- **全库一致性检查是独立命令**，不进召回路径：`/omw-stats` 之外单列，显式触发、可长跑、结果只落报告不改数据。
- 检出后不改任何数据；解除只能走 FR-12 的裁决路径。

#### FR-42：召回结论只有三种，且不许混用（Epic 5；AD-8、AD-17）

**可测结果：**
- 每条返回标 `CERTAIN` / `REFUTED` / `POSSIBLE` 之一：有完整证明链且无未解决冲突为 `CERTAIN`；有反证且无反反证为 `REFUTED`；其余为 `POSSIBLE`。
- `POSSIBLE` 不得当成事实注入：注入文本必须带固定模板的不确定性措辞，与 `CERTAIN` 措辞不同，模板带 `prompt_version`。
- 剪枝只按相关性，不按态——`POSSIBLE` 不得因态低被优先剪掉。
- 三态是**逐条结论**；整批不回答的状态是 FR-41 的 `UNRELIABLE`，两者不在同一层，不得混写。
- 同一库快照 + 同一查询重跑，三态判定逐条相同（不依赖模型打分）。

#### FR-43：证不出来时给出还差什么（Epic 5；AD-8、AD-17）

**可测结果：**
- 结论为 `POSSIBLE` 且被请求解释时，返回「证到哪一步、差哪一条」：已闭合的证明子树 + 至多 N 条缺口描述（N 默认 3，可配置）。
- 缺口只报「补上这条能闭合当前目标」的条目，不做穷举枚举。
- 缺口计算不发起写入、不改状态；额外开销计入召回预算，超预算即只返回已闭合部分。
- 缺口的 `rule_id` 与 FR-40 四列同源，可用同一套坐标复现。

#### FR-44：事实要升成契约，必须先过三道判据（Epic 3；AD-9、AD-21、AD-25）

**可测结果：**
- 断言从「观察」提升为「契约」（可参与裁决的约束型知识）必须过三条：**P1** 有可解析的证据指针；**P2** 不与其他契约矛盾，或已显式声明优先级——求值范围写死为「同一 `(subject, predicate)` 下所有未失效的契约」，不跨谓词；**P3** 概念数在上限内。任一不过只能留作观察。
- **P3 的上限数字不是 v1 的拒收依据**：`tbox.maxConcepts = 10` 没有来源，研究件明写 TBox 范围未决（`extract-ontology.md:13`）。已移入 §8.2 的 D6「设计待解决」；解决前 P3 **只产出 flag 记账不拒收**，理由见 §8.2 的统一规则（未标定值不得触发不可逆动作）。
- **P1 或 P2 不过时**新契约拒收并落 `rejected` 与原因码，不静默丢弃；P3 不过时按上一条只落 flag，不拒收。两者都不得静默丢弃。
- 提升写决策账本，可整条撤销；撤销后既有裁决不回滚（裁决是历史事实），但后续裁决不再引用它。
- 模型只能提案、不能自升：提升必须经人工确认路径。

#### FR-45：置信度由证据计数推导，不存点概率（Epic 3；AD-17、AD-21）

**可测结果：**
- 库内不存任何浮点点概率，也不存计数器；置信带由证据计数（支持数 / 反驳数 / 独立来源数）在**读时**推导，计数＝该断言上的 `evidence` 边按下面的 `source_independence` 去重后的条数（含 FR-34 因重复命中而追加的边）。
- **`source_independence` 是封闭定义，不留解释空间**：两条证据算同一来源，当且仅当它们的 `evidence` 节点指向同一宿主 `session_id` **或**规范化后的引文前缀（前 80 字符）完全相同。同一来源的多条证据在计数时只算 1。该规则是纯函数，可在测试里直接跑。
- 推导带搁置时长折扣：同样证据下越久未复核，置信带越宽；折扣曲线入配置并标**待标定**。
- 证据计数变化只走新断言 + 边（`supports` / `refutes`），不允许原地改计数字段。
- surprise（与预期的偏离）只用于分配写入与固化预算，**不得**用于判定真假。
- 同一证据集合重算得到同一置信带。

### 4.10 上下文治理·确定性半边（折叠阶梯第 0 级）：不花模型，也不爆窗（AD-28 / AD-35 / AD-36 / AD-39 / AD-42）

**描述：** CAP-7 在架构侧已有 AD-28…AD-45 十八条，但 PRD 里从未写入需求。本组落**不花模型的那一半**：第 0 级观测折叠（0-LLM）、要求账本、可逆指针、五档降级、经济性审计、人格免疫、注意力池。唯一有损的第 1 级摘要在 §4.14，同样归 Epic 8（见那里的说明）。

**为什么两半都在同一个 epic（2026-11-25 裁定，最终落在 Epic 8；取代原先「第 1 级推 Epic 8+」的写法）：** 因为启用 CAP-7 必须**替换宿主的 `compaction-basic` 条目**（`CONTEXT-GOVERNANCE.md:400`：否则两个压缩器同时接管历史），而一旦替换，宿主的散文压缩就没了。第 0 级只折工具输出，对用户与助手的散文对话**零覆盖**——只交付第 0 级等于拿掉通用压缩器、换上一个窄得多的，长散文会话会一路涨到上游拒绝。所以第 1 级不是「可晚点的优化」，是这次替换的**成立条件**，必须同批交付。

**功能需求：**

#### FR-46：不花模型也能把没用的工具输出折掉（Epic 8；AD-28、AD-35、AD-42）

**可测结果：**
- 第 0 级四条判据全部是已发生事实：单条工具结果超阈值（默认 4000 字符）且非报错、同路径被后续读取或编辑取代、同命令族重复输出、被后续编辑取代的 diff。
- 产物是**桩**不是摘要，必须含坐标：`[folded: <路径或命令> → seq 起-止, 字节数]`。
- 报错结果原样保留（错误串是承重内容）；含唯一标识（哈希、ID、时间戳）的重复输出不折。
- 判不上的不折——不存在「猜它没用」这条路径。
- 关掉所有模型调用，10 轮重工具会话不爆窗（只靠第 0 级）。此为闸门，不过则补判据，**不得**提前开第 1 级顶替。

#### FR-47：已被抽取的约束，折一百次也不许丢（Epic 8；AD-29、AD-31）

**描述：** 这条只管**已经进账本的**约束——「抽不出来」不归它判（那是提取器召回率的事，见下方第三条），「抽出来了却丢了」才归它判。两者的判据分开写，避免用一个不可观测的承诺（「用户说过的都不丢」）冒充可测结果。

**可测结果：**
- 每会话维护要求账本 `req_ledger:<session_id>`，由**确定性提取器**从真实用户消息抽取，条目含 `{seq, kind: goal|constraint|prohibition|authorization|scope, text_norm, status, source_seq}`。
- 账本不可由模型写：模型无法增删改条目，只能通过用户新消息改变它。
- 折叠时账本由引擎**逐字填入**检查点固定节，模型不得改写该节。
- 折叠后做覆盖核对与极性核对（否定词、上下限、方向、作用域）；任一 `active` 条目丢失即 `fold_blocked`，历史保持不变。
- 已退役/被取代的条目必须随撤销指令一起剔除；退役条目复燃记 `RETIRED_REINTRODUCED` 并阻断。
- 账本会话级、随会话结束失效；结束时**不**复制进记忆库（抽取仍从 L0 读）。
- **提取侧与保持侧分开报数**：以 `CONTEXT-GOVERNANCE.md:341` 的 **G-ctx-2 二十条约束压力集**（含否定、上下限、方向、作用域、授权五类）为固定夹具，折叠前后各跑一遍，分别报 **提取器召回率** 与 **极性保持率**（`requirement-20.md` 的判定口径、`rubric-context.md` 定义什么算「没丢」）。两个数**只报数、不设通过线**——下界属 §8.2 的待标定项（`CONTEXT-GOVERNANCE.md:428` 已承认确定性规则抽不出隐含约束），在标定完成前只进报告与 `low_yield` 标记，不触发阻断。

#### FR-48：折过的原文永远找得回来（Epic 8；AD-30、AD-6）

**可测结果：**
- 每个折叠块必带 `{session_id, seq_from, seq_to}`；展开只把该区间从已遮蔽恢复为当前并置块状态「已展开」——不复制、不重写、不移动原文。
- 指针不可解析时（宿主查询能力缺席、seq 缺号）该块标 `degraded: evidence-unresolvable`，仍可读摘要，但不得声称可展开。
- 折叠不改宿主日志、不改 seq 编号；测试断言折叠前后按同一 seq 回读得到逐字相同原文。
- 不可解析的块必须在 `context_status` 里如实列出，不得显示为正常。

#### FR-49：折叠的状态与展开走固定工具面（Epic 8；AD-40）

**可测结果：**
- 本组只交付两个工具，入参固定：`context_status()`（只读：占用、可折区间与真实尺寸、最近折叠、当前降级档）、`context_expand({block, toFile?})`（恢复区间或写文件，保前缀）。
- 返回统一包封 `{ok, items?, degraded, reason?}`；工具返回码在既有封闭集（`E_BUDGET` / `E_TIMEOUT` / `E_DEGRADED` / `E_BOUNDARY` / `E_GATE_DOWN`）上**仅新增** `E_FOLD_BLOCKED` 与 `E_FOLD_NOT_SMALLER`。
- 两套码别混：`OMW_*` 十一个用于日志与体检（FR-18），`E_*` 用于工具返回；本组只动后者。
- `context_fold` 不在本组：它随折叠阶梯第 1 级交付（§4.14，同为 Epic 8），本组交付期间模型**没有申请入口**，折叠只由 FR-46 判据自动触发。`context_search` 按 AD-35 分期属 v2，v1 不交付。
- 工具改名或改签名必须先改 AD-40，属破坏性变更。

#### FR-50：上下文治理坏了自己降档，不牵连记忆与人格（Epic 8；AD-36、AD-13、AD-18）

**可测结果：**
- 状态封闭五档，由单一状态机持有，进程内不自愈：`full` / `fold-only` / `ledger-only` / `readonly` / `recovering`。
- 触发与行为写死：摘要 provider 不可用、预算耗尽、连续 3 次超时 → `fold-only`（只做第 0 级，永不返回空、永不放弃）；账本核对连续失败 ≥2 次 → `ledger-only`（停止自动折叠，保留账本与 `context_status`）；库不可用、契约版本高于代码、配置非法 → `readonly`（不折叠、不注入折叠块、历史逐字不动，人格照常）；存在未恢复事务 → `recovering`（阻塞新折叠，只读）。
- 与记忆的降级互不牵连：记忆库坏 → 记忆整体 no-op，上下文治理只降自己一档；反向同理；两者共用库句柄但不得互相回滚。
- 任一降级路径不得产生幽灵状态（注入了却标未注入、块标已折但历史已改写）。
- 降档与复档各写一行审计，当前档位可从 `context_status` 读出。

#### FR-51：每折一次都算得清是赚是亏（Epic 8；AD-39、AD-20）

**可测结果：**
- 每次折叠写一行审计（只落文件、按天切分、保留 30 天）：`{ts, session_id, op_id, tier, span, before_tokens, after_tokens, saved_tokens, summary_cost_tokens, prefix_repay_tokens, breakeven_turns, prefix_unchanged, degraded, host_cache_read, host_cache_write, host_cache_uncached}`。
- `breakeven_turns = ceil((summary_cost_tokens + prefix_repay_tokens) / max(1, saved_tokens))`，可复算。
- 超过上限（默认 20 轮）记 `low_yield`，该会话增量门槛临时上调 50%，会话结束即失效。
- 归因只用自己的计量：`prefix_repay_tokens` 由相邻两次请求的未命中 token 差值给出，不引入第二个数字来源。
- 宿主不提供缓存计量时记 `unknown` 并标 `economics_unavailable`，不降频、不阻断。

#### FR-52：折叠不许把身份段带下去（Epic 8；AD-38、AD-11）

**可测结果：**
- 身份段与状态尾巴在系统提示层，不是消息，**永远不进入折叠选区**。
- 折叠前后断言 `sha256(personaText)` 相等；库不可用、折叠失败、降级三种情形各覆盖一次。
- 人格影响折叠的唯一通道是保留优先级（检查点 KEEP 规则里的「用户显式偏好与边界」）；折叠算法不读取人格文本，避免「人格一改，历史重折」。
- 该断言失败即阻塞发布，不是告警。

#### FR-53：注入、折叠、召回共用一个注意力池（Epic 8；AD-42、AD-45、AD-7）

**可测结果：**
- 总池：常驻 + 折叠块 + 近期原文 + 召回 ≤ `govern.attentionPoolRatio`（默认 0.6）× 窗口，余量留给推理与输出。
- 召回条目相关性低于 `recall.relevanceFloor`（默认 0.5）不注入——把「取不满就少给」升级为硬阈值，宁可少给。
- 冲突时按密度删单条，不整档丢弃——密度按 §3 的定义用 `focus_ratio` 复算（AD-42 / AD-45），不靠人工感觉。
- 每轮记 `focus_ratio`，**分子用纯结构量，不用「相关性」这种要人来判的概念**：`focus_ratio = (身份段 + 状态尾巴 + 未折叠的近期原文) 的估算 token / 注入总估算 token`。分子里每一项都有确定的边界（身份段按字符数、状态尾巴按 token 上限、近期原文按 `recentTailRatio` 圈定），所以在测试里可直接复算，不会出现「因为相关所以相关」的循环。
- 折叠后 `focus_ratio` 不得低于折叠前，下降即回滚该次折叠（NFR-14）。
- 低于密度下限 `govern.focusFloor`（默认 0.6）触发**清理**（FR-54）而不是折叠——低密度可能是该给的没给。**注意这个 0.6 与总池的 0.6 是两个键**（`govern.focusFloor` 判「够不够聚焦」，`govern.attentionPoolRatio` 判「占了多少窗」），数值相同纯属巧合。
- 裁剪顺序 身份 > 状态 > 近期原文 > 折叠块 > 召回；但密度规则优先于档位规则。

#### FR-54：低 token、高干扰的残留要清掉（Epic 8；AD-44、AD-42）

**可测结果：**
- 每次折叠同时做任务线收敛：同一主题只留最新一版计划，旧版折成一行「已被 X 取代」；超过 N 轮（默认 8）未被引用的待办与 flag **从注入与检查点选区移除**并记 `noise_removed`；被否决的方案只留结论与理由一行；并行分支在主线恢复后折成一行坐标。
- **「移除」不是物理删除**：待办与 flag 是库内节点，按 FR-3 与 AD-5 无物理删除，一律打 `valid_to` 后不再进选区。审计行记「从哪一轮起不再进选区」，可随时按 FR-19 恢复。
- **「任务步」指的是可数的那一个东西，不是感觉上的「当前在做什么」**：定义为「最近一条用户消息所属的 `episode` 的最后一个 `scene`」，由 `in_episode` / `covers` 两条既有边唯一确定，不引入新字段、不调模型判定。
- 判据：折叠后「超过 N 轮未被引用 **且** 不属于当前任务步所属 `scene`」的条目数为 0（20 个折叠点抽样）。两个条件都是结构判定，抽样点可从折叠审计里按序取。
- 清理是确定性判定，不调模型；判不上的不删。
- 被清理的待办与 flag 在审计里留记录（可查移除了什么、从哪轮起），不做无声消失。

### 4.11 推演结算：What-If 是个赌注（AD-10 / AD-17 / AD-45）

**描述：** What-If 在 v1 默认关闭，但它已经占了一步（第 ⑤ 步）和一张表。真正缺的不是生成能力，而是**可结算性**：推演落成赌注，下次真实对话判命中。没有这条，命中率永远成不了校准曲线，自演进也没有尺。生成仍默认关闭，§6.2 不变。

**2026-11-25 裁定：验收对象是手工 fixture，不是真实产出。** 既然生成在 v1 全程关闭，v1 就不会产生任何 `whatif` 节点——给一条不产物的能力建结算设施，唯一诚实的验收方式就是**用人工构造的 whatif 节点验「打开后能判对错」**，而不是等真实推演攒够样本。本组三条的验收一律跑 `test/fixtures/whatif-*.jsonl` 里的手工样本；它们的交付价值是「闸门与字段就位」，不是「已经能校准」。真实校准曲线属 v1.5 之后的判断，届时若样本不足以支撑，应删掉本组而不是假装在测。

**功能需求：**

#### FR-55：推演是一个能被判定的赌注（Epic 6；AD-10、AD-17）

**可测结果：**
- 每个 whatif 节点必须带 `edit_op`（假设改动什么）、`predicted_delta`（预期变化）、`verified_at`（结算时点）、`outcome`（命中 / 未中 / 无法判定）四个字段；缺任一不得提交。
- 结算窗口是配置项（`dream.whatifSettleSessions` / `dream.whatifSettleDays`），语义为「自生成起 N 个会话或 M 天，先到者为准」；默认值标**待标定**，未标定前只记录不判定。**注意这与「字段写死」是两件事**：四个字段名与取值范围写死（FR-55 上一条），窗口长度是参数。
- 结算只用符号可判的判别式（与 FR-14 同一套操作符白名单），不得用模型自评。
- `outcome=无法判定` 是合法结果，必须记录并计入分母，不许静默丢弃。
- 本条只保证「打开后能被判对错」，不改变「生成默认关闭」。

#### FR-56：推演分四类，各自有判对错的法子（Epic 6；AD-10、AD-17）

**可测结果：**
- 四类固定：一致性（改动后是否与既有断言矛盾）、可答性（改动后某问题是否变得答得出）、剪枝后悔（被归档条目是否被重新需要）、真值敏感（结论是否随参数变化翻转）。
- 每类有写死的判定方式并落进 `test/fixtures/`；判不上的类别不得声称可结算。**v1 的验收输入全部是手工 fixture**，不依赖真实推演产出（见本节描述）。
- 先上符号可判的两类：**一致性**（复用 FR-41 的冲突检测）与**可答性**（固定问题集的可召回性变化）；另两类（剪枝后悔、真值敏感）必须等 FR-57 的覆盖率闸门通过。
- 类别与判定方式进 `addendum`，PRD 只要求「可判定且可复算」。

#### FR-57：不是所有东西都能符号判定，先量出比例（Epic 6；AD-10）

**描述：** FR-14 要求「推断可结算」，但没规定**多少比例**的推断真的能被符号判定。若可判定比例太低，「可结算」就只是话术。本条把它变成一个先测后用的闸门。

**可测结果：**
- 在 `eval/golden-l1.jsonl` 与真实 dogfood 数据上各跑一遍，统计「存在可执行判别式」的推断占比，产出比值并落报告。
- **本条不设阈值，只出报告**：把实测覆盖率连同分母口径一起报出来，**开不开由人看报告决定**。早先写的「阈值不得高于实测值」是自相矛盾的——那样闸门恒真、永远能开。已按 §8.2 的 D5 处置改掉。
- 在报告出来之前，FR-56 的后两类推演（剪枝后悔、真值敏感）与 §6.2 的策略自演进**默认不开**；报告出来后是否开启，是 Elliott 的显式决定，须记进决策账本。
- 覆盖率在每次判定方式变更后重测；不设为持续运行指标。
- 报告须写明分母口径（哪些推断被计入样本），换口径即视为新的一次测量。

#### FR-58：结论带不确定性，但不用模型自评（Epic 3；AD-17、AD-45）

**可测结果：**
- 召回结果附一个派生的不确定性折扣 `U ∈ [0,1]`，由四个结构事实合成：无来源、陈旧度、未决 flag 数、冲突数。
- 合成的输入**只能是结构事实**，不得读取任何模型置信度、概率或自评分。
- `U` 只作排序与展示的降权因子，**不参与真假判定**，也不得单独把一条断言过滤掉；过滤只看 FR-53 的相关性下限。
- 四个权重入配置并可读出；默认值标**待标定**（§8.2 的 T3），未标定前 `U` 只展示不排序。
- 同一库快照 + 同一时间基准重算，`U` 逐条相同。

### 4.12 视频素材：成本可预算、结论可自检（**整组 Deferred，不进 v1**）

**描述：** 看视频这条线在 DSH 里是真实用法，但研究结论是：**实时陪看与查询期证据装配都不该进**（用户已裁定）。剩下三件更朴素的事——花多少钱事先算得出、结论有没有偷懒能被指出来、帧取够了没有能被数出来。

**2026-11-25 裁定：整组移出 v1。** 理由不是价值不足，而是**它要检查的服务对象不存在**：这四条要检查「视频结论」、数「帧覆盖率」、按「张」计价图版，前提是系统里有一条「看视频」的能力面；而架构侧 CAP-8 明写「仅候选，未立项」（`ARCHITECTURE-SPINE.md:297`），addendum §9 对这四条也挂不上任何 CAP-8 的 AD。给一条不存在的路径建台账，等于先造仪表再造车。四条 FR **原文保留、编号不复用**，重启条件见 §6.2；它们不进任何 Epic 的验收，也不在 §6.1 的 v1 清单里。

**功能需求：**

#### FR-59：提供一套可被外部调用的观看自检器与码表（Deferred；原定 Epic 3；AD-20、AD-25）

**描述：** 本条早先写成「涉及视频内容的结论必须过七项自检」，但那个「结论」是**助手消息**，而助手消息在本项目里是不可变、不可写的（§5 非目标、FR-77 也只在生成前起作用）——于是这条 FR 没有任何合法的执行点。已改为：**只交付纯函数检查器与封闭码表**，由未来那条看视频的能力面在生成**之前**调用。这样它在 Deferred 状态下也是自洽的：一个函数存在不需要使用者存在。

**可测结果：**
- 交付一个纯函数检查器（入参为候选结论与证据清单，出参为命中的码数组），以及一张**封闭码表**：`FRONT_BIAS`（只看开头就下结论）、`SHEET_READ`（把封面/分镜图当正片）、`NO_EVIDENCE`（无时间戳证据）、`SPAN_GAP`（结论跨越未采样区间）、`AUDIO_AS_VISUAL`（把音频转写当画面）、`SINGLE_SOURCE`（单路信号定论）、`STALE_FRAME`（引用已判覆盖不足的区间）。
- 七码是**封闭集**；新增码必须先改本条。检查器对这些码各有至少一个正例与一个反例，全部在测试里直接调。
- 自检不依赖任何外部工具、不调模型，是纯判定；同一输入重跑输出逐项相同。
- **本条不规定谁来调、也不规定结果如何展示**：调用方不是本插件（助手消息不可写），本条只保证「有这么个东西、码表封闭、行为可测」。标注码不阻断任何回答——它的用途是让偷懒在生成前就可见。

#### FR-60：帧取够了没有，要报得出数（Deferred；原定 Epic 5；AD-20、AD-39）

**可测结果：**
- 报出帧覆盖率：以 60 秒为窗口，统计「至少取到一帧」的窗口占比。
- 覆盖率低于下限（默认 0.95）时触发一次加密重采；重采上限一次，仍不足则如实标注，不假装覆盖完整。
- 覆盖率与其口径随结论一起给出，可复算（同一视频同一参数重跑得同一比值）。
- 该指标只进成本台账与自检，不设为目标值考核。

#### FR-61：量测不花 token，且不许常驻（Deferred；原定 Epic 3；AD-20、NFR-13）

**可测结果：**
- 抽帧、切点、音频能量这类量测走**一次性短命子进程**，产出一份 `timeline.json`；不占用模型 token。
- 子进程必须显式等待退出并在超时（默认 120 秒）后强制回收；**不得**常驻、不得后台、不得监听端口。
- 临时文件写系统临时目录并在结束时删除；失败重试上限 1 次。**失败的处理与 NFR-13 对齐**：本条自身不产出结论（不猜、不用估算值顶替），但整条量测路径的失败只让「这次量测不成账」，**不阻断主流程**——调用方按「没有 timeline」继续，而不是报错退出。
- 该路径是 NFR-8 放宽后的唯一例外形态；出现第二个常驻进程即违反非目标。

#### FR-62：一次能塞几张图、一张图多少钱（Deferred；原定 Epic 5；AD-20、AD-45）

**可测结果：**
- 图版按「张」计价，一版固定价，与版内 4 帧或 8 帧无关；因此加密采样在预算内**不加价**（这是 FR-60 能重采的经济前提）。
- 同时进上下文的图版数量有硬上限（默认 3），超限必须显式取舍，不得静默丢弃。
- 计价与上限**不属于** FR-20 的四类日上限（抽取调用 / 向量调用 / 重排调用 / 固化 token）——图版是第五类，v1 不存在。本条若随 CAP-8 重启，须先在 FR-20 里增列第四类之外的新类别并给出降级路径，在此之前不得假定它已被现有预算覆盖。
- 成本在请求前可估算：给定视频长度与采样密度，报出预计图版数与 token 数。

### 4.13 人格保真：不会悄悄变坏（AD-11 / AD-12 / AD-13 / AD-21）

**描述：** §4.4 保证了「库坏了人设还在」，但没保证「人设还在且还是那个她」。人格是长期漂移的资产：没有探针就看不出她三个月里变冷、变软、变谄媚。这一组补的是**可观测性与写入闸门**——不改人格内容，只让人格的变化可被发现、非法改动被拒绝。

**功能需求：**

#### FR-63：人格漂移要有探针，不能只靠印象（Epic 9；AD-11、AD-13）

**可测结果：**
- `eval/persona-probe.jsonl` 收 20–30 条探针题，分三类：身份（她是谁、不是什么）、语气（句长、口语度、称呼）、边界（拒绝什么、不承诺什么）。
- 每个版本的人格文本跑一遍探针，产出可比较的趋势记录；题集与报告都带版本号，**换题集即视为新基线**。
- 探针只报告趋势，不设及格线（及格线要靠基线数据标定，标定前设线等于编数）。
- 探针跑在离线 eval，不进运行时路径、不花日常预算。

#### FR-64：人格是否被污染，四条判据（Epic 9；AD-11）

**可测结果：**
- 四条判据各自独立判定、独立报告：综合分跌幅超阈值、文本 diff 占比超阈值、新增边界违规 ≥1 条、关键词漂移率超阈值。四个阈值全部入配置并标**待标定**；起点值分别是 15 分、50%、1 条、未定（见 §8.2 的 T4）。按假设 A6，起点值来自研究报告的他方实验，**不得直接当验收线**。
- 任一判据命中即标「疑似污染」并**阻断该版本进入发布**，不是告警。**但这一条以阈值已标定为前提**：四个阈值仍待标定期间（§8.2 的 T4），命中只产出报告与 `persona_pollution_suspected` 记录，**不阻断发布**——未标定的数字不得触发不可逆动作（§8.2 统一规则第 ①条）。
- 四条判据不合成单一总分——合成就说不清是「变冷了」还是「变软了」。
- 与 FR-67 的分工：**污染四条是硬闸门（自动阻断发布）**，讨好探针是软报告（人可否决、探针不自动否决）。两者的差别来自误报代价——污染判据全部基于可比对的确定性测量，讨好探针依赖语义评审，自动阻断会误杀合法改版。
- 判定全部可复算：同一基线 + 同一新版本，四条判据结果逐条相同。

#### FR-65：人格只能按白名单改，非法迁移在写入前被拒（Epic 7；AD-12、AD-13）

**可测结果：**
- 可写字段是**封闭白名单**；白名单之外的字段时间接拒绝，返回既有拒绝码，不落库。
- 枚举型字段（如语气正式度）取值被夹取到合法区间，越界即拒绝而非截断。
- 关系阶段只允许逐级迁移：不跳级、不回退（回退走显式重置操作并记账）。
- 校验在工具执行前完成；非法写入不产生任何审计行之外的副作用。

#### FR-66：关系阶段是枚举，且留迁移历史（Epic 7；AD-12）

**可测结果：**
- 阶段是五级封闭枚举（`stranger` → `acquaintance` → `familiar` → `close` → `intimate`），由四维取值按常量表映射得出。
- **四维就是 §3 词汇表与 FR-16 用的那四个，不改名**：`temperature`（温度）、`trust`（信任）、`intimacy`（亲近）、`understanding`（理解），各 0–100，初值 50。映射常量表的键必须用这四个名字——早先草稿里写的 `familiarity / warmth / playfulness` 与正文不同名，只有 `trust` 重合，已废止。
- 每次迁移追加一条 `stageHistory` 记录：`{ts, from, to, cause}`；历史只增不改。
- 阶段与四维都进状态尾巴时受 30 token 预算约束，超预算按既有裁剪顺序处理。
- 同一四维取值重算得同一阶段（映射是纯函数）。

#### FR-67：不许讨好——讨好是要被检出的缺陷（Epic 9；AD-11）

**可测结果：**
- 讨好探针集独立于漂移探针，专门覆盖：无条件附和、过度道歉、无依据夸赞、为避免冲突而改口。
- 命中即计入报告并标注具体类型；**不与漂移分合成总分**。
- 该探针的结论可用于否决一次人格版本，判定权在人，不由探针自动否决。
- 不引入「重说直到不讨好」的多次采样——成本三倍且优化的是评分不是行为。

#### FR-68：入站的危险信号也要拦（Epic 7；AD-12、AD-13）

**可测结果：**
- 除既有出站越界拦截外，入站消息也过一道检查：确定性规则前置（命中即置顶固定指令），未命中才做一次轻量分类。
- 覆盖至少四类：自伤/危机、越权指令（要我冒充他人或绕过限制）、诱导披露他人隐私、要求放弃既定边界。
- 该检查可全局关闭；关闭后行为与原版本**逐字相同**（用于对照测试）。
- 拦截不改变用户原话、不静默删改消息，只追加固定指令。

#### FR-69：偏好要攒够了才配进状态尾巴（Epic 4；AD-7、AD-12）

**可测结果：**
- 一条偏好进入状态尾巴前须满足：来自**用户显式表达**，且累计出现次数达门槛 N（**待标定**，见 §8.2 的 T2），或由 `remember` 显式写入。
- **N 未标定前，本条只能「不晋升」**，不能按某个猜的数字晋升：未标定值不得触发占预算的动作（§8.2 统一规则）。`remember` 显式写入不受此限——那是用户的直接指令，不是推导。
- 未达门槛的偏好只留在库里可召回，**不占** 30 token 常驻预算。
- 「出现次数」＝该偏好断言上的 `evidence` 边按 FR-45 的 `source_independence` 去重后的条数（FR-34 的重复命中会追加边，因此重复表述数得到）；不另存计数器。多次表述合并计数，不因改写而重新计数。
- 门槛内置于配置；调低门槛不需要改代码，但需在 addendum 记一次变更理由。

#### FR-70：降级的时候她还得是她（Epic 7；AD-11、AD-13）

**可测结果：**
- 库不可用、向量路径失效、固化失败三种降级情形各有一条验收记录，记 `sha256(personaText)` 与当次注入文本。
- 三种情形下身份段的字节与正常态**完全相同**；状态尾巴允许缺席，但不得编造内容。
- 降级期间禁止任何「临时简化人设」的路径——简化即改写，改写即击穿缓存与身份稳定。
- 验收记录落 `eval/degradation-persona.md`，随版本更新而不是每次跑。

#### FR-71：人格体检只报告，不设线（Epic 9；AD-11）

**可测结果：**
- 可用 20 题自评量表算出一个五维人格画像，作为趋势记录。
- 结果**只报告不设线**：不设及格分、不据此自动否决版本、不进运行时判定。
- 画像与探针分开放、分开报，避免读者把「分数低」误读成「人格坏了」。
- 若将来要设线，必须先有 ≥3 个版本的基线数据，并改写本条。

### 4.14 上下文治理·有损半边（折叠阶梯第 1 级）：唯一有损的那一步（AD-29 / AD-32 / AD-33 / AD-34 / AD-41）

**描述：** §4.10 交付的是不花模型的第 0 级。本组交付唯一有损步骤——增量检查点摘要，以及围绕它的一整套守门规则。

**归属：Epic 8（2026-11-25 裁定，取代原先的「推 Epic 8+」；第二次裁定把它从 Epic 3 拆到独立的 Epic 8）。** 理由不在技术难度，在替换关系：v1 要接管宿主上下文，就得替换 `compaction-basic`（`CONTEXT-GOVERNANCE.md:400`），而第 0 级不处理散文——只交第 0 级就是把宿主的通用压缩换成更窄的一个。因此本组与 §4.10 是**同一次替代的两半**，必须同批交付、同批验收。第 1 级仍是唯一有损步骤，所以本组每条守门规则（双重缩小、前缀不可重折、触发时机、代码守门、提示词版本）都是**硬闸门**，不是建议。

**组内顺序（不作跨组要求）：** 先第 0 级与账本，再本组——不是因为排期，而是第 1 级的守门规则要读账本、要与第 0 级共用注意力池与降级状态机，缺了它们无处落地。二者在 Epic 8 内分两个 story（先第 0 级与账本，再第 1 级），但**验收必须同批**——G-E8-1 与 G-E8-2 同场。

**功能需求：**

#### FR-72：摘要必须双重更小，否则不算数（Epic 8；AD-32）

**可测结果：**
- 一次折叠必须同时满足 `after_tokens < before_tokens` **且** `after_canonical_bytes < before_canonical_bytes`；只满足其一即拒绝并记 `E_FOLD_NOT_SMALLER`。
- 双重判据的理由：token 少但字节多的摘要会让前缀缓存失效，反而更贵。
- 在 ≥3 个真实长会话上，100% 的折叠满足双重严格缩小——任一例不过即停用第 1 级、退回只做第 0 级。
- 判据可复算：同一折叠输入重算得同一结论。

#### FR-73：只折增量，不许重折前缀（Epic 8；AD-33）

**可测结果：**
- 折叠只作用于新增区间，已折过的前缀不再重新处理；每次折叠记 `prefix_unchanged` 布尔值。
- 前缀变更即视为失败：本次折叠回滚，历史逐字不变。
- 该约束的理由是缓存——重折前缀会让每一轮都重新付一次未命中成本。
- 测试断言：连续 N 次折叠后，第一块的字节与首次折叠完成时逐字节相同。

#### FR-74：什么时候折，规则写死且不告诉模型百分比（Epic 8；AD-34）

**可测结果：**
- 触发只有三个时机：增速门（填充比例达 0.45 且新增 ≥32K token）、阶段边界、模型显式申请。
- 面向上游的 nudge 文本**不得**包含填充百分比等具体数值（会诱导模型提前申请）；只描述可用动作。
- 溢出（上游拒绝或超窗）只解锁第 0 级与应急截断，**不解锁**第 1 级——撞墙时最该做的不是再花一次模型调用。
- 三个时机的判定是纯函数，可单测。

#### FR-75：选哪段折由模型提议，由代码守门（Epic 8；AD-29、AD-43）

**可测结果：**
- 模型只能**提议**候选区间；是否接受由代码按封闭判据判定，判据五条且不可扩展（不改代码就改不了判据）。
- 拒绝分两类：违反判据记 `fold_rejected`；模型自己撤回记 `fold_declined`，**不重试**。
- 选段依据只能是结构事实（相关性 × 陈旧度），不得读取模型自评的重要性分数。
- 任一次折叠的接受/拒绝都可从审计行复现。

#### FR-76：给模型的提示词要有版本，且标清它是给模型的（Epic 8；AD-41）

**可测结果：**
- 面向模型的文本带 `prompt_version`，与代码版本解耦、可单独回滚。
- 该文本在审计与日志中标记为「面向模型」，不得被误当作对用户的输出。
- 提示词变更须同步更新版本号；未更新版本号的变更在评审中视为缺陷。
- 提示词本身不写进人格身份段（AD-38 的身份免疫仍成立）。

### 4.15 自有产物的文案门禁（AD-11 / AD-20）

**描述：** §5 明确「不改写已生成的助手消息」，但本插件自己产出的卡片、通知、简报是**生成前**的文本，可以也应该管。这一节只管这一种文本，不越界。

**功能需求：**

#### FR-77：自己写的字，发出去之前先过检查（Epic 3；AD-20）

**可测结果：**
- 本插件自产的文本——**v1 只有两类：`/omw` 命令输出与 `reports/brief-<date>.md`**——在生成前过一道结构检查：必填字段齐全、长度上限不超、禁用语不出现。（v1 没有通知面：不主动搭话、无定时投递，见 §5 与 §6.2）
- 命中已批准的固定措辞表时，要求显式确认（`copy_confirm`）才提交；不确认即拒绝。
- 检查是纯函数，规则表以文件形式发布，可单独更新而无需改代码。
- **只作用于生成前**；已生成的助手消息不进这条路径（§5 非目标不变）。

### 4.16 对已交付契约的变更登记（2026-11-25 新增）

**为什么单列一节：** §4.8–§4.15 与 CAP-9 一共有四处**碰到了 Epic 1/2 已交付的契约**。约束 C1 说「Epic 1/2 不改」，若不作区分，读者会以为要么这些新 FR 违规、要么已交付的东西被悄悄改了。真相比两者都具体：**已交付的语义一个字不动，新需求一律挂在自己的 FR 下、带自己的检查**。本节就是把这三处（外加 CAP-9 那处判据改判）逐条钉清楚，供 `bmad-create-epics-and-stories` 直接引用。

**分层规则（三条）：**

1. **原有语义归还既有 epic**：已交付的 FR 原文不改。它们的验收标准仍是 `epics.md` 里那几条，不因本次修订而变。
2. **新增项自带检查**：新 FR 若扩展了已交付的行为，扩展部分（字段、追加项、追加档）由**新 FR 自己**验收，不并入旧 story 的 AC。
3. **扩展必须是可缺席的**：新字段缺省时旧契约逐字节不变；新档位未启用时旧裁剪顺序不变。这条是判据——做不到可缺席的扩展，属契约破坏，须改设计而不是改本节。

## 5. 非目标

- **不是**要记得更多——v1 不比对标产品记更多，只比它们更可查账。
- **不是**参数化学习：不改权重、不训练模型、不做梯度式记忆更新。
- **不是**多用户产品：无鉴权、无多租户、无团队共享、无跨设备同步。
- **不是**独立应用：它是 DSH 插件，不常驻任何进程、不监听端口、不起后台服务；唯一允许的进程外动作是一次性短命子进程（NFR-13）。
- **不是**主动助理：v1 不主动搭话、不改写已生成的助手消息。
- **不是**检索型问答产品：召回是为了注入与工具调用，不是做 RAG 问答界面。
- **不重写人格**：不做「整篇画像重写」。旧方案把 L3 当成「整篇重写、只用于注入」的对象，v1 拆成「字节稳定的文件身份」+「可治理的偏好节点」，因为整篇重写会每轮击穿前缀缓存，而且单条偏好失去来源（AD-11）。

### 6.2 范围外（v1 不做）

**怎么判断一条研究候选该落在哪**（2026-11-25 补入，供下一条研究线直接套用）：按序过四道，命中即停，不跳档。

1. **服务对象不存在 → Deferred**：要检查 / 要优化的那个东西在本系统里还没有生产者（例：视频组要自检「看视频得出的结论」，而看视频的能力面在 `ARCHITECTURE-SPINE.md:297` 仍是「仅候选，未立项」）。给它建台账等于先造仪表再造车。**重启条件是「服务对象正式立项」，不是「以后有时间」**。
2. **不改既有条目语义即可交付 → 并入既有 epic**：能挂到某个已存在的验收事件上、且缺省时旧契约逐字节不变（§4.16 第 3 条）。这是绝大多数增量的落点。
3. **必须改变已交付行为才能成立 → 新 epic 或改 PRD**：不满足「可缺席」就不是扩展而是替换，只能进新 epic 或重写既有 FR，不得悄悄改旧 story 的 AC（本次的实例：上下文治理替换宿主压缩器 → 新开 Epic 8）。
4. **验收前提是「有若干个已发布版本」→ 排到 v1 之后的 epic**：人格漂移、污染判据这类要拿多个版本做基线的（例：v1 交付时只有一个版本，没有基线可跑）。本次的实例是 Epic 9。

第 1 与第 4 都叫「不在 v1」，但性质不同：**第 1 是前提不成立（连「以后做」都不算），第 4 是要做但排在后面**。写范围外清单时必须标出是哪一种，否则读者会以为它们等价。

- **表达层（Voice）**：DSH 助手消息不可变，生成后无法改写；v1 只留预生成契约与生成后记账的位置。重启条件：**契约与记账可落地即可只启形状半边**（见骨架 Deferred）。
- **主动搭话**：宿主能定时投递，卡点在门控（概率、日上限、安静时段、硬退避），缺一条就变骚扰。
- **技能自演进**：宿主不提供候选重排所需信号，闸门与归因链没落地前不做。
- **What-If 生成**：v1 只建表与结算字段，生成默认关闭。
- **治理界面（GUI）**：先有数据契约再定视图，v1 用命令 + 导出，图形界面在这之后（AD-24 的治理投影是它的唯一只读出口）。
- **跨设备同步、多用户、鉴权**：一开就要服务端。
- **上下文治理第 1 级（有损摘要）**：~~整组推 Epic 8+~~ —— **2026-11-25 已改判为进 v1（现落 Epic 8）**，见 §4.10 的理由段与 §6.1 清单。留在本处的只有一句记录：它曾是范围外，因为「晚做代价更小」；改判的原因是晚做不成立——替换了 `compaction-basic` 却只交第 0 级，散文无人压。

## 7. 成功指标

四条全要，分阶段。阶段定义：**v1** = 本轮交付并开始 dogfood；**v1.5** = 用真实数据做首次验收；**v2** = 新增能力并开始设线。

**主指标**
- **SM-1 记忆准确率**：从断言层按时间分层抽 50 条（近 7 天 20 / 7–30 天 20 / 30 天以上 10），按 `eval/rubric.md` 判定「该不该记」，≥80%；假阳性与假阴性分开统计，报告 95% 置信区间（50 样本约 ±11%，故同时记录「离 80% 多远」而不只看过线与否）。抽样种子预注册，样本集写入 `eval/golden-l1.jsonl` 并冻结；评判人至少一名不知道抽取提示词的人（若确实只有 Elliott 一人，则改为「隔 **≥7 天** 重判 + 两次一致性 ≥90%」，并在报告里注明这不是独立盲判——2026-11-23 定案采纳此口径，不造第二评判人）。**及格线按假阳性加权**：错记比漏记更贵（承 FR-22 的 precision 优先），假阳性与假阴性分开统计，并同时给「离 80% 多远」的判断。v1 交付评测集与口径，v1.5 验收。验证 FR-22、FR-14。
- **SM-2 可治理性**：固定 20 条 fixture 记忆，用 `scripts/eval.ts` 逐条跑治理命令并计时，单条从执行到输出三个答案 ≤30 秒、字段齐全，20/20；结果写 `eval/governance-20.md`。人工只判「答案读得懂」，不判「查得到」。验证 FR-23、FR-11、FR-3。
- **SM-3 遗忘可回滚**：10 次操作（手动删除、固化归档、冲突替换、过期失效、整场景废弃各两类）后完整撤销，内容、版本链、标记状态、检索结果逐条复原，10/10 零残留。验证 FR-13、FR-12、FR-8。

**次指标**
- **SM-4 规模成本曲线**：记忆量 100 / 1000 / 10000 条（含合成语料生成器）下，测**召回 p95、库文件体积、embedding 与抽取日调用数、宿主缓存命中率**四项——常驻注入 token 由预算钉死、三档必然相同，**不作为指标**。v1 只建监控与基线；v2 设线时保留简报的「命中率下降 <10%」作为阈值。验证 FR-5、FR-7、FR-20。
- **SM-5 记忆卫生**：同一事实重复陈述 10 次，断言净增 1 条（验证 FR-34）；同一事实改述 3 次产生 `possible_duplicate` 标记，且**不静默合并**——3 条都在、可各自召回（验证 FR-34）；对同一条目连续提交 10 次内容未变的补丁，版本数不变（验证 FR-35）。v1.5 验收（需 Epic 4 交付后）。
- **SM-6 折叠经济性**：在 3 个真实长会话上验收。指标分两半，两半都在 v1：
  - **第 0 级半边**（验证 FR-51、FR-53）：`breakeven_turns` 可复算且与审计重算一致；`focus_ratio` 折叠后不低于折叠前（任一例下降即回滚该次折叠并计失败）。

**反指标（不要优化）**
