# PRD 质量审查（rubric walker）— DSH 哦鲸鲸（oh-my-whale）

**verdict: pass-with-fixes**

这是一份判断力很强的 PRD：主线（可查账、可撤销）一路贯彻，非目标与 Deferred 都写了理由与重启条件，反指标 SM-C1…C3 在同类文档里罕见。风险集中在「验收收口」：§7 的三条主指标没有落到可执行的验收程序与对应的 FR，§9 又把架构已经定死的问题重新当成未决；另有三处架构显式覆盖上游决定，PRD 未向读者披露。修法都是补写，不需要重排结构。

## 三、发现（按严重度排序）

### 1. [high] v1 的出口判据没有闭合

- **位置：** §7（prd.md:326-339）、§10 第 5 条（prd.md:363）。
- **问题：** §7 首句「四条全要，分阶段」，随后 SM-1「v1 建评测集与口径，v1.5 验收」（329）、SM-4「v1 只建监控与基线，v2 起设线」（334），再叠加 §10 末条「dogfood 期不设质控门控，只做基线采集」（363）——v1 实际只剩 SM-2 与 SM-3 两条一次性人工抽查，而这两条既没写验收时点（brief.md:89-90 写的是「v1 末」，PRD 未继承），也没写由谁、用什么产物判定。§0 声明本文定义「怎样算做到」（15、20），这一项没做到；「dogfood 不设门控」与「v1 末验收 SM-2/SM-3」在同一份文档里也没有被调和。分阶段本身有据（brief.md:93），缺的是收口。
- **改法：** 在 §7 末尾加一节「v1 出口判据」：SM-2 / SM-3 在 v1 末各跑一次，产物固定为 eval/governance-20.md 与 eval/reports/<date>.md（spine:377 已点名这三个文件），判定口径写进 eval/rubric.md；把 §10 第 5 条改写为「dogfood 期间不做持续门控，v1 末必须有一次终局验收」，否则删掉「怎样算做到」的承诺表述。

### 2. [high] §7 的指标与 §4 的 FR 不对齐：四个度量里有三个没有对应的功能需求

- **位置：** §7（329-334）、§6.1（311-312）、§4.3 FR-11（200-202）。
- **问题：**
  - SM-1 自述「验证 FR-1、FR-2」，但「该不该记」是抽取判定质量：FR-1 只保证写入可追到来源（103-106），FR-2 只保证写入原子性（113-115），全篇没有一条 FR 约束「什么值得记 / 不许编造」（UJ-1 边界情况 prd.md:53 提到「不会编造推断」，但没有升成 FR）。用 FR-1/FR-2 去验收 SM-1，测的是可追源性，不是准确率。
  - SM-2 要求「30 秒内答清」，且 §10 第 4 条自己承认「v1 必须交付只读查询命令」（362），但 FR-11 只写「一次查询即可返回版本链 + 账本 + 证据」（202）——没有命令名、没有输出字段、没有「一次调用还是三步」。架构侧同样没有 v1 的命令面：spine:300 的 scripts/ 只有 snapshot / verify / migrate；AD-24 的 DTO 要经 projection-bridge 给浏览器插件（spine:196，即 M5 的 GUI）；AD-25 的 explain(mem_key) 只是模型侧工具（spine:202）。也就是说 SM-2 的使能能力在 PRD 与架构里都没有落点。
  - SM-3 的五类操作里，「固化归档」「过期失效」「整场景废弃」没有任何 FR 定义行为与级联：FR-8 只约束第 ⑥ 步不调模型（171-173），没写归档做什么；「过期」只出现在词汇表（84）与 SM-3，没有任何 FR。而 SM-3 要求这五类操作撤销后「逐条复原、10/10 零残留」。
  - §6.1 承诺的三项也无 FR：「纯文本导出」（311）只被 FR-1 顺带提了「导出默认排除脱敏引文」（105），没有导出范围/格式/命令；「固定错误码」（312）没有任何 FR 列举或要求封闭（八个码只在 addendum:42 与 spine:247）；「标记」有定义（84）无生命周期（brief.md:61 的 dismiss / acknowledge / link 在 PRD 无对应）。
- **改法：** 补三条 FR 并回写 §7 / §10 的验证指向：FR-22 抽取判定（什么必须记、什么禁止记、缺证据怎么办，落成 SM-1 可判的口径）；FR-23 治理查询命令（命令名、入参、输出字段、单次调用覆盖版本链 + 账本 + 证据，供 SM-2 直接跑）；FR-24 纯文本导出（格式、范围、与脱敏开关的关系）。错误码不必新开 FR，作为 FR-18 的一条可测结果（「八个错误码封闭，改名即破坏兼容」）；标记生命周期同理并入 FR-12。若不愿扩范围，则把 §6.1 这四项移入 §6.2 Deferred，并把 SM-1 的验证对象改到 FR-14。

### 3. [high] 架构三处显式覆盖了上游决定，PRD 全部按「既定事实」写，读者看不到被牺牲的选项

- **位置：** §4.3（193、204-210）、§4.4 / FR-6（149）、§1 与 §5（78、301）。
- **问题：**
  - AD-9 的 Rule 明文写「此处显式覆盖简报『落库一律待人确认』的主张」，理由是「可回滚（AD-22），不是自动更省事」（spine:106）；简报原文是「其余一律只提议、挂起待人确认」（brief.md:46）。PRD §4.3 只写「符号可判的自动落库并可撤销，其余只提议」（193），既没说这是对简报立场的反转，也没给「为什么敢自动」的依据。
  - AD-7 明文写「此处有意取代设计稿的 ≤120 token 常驻档」（spine:81）；PRD 的 30 token（149）读起来像天然如此。
  - 骨架把简报 L3「整篇重写」拆成「文件身份 + 可治理偏好节点」，并自称「这是对简报的显式替代」（spine:361）；PRD §5 只留一句「不重写人格」（301）。
  - 决策就绪度的判据是「反对者能否看到自己的意见被处理」（校验清单 §1）。这三处恰好是反对者最会攻的点，也是下游最容易在 story 里走回头路的地方。
- **改法：** 各补 1 行取舍说明即可：§4.3 加「简报主张一律待人确认；v1 允许符号可判的自动裁决，唯一理由是整条操作可撤销（AD-22），判据见 FR-13」；§4.4 / FR-6 加「常驻预算从设计稿 120 token 收到 30 token，多出的偏好走按需召回」；§5 或 §6.2 注明 L3 的拆分替代。

### 4. [high] §9 的五条未决问题全是架构 Open Questions 的复述，其中第 3 条与 AD-6 已定的行为矛盾

- **位置：** §9（prd.md:349-355）对 spine:391-397。

### 5. [medium] 三条 FR 的「可测结果」不可测，其中含一个未定义的核心词

- **位置：** FR-14（prd.md:223）、FR-16（prd.md:244-245）、FR-17（prd.md:256）。
- **问题：** FR-16 写「关系四维有明确初值、单次变化步长与三档阈值」——只断言「有明确」却不给值，值在 AD-12（spine:124：初值 50、±3×intensity、<45 / 45–69 / ≥70），工程师照 PRD 无法判定做对没做对；同一条里的「越界检查」中「越界」全文未定义（词汇表 73-88 无此词）。FR-14 写「可判错的预言（可执行的判别式）」——「可执行」没有封闭集合，AD-17 给的是 op ∈ {eq, ne, gt, lt, gte, lte, exists, count_gte} 的判别联合加字段白名单（spine:154）。FR-17 写「改错文件必须能被文档与体检识别」——「被文档识别」无法测，「体检识别」也没说判定项。
