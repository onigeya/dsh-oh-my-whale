# Epic 2 Context: 记得进、查得到 — 显式记忆与可追源的最小闭环

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

本 epic 交付第一个业务能力：一句显式写入变成可按业务键或关键词召回的记忆，并带回来源（会话、seq 区间、≤200 字引文）；改写留旧版本，一次写入全成或全不成；注入只有一个出口、两段各有硬预算；召回只读有界，注入与召回各留一行审计。它是治理、自动抽取与召回提速的共同底座，判据是「写得进、查得回、追得到来源」；写事务与注入组装的 p95 是硬 AC，召回延迟只出基线（终判在召回提速 epic）。

## Stories

- Story 2.1: 用 remember 写下一条断言，立刻能按业务键读回
- Story 2.2: 每条记忆追得到来源，且引文不夹带隐私
- Story 2.3: 改写留旧版本，每次写留一条决策
- Story 2.4: 注入只有一个出口，两段各有预算
- Story 2.5: 召回只读、有界、只给未失效版本
- Story 2.6: 每次注入与召回都留一行审计

## Requirements & Constraints

**写入可追源**：每条断言配一条证据指针 `{session_id, seq_from, seq_to, quote, quote_truncated, deidentified}`，只有指针、没有整段消息。引文恰好 200 字符不截断、201 截断并标记；脱敏先于截断，膨胀后仍 ≤200。命中手机号 / 身份证 / 邮箱 / 银行卡即脱敏标记，原文不入库，默认导出不含。宿主无回读能力时仍返回该条并标「不可解引用」，不伪造原文。

**一次写入一次事务**：一张补丁表一次提交，任一 op 非法则节点、边、账本全为 0，另落一条被拒记录（原因 + 原始补丁），普通查询读不到；同键永不两条未失效；唯一约束冲突要翻成可读错误码，不许裸异常上抛。

**改写与账本**：旧版本置失效、让出活动位，默认查询只剩新版本，历史查询可取回旧值与有效期；每次成功写入恰一条决策（操作者、操作单元、受影响对象、目标键、前后值、理由、契约版本），账本只增不改不删。

**零物理删除**：业务代码不得出现删除类函数调用与删除类事务 op 字面量；CI 两道门（文本搜索 + AST）拦截，唯三豁免文件头写明用途。

**召回只读有界**：默认 5 条、硬上限 8 条，schema 无翻页字段，越界与非整数查库前即拒；只返回未失效版本，写调用为 0；候选池默认 12 是外层闸门，与最终条数不互替；同输入重跑集合一致，结果带耗时与封闭取值的降级原因。本 epic 只记不含重排的基线。

**注入单一出口**：身份段 ≤1200 字符、字节稳定（100 轮哈希不变，含库不可用轮次）；尾巴 ≤30 token、至多一条已确认偏好与一条待处理标记；场景常驻 0；超预算按 身份 > 状态 > 召回 裁剪；注入不查库，缺值整段省略。尾巴在关系状态交付前整段不出现并记 tokens 0，不写占位。

**审计可复算**：每次注入与每次召回各一行，字段固定（档位 / 字符 / 条目 / 截断 / 前缀 / 宿主缓存；命中 / 耗时 / 降级原因六值封闭）；只落文件、按天切分、留 30 天，轮转只经保留模块；报告命令给注入 / 召回 / 写事务的 p50/p95 与降级计数；行内不含节点 id。

## Technical Decisions

- **身份落在索引键**：业务身份是 `mem_key`（三段 `kind:subj:pred` 表单值谓词，四段带规范化宾语表多值，其他 kind 用 `kind:稳定名`）。唯一索引 `(mem_key, active_slot)`：活动写 1、失效写失效毫秒数，「同键至多一条未失效」由数据库在插入与更新 payload 上强制（实测抛唯一约束错），不靠部分唯一索引或 CAS；另建 `(mem_key, valid_from)` 供历史查询。规范化算法带版本号写进 payload，换算法走重键迁移。节点 id 不进导出、配置、日志与 flag 负载。
- **谓词是数据**：`pred` 节点承载登记表，10 个种子谓词随安装写入，但表是开放集合；基数决定键形态与冲突判定。表外谓词在同一事务内先建 `pred`（多值 / 候选 / 模型决定）再写断言并挂新谓词标记，不触发自动裁决；只有用户写入能提升为单值（同事务、走账本、可撤销）。名称规范化与非法名拒收在谓词模块，每日新建超限则断言降级为场景文本并记审计；`pred` 不进召回与注入。
- **写入路径**：core 依本轮活动版本算出每个节点的完整终值；唯一索引抛错即写被拒记录，不做 CAS 重试。全进程一个写队列串行提交，优先级 对话 > 快照 > 固化，模块不得自行加锁或绕过。
- **存储与查询纪律**：只经 store 具名函数访问库，不引入通用仓储抽象；写方法只在提交子目录，库包只允许 store 层 import，store 不 import 其他层、core 不 import seams。TQL 只在查询模板目录，预编译首参须字面量（AST）；未失效过滤器只在 `store/filters.ts` 的 `liveOnly()` 构造，`$exists` 未被类型声明覆盖，本地放宽并钉死版本 + 语义测试；集合条件由模板构造为过滤对象，预编译只收标量。
- **召回候选线程化**：同步原生检索无超时参数，必须放同进程线程并用原生请求上下文限时；端口与子进程仍全线禁止。
- **注入通道**：身份段走 `section({name:'harness:identity'})`、尾巴走 `context({name:'omw:persona-state'})`，调用只允许出现在提示词组装模块；`compose()` 同步段 p95 ≤20ms，审计异步。
- **工具面**：`remember(patch)`、`recall(query, topK?≤8)` 的签名与返回包封（ok / items / degraded / reason）在此固定，`forget` / `explain` 的名字与入参形态一并锁定；越界检查在 execute 前完成。
- **错误码与 schema**：运行时八个 `OMW_*` 沿用；工具侧封闭为 `E_BUDGET` / `E_TIMEOUT` / `E_DEGRADED` / `E_BOUNDARY` / `E_GATE_DOWN`；时间 ISO-8601 UTC 毫秒。首次建 schema 只建断言集合与两个索引，其余等真正需要的 story 再建。

## Cross-Story Dependencies

- **2.1 是其余五条的契约源**：键形态、唯一索引语义、补丁表与被拒路径在此钉死；它的语义测试是后续所有「同键至多一条未失效」推论的唯一依据。
- **2.2 与 2.1 共用同一写入事务**：证据与断言同批提交，脱敏与截断在写入路径完成，不能事后补。
- **2.3 的失效与账本是 2.1 改写 AC 的实现**，并定义治理撤销所需的受影响清单；账本字段此时定形，后续 epic 只加读命令。
- **2.4 只依赖上一 epic 的身份段文件**；尾巴整段省略的约束保留到关系状态交付后复测，不能靠占位提前判合格。
- **2.5 复用 2.1 的模板与未失效过滤器**，产出不含重排的延迟基线；后续 epic 在同一路径加重排与熔断，故边界要留清。
- **2.6 的审计行是跨 epic 落盘契约**：本 epic 保证字段齐全、降级原因封闭，重排与向量类原因由后续填充。
