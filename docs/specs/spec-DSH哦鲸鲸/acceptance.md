## 成功指标（七条全要，分阶段）

阶段定义：**v1** = 本轮交付并开始 dogfood；**v1.5** = 用真实数据做首次验收；**v2** = 新增能力并开始设线。

**主指标**
- **SM-1 记忆准确率**：从断言层按时间分层抽 50 条（近 7 天 20 / 7–30 天 20 / 30 天以上 10），按 `eval/rubric.md` 判定「该不该记」，≥80%；假阳性与假阴性分开统计，报告 95% 置信区间（50 样本约 ±11%，故同时记录「离 80% 多远」）。抽样种子预注册，样本集写入 `eval/golden-l1.jsonl` 并冻结；评判人至少一名不知道抽取提示词的人——若确实只有 Elliott 一人，改为「隔 ≥7 天重判 + 两次一致性 ≥90%」并在报告注明这不是独立盲判。**及格线按假阳性加权**：错记比漏记更贵。v1 只交付评测集与口径，v1.5 验收。验证 FR-22、FR-14。
- **SM-2 可治理性**：固定 20 条 fixture 记忆，用 `scripts/eval.ts` 逐条跑治理查询并计时，单条从执行到输出三个答案 ≤30 秒、字段齐全，20/20；结果写 `eval/governance-20.md`。人工只判「答案读得懂」，不判「查得到」。验证 FR-23、FR-11、FR-3。
  - **形态已定（2026-11-25 用户裁定「不要任何 CLI，只保留 command」）**：治理查询是聊天内斜杠命令 `/omw explain` 等，没有退出码。`scripts/eval.ts` 是开发期评测驱动、不是交付命令，它直接走治理投影 DTO 的读取路径，与命令面无关，不 fork 子进程。
- **SM-3 遗忘可回滚**：10 次操作（手动删除、固化归档、冲突替换、过期失效、整场景废弃各两类）后完整撤销，内容、版本链、标记状态、检索结果逐条复原，10/10 零残留。验证 FR-13、FR-12、FR-8。
- **SM-4 规模成本曲线**：记忆量 100 / 1000 / 10000 条（含合成语料生成器）下，测**召回 p95、库文件体积、embedding 与抽取日调用数、宿主缓存命中率**四项——常驻注入 token 由预算钉死、三档必然相同，**不作为指标**。v1 只建监控与基线；v2 设线时保留「命中率下降 <10%」作为阈值。验证 FR-5、FR-7、FR-20。
- **SM-5 记忆卫生**（2026-11-25 随扩展组新增）：同一事实重复陈述 10 次，断言净增 1 条（验证 FR-34）；同一事实改述 3 次产生 `possible_duplicate` 标记，且**不静默合并**——3 条都在、可各自召回（验证 FR-34）；对同一条目连续提交 10 次内容未变的补丁，版本数不变（验证 FR-35）。**两头核**：断言节点净增 1，而该断言的 `evidence` 边按实际来源数净增（FR-34 重复命中追加边），所以「重复 10 次」不是恒真的空话。v1.5 验收（需 Epic 4 交付后），v1 内的闸门见 G-E4-1。
- **SM-6 折叠经济性**（2026-11-25 随 CAP-7 进 v1）：在 3 个真实长会话上验收。指标分两半，两半都在 v1：
  - **第 0 级半边**（验证 FR-51、FR-53）：`breakeven_turns` 可复算且与审计重算一致；`focus_ratio` 折叠后不低于折叠前（任一例下降即回滚该次折叠并计失败）。
  - **第 1 级半边**（验证 FR-72）：100% 的摘要折叠同时满足 `after_tokens < before_tokens` 与 `after_canonical_bytes < before_canonical_bytes`；任一例不过即停用第 1 级、退回只做第 0 级。这一半原先是「Epic 8 交付后补测」，2026-11-25 随第 1 级一起改判进 v1——**不能只交第 0 级**（第 0 级产物是带坐标的桩，不是摘要，压不了散文），所以这一半不能推后。
- **SM-7 人格边界**（原编号 SM-5，2026-11-25 改号）：同一台机器上开三个会话——主对话（`omw-main`）、另开一个不带 preset 的普通会话、一个派发出来的 worker 会话——断言**只有主对话**的 system 消息含 `harness:identity` 全文；另两个会话的 system 消息对身份段的命中数为 **0**（不是「隐藏」、不是「关掉」，是从来没有）。同时四个记忆工具在三个会话里都可调（CAP-9 要求「只有记忆读写能力」）。判定方式：把三次 `compose()` 的产物落盘逐字节 diff，并静态断言 profile 位未注册任何 section。验证 FR-25、FR-26、I17、I18、I24、`entry-routing.md` §九。

**反指标（不要优化）**

- **SM-C1 召回条数**：不要为了「显得记得多」提高默认条数；条数上升通常意味着精度下降。反制 SM-1。
- **SM-C2 自动裁决占比**：不要追求自动驳回更多冲突；每多一次自动裁决就多一次无人确认的语义改写。反制 SM-2 的账面好看。
- **SM-C3 固化产出量**：不要用「提炼出多少条新洞察」当成绩；证伪率高的推断越多越糟。反制 SM-1。

## v1 的出口判据

**（一）全局终局验收（2026-11-23 定，不变）**

- **SM-2 与 SM-3 各跑一次，20/20 与 10/10 是及格线**；SM-1 在 v1 只要求「评测集与口径就绪」（50 条标注 + 判定规则落盘），不要求通过 80%。
- 产物固定四件：`eval/governance-20.md`（20 条三问的记录）、`eval/golden-l1.jsonl`（50 条标注样本）、`eval/rubric.md`（盲判口径）、`scripts/eval.ts`（运行脚本）。
- 判定由 Elliott 本人完成并签字式确认（单用户产品，无第二人复核）。
- dogfood 期间不做持续门控，只采基线；唯一例外是 SM-2 的 30 秒上限——它是可用性底线，低于底线即视为未通过。
- **折叠接管的替换必须自证成立，否则判「替换未成立」并整体回滚**（2026-11-25 新增终局项）。判据：SM-6 的第 1 级半边（100% 双重严格缩小）**与** G-E8-0 的替换三问同时在 v1 末仍成立。任一不成立，处置只有一条——**摘掉本插件的折叠接管、回滚到宿主压缩器、把 CAP-7 重开为一个新 epic**，不允许「降级成只做第 0 级」继续留在 v1：只交第 0 级等于拿掉宿主的散文压缩器而不给替代，那不是降级，是退化。这条与 SM-2 的 30 秒上限同属「唯一可用性底线」的例外，需 Elliott 签字。

**（二）扩展组的硬闸门：挂进各自 epic 已有的验收事件，不新开终局验收（2026-11-25 新增）**

§4.8–§4.15 的 36 条 v1 增量若全部堆到 v1 末一次性验收，结果是**交付到一半无法判断对错**，且违反「story 不得为自己的验收预埋后续 epic 实现」的反向约束。因此每一条增量都必须挂到**它所属 epic 已有的那次验收事件**上，判定在 epic 内完成；失败处理统一为「该 epic 不算完成，延后而非降级」——不允许把测不过的条目挪进 v1.5 当作已交付。

## 与指标相关的既有事实（不要重新论证）

- 记忆精度 ≥80% 靠人工抽样判定，不做自动评分器（AD-6 证据可追 + AD-17 可结算）。
- 治理 20/20 计时 + 人工确认答案读得懂（AD-5 + AD-9 + 版本链查询）。
- 遗忘回滚 10/10：软删除后默认查询与召回都不出现；撤销后逐条复原（AD-5 + AD-22）。
- 注入成本可控：审计行可复算，且 DSH 原有任务不退化（AD-7 + AD-20）。
- 折叠经济性靠 `focus_ratio` 与 `breakeven_turns` 两个可复算量判定，不靠「感觉变短了」（AD-39 + AD-42）。
- 待标定项（PRD §8.2 的 T1–T4 / D1–D6）在标定前**只能触发记录、打标、报告**，不得触发不可逆动作或成本支出；跳过判定必须留显式标记。任一项在其所属 epic 交付前未收口，该 epic 闸门判未通过。
- 对标项目的数字全部不可复现（Mem0 的 92.5 是厂商自测平台口径、MemoryOS 的 F1 +49.11% 无人复现），所以指标自建、口径写死。
