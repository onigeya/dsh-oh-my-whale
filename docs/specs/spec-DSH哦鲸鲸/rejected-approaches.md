# 被否掉的方案（不要重新引入）

> 出处：简报 addendum §2 与 PRD addendum §8——八条在架构侧均未被重新引入。列在这里是因为下游很容易「顺手优化」回其中某一条。每条给出否定理由与 v1 的替代做法。

| # | 被否方案 | 来源 | 否掉的理由 | v1 的做法 |
| --- | --- | --- | --- | --- |
| 1 | 参数式 dream（后台更新权重 / 衰退系数） | elo-memory 的设计意图 | 代码里根本没接上；要做对需要可验证的训练回路，本地插件够不着 | 生成式固化：八步 dream + 可结算推断（AD-10、AD-17） |
| 2 | 四包服务化 + 多存储后端 | TencentDB Agent Memory | 本地插件会被原生模块与运维面拖死 | 单进程单文件库直连，不设适配层（AD-1、AD-2） |
| 3 | 只做 ADD、不裁决 | Mem0 | 只增不减，且没有任何回滚路径 | 三级裁决 + 按操作单元撤销（AD-9、AD-22） |
| 4 | 召回即写入（记 access、升 stability） | CerebroCortex / elo-memory | 记忆被「被检索过的」而非「重要的」占据 | 召回只读，热度只作读时排序因子、不写回（AD-8） |
| 5 | 分层用 FSRS + ACT-R 双理论 | CerebroCortex | 需要 50 条访问时间戳与三套参数，且它自己就栽在召回即写入上；样本里没有一家证明复杂衰减带来可测收益 | 幂律 + 对数 rehearsal 只作排序因子，不改变存储位置 |
| 6 | 把裁决完全交给人 | nmem | 机器不提议，用户面对一堆 Flag 无从下手 | 自动档只覆盖符号可判的唯一情形，其余提案挂起（AD-9） |
| 7 | 把裁决完全交给 LLM | TencentDB | 无版本链回滚，改错了追不回来 | 模型只提议，裁决由规则或人执行，且整条操作可撤销（AD-22） |
| 8 | 梯度式连续记忆（CMS） | Nested Learning（arXiv:2512.24695） | 记忆更新依赖 ∇L，本地插件无训练回路；无官方代码 | 只借「多时间尺度 + 周期批量合并」的调度直觉 |

**重新引入的条件**：某条要回来，先改对应的 AD 并说明「现在为什么不再成立」，不要在 story 或代码里悄悄做。

## 2026-11-25 扩展组新增的「不要做回来」

下面九条不是从对标项目抄来的，是从六条研究线里挑出来时**明确否决过**的做法。它们最容易在 Epic 3 之后的实施里被「顺手优化」回来。

| # | 被否方案 | 出处 | 否掉的理由 | 替代做法 |
| --- | --- | --- | --- | --- |
| 9 | 给断言节点加 `support_count` / `access_count` 一类可变计数字段 | 直觉做法 | 写入侧去重会吃掉重复（FR-34 精确命中不新建节点），另存计数器在快照恢复后会与库不同步；且与 FR-36「热度只算不写回」自相矛盾 | 计数一律按 `evidence` 边在读时推导（`data-model.md` §2.1），重复命中追加一条指向本次 `source seq` 的边 |
| 10 | 用 FSRS + ACT-R 双理论做衰减投影 | CerebroCortex | 需要 50 条访问时间戳与三套参数；样本里没有一家证明复杂衰减带来可测收益 | 幂律 + 对数 rehearsal 只作排序因子（rejected #5 已否）。2026-11-25 的 FR-36「读时衰减投影」是同一件事的**具体化**，不是重新引入——它明确不写回、不改变存储位置 |
| 11 | 引入本体推理器 / 自研 Datalog 引擎做证明式召回 | 本体与推理线研究 | 实测 8000 条聚合加载 30845ms；把聚合、计数、排序、向量相似度推给推理层直接崩 | FR-40–45 的证明链是**封闭常量规则表**上的符号计算：`justification_id` 由前提业务键集合哈希算出，可复算、可拒收，不做通用推理 |
| 12 | 预测式世界模型（AriGraph 一类的状态转移预测） | 本体与世界模型研究 | 报告里那条线没有转移函数，只有三元组聚合；做出来是「看起来像预测」的统计 | 不做预测。不确定性做成可判定三态（CERTAIN / REFUTED / POSSIBLE）+ 缺口描述（FR-42、FR-43） |
| 13 | 只交付折叠阶梯第 0 级（0-LLM 观测折叠）就算完成 CAP-7 | 节省工作量的直觉 | 第 0 级只折工具输出，对散文零覆盖；而启用 CAP-7 必须替换宿主 `compaction-basic`，净效果是拿掉通用压缩器换一个覆盖更窄的 | 第 0 级与第 1 级**同批交付同批验收**（G-E8-1 与 G-E8-2 同场）。做不到就整组退回 Deferred，不允许「降级成只做第 0 级」留在 v1 |
| 14 | 第 1 级用「模型摘要」但不要要求账本与可逆指针 | 常见的对话压缩做法 | 摘要不可逆、无法核对丢了什么；一旦摘要把约束摘掉，后续每一轮都在错的上下文里工作 | 折叠必带 `{session_id, seq_from, seq_to}` + `req_ledger` 账本核对 + 可展开指针（AD-30、AD-31、FR-47、FR-48） |
| 15 | 为了量测视频时长/帧率而常驻一个后端进程（或起一个本地服务） | 视频融合研究的量测层 | 违反单进程纯插件形态（NFR-8）；插件一旦常驻就会带来安装、端口、崩溃域、卸载残留四条运维面 | 允许的只有**一次性短命子进程**（NFR-13）：带超时、退出即回收、不常驻不监听。且该类在 v1 休眠、无消费者 |
| 16 | 把研究报告里的数字直接当验收线（如「帧覆盖率 0.95」「污染跌幅 15 分」写死） | 研究结论 | 那些数字来自别的产品、别的语料、别的口径，不可复现 | 数字只能当**起点值**，一律入配置并标待标定（PRD §8.2 的 T1–T4 / D1–D6）；标定前只触发记录、打标、报告，不触发不可逆动作 |
| 17 | 给全程关闭的 What-If 生成器做「真实产出校准」验收 | 推演结算研究 | 生成关闭 ⇒ 不产 `whatif` 节点 ⇒ 没有样本可校准，写这种验收等于给自己造一个永远过不了的闸门 | 验收对象明写是**手工 fixture**（`test/fixtures/whatif-*.jsonl`），验「打开后能判对错」；真实校准属 v1.5 之后，样本不足就删掉该组 |

**与本文件上半部分的关系**：#9–#17 与 #1–#8 同级——一样是「要么改 AD 并说明为什么不再成立，要么别做」。区别只在来源：#1–#8 来自对标项目复盘，#9–#17 来自 2026-11-25 六条研究线的筛除过程。
