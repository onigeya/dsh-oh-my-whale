- (decision) slug 继承上游产物命名 DSH哦鲸鲸，输出 docs/specs/spec-DSH哦鲸鲸/；与 prd-、architecture- 同前缀，便于下游按同一 slug 找到三件产物。
- (decision) 能力编号沿用架构 Capability→Architecture Map 的 CAP-1…CAP-5（记忆/固化/治理/人格/运维），新增 CAP-6 迁移；另起 1…24 会与 AD 的 Binds 引用冲突。
- (capability) CAP-1 记忆——多轮之间保留可判真假的断言与偏好并按需取回；success = FR-1…7 与 FR-22 的可测结果（证据指针 ≤200 字符、单事务写入、召回默认 5 硬上限 8、注入 1200 字符 + 30 token）。
- (capability) CAP-2 固化——离线八步把记忆整理得更少更准，且每个产出可追；success = ①②⑥⑦ 无 LLM 依赖、③④⑤⑧ 提炼+核验两段记录、断点续跑、日预算停在段边界。
- (capability) CAP-3 治理——答清三问并按操作单元撤销；success = 一次查询返回版本链+账本+证据、自动档仅一种情形、20 条 fixture 撤销后逐条等于操作前、四条只读命令退出码固定、导出纯文本+JSONL。
- (capability) CAP-4 人格——库坏了人设还在；success = 库不可用时身份段照常注入且 100 轮 sha256 不变、状态缺失整段省略、四维越界在 execute 之前拒绝。
- (capability) CAP-5 运维——一次重启确认它真在工作，坏时知道是哪一档；success = 启用三步+体检五项、两档降级、八个封闭错误码、快照 7 份、四类日上限命中即降级。
- (capability) CAP-6 迁移——从 mnemon 一次性迁入且失败不改变任何东西；success = 幂等、迁移报告四项计数、失败回滚到迁移前快照、注入快照里 mnemon 段落为 0。
- (constraint) 单进程纯插件，禁止子进程/端口/跨进程锁文件，后台任务只用 ctx.timer；多一个部署单元就多一套生命周期，而宿主已有 timer。
- (constraint) 单文件库直连不设适配层，业务只经 store/ 具名函数访问；适配层会把图扩散、payloadFilter、快照校验削平成 CRUD。
- (constraint) 身份是 mem_key 业务键、节点 id 禁进导出/日志/配置；同一 mem_key 至多一条未失效由 (mem_key, active_slot) 唯一索引在数据库层强制。
- (constraint) 唯一写入口 + 全进程单写队列，一次业务写入一张补丁表一次 commitTransaction；三个入口（remember / 用户命令 / 去抖抽取）共用这一段。
- (constraint) 零物理删除：delete/unlink 的方法形态与事务 op 字面量都进 AST 门禁，仅三个具名豁免（快照目录/审计轮转/卸载前导出）。
- (constraint) 证据是指针不是副本，负载只允许 {session_id, seq_from, seq_to, quote≤200, quote_truncated, deidentified}；不可解引用时标 evidence-unresolvable，绝不伪造原文。
- (constraint) 注入单出口：身份段 ≤1200 字符走 section()、状态尾巴 ≤30 token 走 context()，两处只在 prompt-composer；场景常驻 0；注入路径不查库。
- (constraint) 召回只读有界：5/8 条、三段 250+600+20ms、硬上限 1000ms 到点不返空；② 失败只降不空，只产分数，剪枝由阈值+top-k 确定性执行。
- (constraint) 三级裁决：自动档仅 single 谓词同键区间重叠值不同；其余提案挂起，人工解除是唯一解除路径。
- (constraint) 撤销以 op_id 为单元，affected 闭包只含状态节点与边，账本类对象永不撤销且在判据比较中排除，否则追加 revert 会让判据自我否决。
- (constraint) 推断必须带 falsifier 与 settle_state，缺判别式只能降级为 scene 文本；证伪 = 置失效 + flag(refuted)，不删除。
- (constraint) 固化八步确定性先行：①②⑥⑦ 依赖对象不含 LLM（测试断言），③④⑤⑧ 核验不过不提交，每步独立 dream_log 可断点续跑。
- (constraint) 降级只有两档（整体 no-op / 只关向量路径），八个错误码封闭，恢复需重载；半开状态会让用户以为记忆在生效。
- (constraint) 外部 provider 三出口（embedding / llm / systemone）各自熔断与预算，密钥只从环境变量读，返回维度必须等于 db.dim。
- (constraint) 配置与预算单一出处（seams/config.ts 的 zod schema），环境变量只承载密钥；新增键必须改 AD-26 并补 schema 测试。
- (constraint) 工具面是公开契约（recall/remember/forget/explain + ok/items/degraded/reason + 五个 E_*），改名即破坏兼容。
- (constraint) 迁移替代而非共存：uuid5 只作 migration_id 不作身份，源文件不删不改，回滚开关需重启。
- (constraint) 平台定为 Windows 本地单用户、Node 24.21 / TS 7.0.2 / triviumdb 0.9.3；M0 八道闸门全过才进 M1（G0-1/2/3 已实测通过）。
- (decision) 非目标 9 条（记得更多/参数化学习/多用户与同步/独立应用与 RAG 界面/主动搭话与改写消息/技能自演进/What-If 生成/治理 GUI/整篇重写人格），每条写理由或重启条件，防止下游把 Deferred 当 backlog。
- (decision) 成功信号取 v1 终局验收（SM-2 20/20、SM-3 10/10、SM-1 评测集与口径就绪 + 本人签字），不取「跑起来了」；SM-1 过线推到 v1.5，因为 v1 末没有 50 条真实样本。
