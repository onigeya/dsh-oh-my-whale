# 需求目录：FR-1…FR-24 与 NFR-1…NFR-10

> 由 PRD §4 蒸馏：每条只留「要什么 + 可测结果」。FR 标题后的 AD 号是约束边界（story 的验收不得越过这些不变量），机制与「为什么」在两类 companion 里：`ARCHITECTURE-SPINE.md`（AD 全文）与 `data-model.md`（数据结构）。CAP 分组见 `SPEC.md`。

## CAP-1 记忆（AD-2 / AD-3 / AD-4 / AD-5 / AD-6 / AD-21）

三个入口（agent 显式调用、用户显式命令、回合结束后的去抖抽取）汇到同一条写路径：一张补丁表、一次事务、一份决策账本；被拒的写入不静默丢弃，落 `rejected` 并挂标记。

**读取边界（v1 定案）**：抽取只读「显式写入 + 当前会话自上次游标以来的新增 seq」，不回溯、不外扩、不回填宿主历史日志；固化 ② 的重放抽样只重放库内已有证据指针（经宿主可选查询能力回读短引文与 seq 区间），lookback 上限 30 天；任何路径都不把宿主消息全文写进库。

### FR-1 一条记忆可以被写进来并追到来源（AD-2、AD-4、AD-6、AD-21、AD-25）

- 写入后能按业务键查回该条，并取回 `{session_id, seq 区间, 短引文}`；短引文 ≤200 字符，超长时标截断。
- 命中手机号 / 身份证 / 邮箱 / 银行卡正则时，引文自动脱敏并标 `deidentified`。
- 导出默认排除已脱敏引文，需显式开关才包含。
- 来源不可解析时（宿主查询能力缺席），该条仍返回但标 `evidence-unresolvable`，绝不伪造原文。

### FR-2 写入要么全成，要么全不成（AD-4、AD-5）

- 补丁表里任一 op 失败，整次写入不留下任何节点、边或账本条目。
- 被拒的写入留下一条 `rejected` 记录（含原因与原始补丁），且不可被普通查询当成记忆读到。
- 同一业务键不会同时存在两条未失效版本。
- 谓词不在登记表时，同一事务内先建 `pred` 节点（默认 `multi` / `candidate`）再写断言，并挂 `flag_type=predicate_new`；谓词名非法则整张补丁表拒收（AD-27）。

### FR-3 改写会留下旧版本，而不是覆盖（AD-3、AD-5、AD-15、AD-21）

- 改写后旧版本默认查询不再返回，历史查询能取回。
- 每次改写写一条决策账本条目，含操作者、操作单元、受影响对象清单。
- 业务数据（节点、边、账本）没有物理删除路径；仅三个具名豁免：快照目录清理、审计与日志轮转、卸载前导出后删除。
- 其余 `delete` / `unlink` 由静态门禁（grep + AST）阻断：故意在业务代码里写一次 `delete(`，CI 必须失败。

### FR-4 召回只读、有界（AD-8、AD-25）

- 召回路径不产生任何写调用（含更新 payload 与刷盘）。
- 默认返回 5 条，硬上限 8 条；不提供翻页 / offset 循环；默认只返回未失效版本。
- 召回结果可解释：命中哪些、耗时多少、是否降级、降级原因（取值封闭）。
- 模型只给分数，不给「删哪条」的许可：排序与剪枝按分数 + 阈值 + top-k 由代码决定，同一批分数重跑得到同一批结果。
- 候选池上限读 `recall.candidatePool`（默认 12，AD-26）；它是最外层闸门，`topK` 仍是默认 5 / 硬上限 8。

### FR-5 召回分三段，每段有退路（AD-8、AD-19、AD-23）

- ① 候选段超时（默认 250ms）才算「没有细节」；② 重排段（默认 600ms，经 System One 打分：`POST /systemone` 的 score 任务 + `SemIf`）超时只跳过排序、按候选顺序照常注入并标 `rerank_unavailable`；③ 注入段（默认 20ms）取不满就少给，不凑数。
- 三段合计硬上限 1000ms，到点交候选，**不返回空**。
- 同一回合至多重排一次；命中缓存不重复付费。
- 连续 3 次重排超时熔断 10 分钟，期间只走 ①③。
- 重排默认开启、可关闭；关闭后不得报警或计入降级。

### FR-6 注入只有一个出口，且带预算表（AD-7、AD-11、AD-20）

- 身份段 ≤1200 字符，字节稳定：文本不变则不重写。
- 状态尾巴 ≤30 token：关系四维与档位、至多一条已确认偏好、至多一条待处理标记。
- 场景永不常驻。
- 超预算按 身份 > 状态 > 召回 顺序裁剪，并记一行审计。
- 注入路径不查库：缺值整段省略，不填默认值。

### FR-7 每次注入与召回都可核（AD-8、AD-20、AD-26）

- 每次注入与每次召回各留一行审计：档位、条目、是否截断、耗时、是否降级、降级原因。
- 审计可按天回溯 30 天；不落库、不参与召回。
- 注入组装 p95 ≤30ms（其中 `compose()` 同步段 ≤20ms）；召回 p95 ≤900ms；写事务 p95 ≤10ms。
- 看数有命令：按时间窗口输出 p50/p95 与降级计数。

### FR-22 什么值得记、什么禁止记（AD-4、AD-6、AD-17、AD-25）

承重缺口：SM-1 测的「该不该记」必须由一条功能需求约束，否则准确率无从谈起。

- 抽取的输入是会话片段 + 已有记忆的稳定身份，输出只有一张补丁表；禁止逐条流式写库。
- 用户显式说出的偏好 / 决定 / 纠正必须落断言；纯寒暄、纯执行性对话必须不落（两类各有 ≥20 条标注样本可判）。
- 证据缺失（拿不到会话原文）时该条只能标 `evidence-unresolvable`，不得凭印象写出引文。
- 模型给出的「推断」若无合法判别式，只能落成场景描述文本，不得进断言层。
- 单次抽取失败不重试超过一次；失败留 `rejected` 与错误码，不写半截。
- 越界读取 = 0：抽取与固化只碰「本轮新增 seq」与「库内已有证据指针」；每次回读都记 `session_id` 与 seq 范围，可审计复算。
- 回读 lookback ≤30 天，超出范围的证据标 `evidence-expired`，不回读原文。
- v1 的抽取阈值**偏 precision**：不确定即不落；漏记由 `remember` 工具与用户显式命令兜底，不计为缺陷。
- 评测时假阳性与假阴性分开统计，**及格线按假阳性加权**——漏记可补，错记只能靠治理清账。

## CAP-2 固化（AD-10 / AD-14 / AD-15 / AD-25）

夜间窗口（本地 02:00–05:00）优先；宿主不在线则下次启动补跑当天一次；长会话跨过安静时段时由空闲触发接管（最后一次交互后 30 分钟无新事件即跑一次，当天已固化则跳过）。八步固定顺序：确定性结算 → 重放抽样 → 模式提取 → 场景抽象 → What-If（默认关闭）→ 剪枝归档 → 跨主题重组 → 策略提炼。

### FR-8 八步顺序固定，且确定性步骤不碰模型（AD-10、AD-14、AD-17、AD-23）

- ①②⑥⑦ 的依赖对象里不含模型客户端——由测试断言，不靠代码评审。
- ③④⑤⑧ 的产物带提示词版本与周期标识。
- ③④⑤⑧ 每个模型步骤都留下「提炼产物 + 核验结论」两段记录；核验不通过的步骤不得提交，后续步骤按缺步处理，不得带病继续。
- 核验模型对一条刻意删掉证据指针的产物必须判「不通过」——这条作为 G0-8 的验收样例。
- ⑤ 默认关闭；开启时有硬约束（深度 ≤2、默认一条、单锚点一分叉），且产物永不进断言层。

### FR-9 每一步独立提交，能从断点续跑（AD-10、AD-21）

- 进程在第 ④ 步被杀，重启从 ④ 续跑，不重跑 ①②③。
- 每条固化日志记录阶段、种子、diff 摘要、消耗的 token。
- 确定性步骤（①②⑥⑦ 与 ② 的抽样）可复现（种子由日期与阶段决定）；③④⑤⑧ 只要求固化日志记录提示词版本、种子、输入锚点集与输出摘要，**不承诺逐字节一致**。
- 一天最多一个周期标记。

### FR-10 预算三层取最小，超了停在段边界（AD-10、AD-26）

- 阶段预算、日 token 上限、provider 配额三者取最小。
- 一次固化至少发生 6 次模型调用（③④⑧ 各一次提炼 + 一次核验），日调用上限必须覆盖这个下限并留重试余量。
- 命中即停在阶段边界并记一条截断记录，不半途写入。
- `--dry-run` 只跑 ①②，出 diff 不写库。
- 错过**不补历史多天，只补当天一次**：连续 3 天在 02:00–05:00 离线、第 4 天 09:00 启动，恰好跑 1 个 cycle，固化日志有记录。
- 空闲触发：最后一次交互后 30 分钟无新事件，且当天 `dream_cycle:<date>` 不存在、无进行中轮次、无排队写入时开始一次固化，日志标 `idle_triggered`；同一天连续空闲 10 次仍只产生 1 个 cycle。
- 触发途中用户发起新交互，只在**段边界**让路（当前步提交完再停，可从断点续跑），不打断写事务、不占下一轮首 token 路径。
- 审计里能看到最近一次固化的日期与结果——「从未运行」是可见状态，不是沉默。

## CAP-3 治理（AD-9 / AD-21 / AD-22 / AD-24）

治理面回答三个问题：谁改的、依据什么、为什么。冲突分三级：自动档（符号可判，唯一会改数据的档）、提案挂起档、人工解除档。撤销以操作单元为单位。

### FR-11 每条记忆都答得出「谁改的、依据什么、为什么」（AD-21、AD-24、AD-25）

- 三个问题分别由决策账本（操作者与时间）、证据指针（来源与 seq 区间）、决策账本（类型、理由、提示词版本、引用先例）回答。
- 账本只增不改不删。
- 一次查询即可返回版本链 + 账本 + 证据，不需要多步翻找（命令见 FR-23）。

### FR-12 冲突分三级，只有自动档改数据且必须可撤销（AD-9、AD-22）

- 自动档成立条件严格：同一谓词的单个取值、同主体同谓词、有效区间重叠、归一化值不同。
- 自动档结果 = 旧版本置失效 + 新断言 + 一条已解决的标记 + 一条矛盾边，全在同一事务内。
- 其余冲突只能「提案 + 挂起」，不得改动既有断言；人工解除是唯一的解除路径。
- 标记是两态 `status ∈ {open, resolved}` + `flag_type` + `resolved_by(auto|human)`；PRD 的「创建 / 挂起」都是 `open`，「已证伪」是 `flag_type=refuted`，「已撤销」由 revert 账本表达（口径已裁决，见 `data-model.md` §7）。
- 自动档的每次裁决都能按操作单元整体撤销。

### FR-13 撤销是一个操作单元（AD-5、AD-22、AD-25）

- 每个操作带操作单元标识与受影响对象清单；清单只含状态类对象与边，不含账本类对象。
- 撤销在单事务内反向执行，并追加一条「撤销」账本条目。
- 复合操作要么整体撤销、要么整体不动。
- 判据（比较域写死）：固定 20 条 fixture 查询、关闭重排（或固定缓存键），只比较 `{mem_key, active_version, flag_status, edge_label}` 的集合；不比顺序、耗时与审计字段；账本类对象不参与比较。

### FR-14 推断必须可结算（AD-6、AD-17）

- 推断类断言必须带可执行的判别式（操作符限于 `eq/ne/gt/lt/gte/lte/exists/count_gte`，字段限于白名单）与结算状态（未定 / 已确认 / 已证伪）。
- 缺判别式或字段不在白名单 → 拒收，该推断只能落成场景描述文本。
- 证伪不删除，改为置失效 + 一条已证伪标记。

### FR-23 治理查询命令是 v1 的交付物（AD-21、AD-24）

SM-2（30 秒答清三问）需要一个真实入口；治理界面在 v1 之后，命令必须在 v1 交付。

- 四条只读命令：`omw explain <mem_key|关键词>`（版本链 + 账本 + 证据，一次调用）、`omw version-chain <mem_key>`、`omw flag-queue [--status open]`、`omw export [--include-quotes]`；字段名与 AD-24 的治理投影 DTO 对齐。
- 退出码固定：0 成功、2 未找到、其他非零为错误；不使用交互式分页。
- 输出为结构化 JSON 与人类可读两种；字段名与导出格式一致。
- 任取一条记忆，从执行命令到看到三个答案 ≤30 秒（含人工阅读）。
- 命令只读：不产生任何写入、不更新热度。

### FR-24 全量数据可导出（纯文本 + JSONL）（AD-3、AD-5）

- 一条命令导出全部断言（含版本链关系）、偏好、场景摘要与账本；默认不含已脱敏引文与节点 id。
- 导出格式为纯文本 + JSONL，可直接归档；不需要本产品即可读懂。
- 导出是卸载的前置条件：未导出不允许卸载（AD-5 的第三个豁免）。

## CAP-4 人格（AD-11 / AD-12 / AD-13）

身份是随插件发布的文件，字节稳定；状态是可缺席的一小段。**常驻预算的收窄**：v1 收到 30 token、场景常驻为 0，多出来的偏好走按需召回——每轮多占的 token 永久留在历史里且击穿前缀缓存。

### FR-15 身份段不依赖库（AD-11、AD-13）

- 库打不开时，身份段照常注入。
- 身份段文本哈希不变则不重写，保持前缀缓存可用。
- 身份段不承载任何逐轮变化的内容。
- 落地内容（方案设计 §7）：`assets/persona.md` 四段顺序固定——身份（鲸鲸是谁、与用户的关系形态）、说话方式（句长 / 语气 / 用词 / 何时简短）、边界（明确不做什么）、她不是谁（防滑向通用助手腔）；≤1200 字符。

### FR-16 状态可缺席，但不许编造（AD-7、AD-12、AD-20）

- 状态字段缺失或库不可用时整段省略，不填默认值。
- 四维初值 50、单次正向步长 ≤3×强度（负向 ≤2×强度）、三档阈值 45 / 70 可从配置读出并解释档位归属。
- 越界（四维超出 0–100 或步长超限）在工具执行前返回拒绝，不靠提示词提醒。
- 落地内容（方案设计 §7）：四维事件分类表——用户主动分享私事 → intimacy / trust 正向；用户纠正她并接受 → understanding 正向；用户冷淡或拒绝 → temperature 负向；她记错并被指出 → understanding 负向；长时间未互动 → temperature 缓慢回落。三档（<45 / 45–69 / ≥70）只改行为约束、不写台词。边界硬拦截四类在 `execute` 之前返回结构化拒绝：自伤与危机、越界亲密、法律医疗的确定性建议、索取他人隐私。

## CAP-5 运维（AD-13 / AD-18 / AD-24 / AD-25 / AD-26）

### FR-17 启用是可验证的三步，不是一步（AD-1、AD-15、AD-26）

- 依赖声明、宿主补丁配置、重启验证三步缺一不可；改错文件（改生成物 `cordis.yml` 而非补丁文件 `cordis.patch.yml`）必须能被文档与体检识别。
- 启用后有体检命令，检查五项：库能开、快照校验过、维度匹配、凭据可用、注入段已注册。
- 对五种错误配置（无库、快照损坏、维度不符、凭据失效、注入段未注册），体检各返回非零退出码与对应错误码。

### FR-18 降级只有两档（AD-13、AD-18、AD-19、AD-23）

- 库打不开、快照校验失败、配置维度与库不符、契约版本不符 → 整体 no-op：不注入记忆、不注册写工具、不排固化、不写任何节点，只记一行原因。
- 仅向量路径故障（凭据 401/402、embedding 返回维度不符）→ 只关向量路径，文本与图召回照常。
- 不存在中间态：不写一半、不注入半段；注入与工具各自独立降级，不互相回滚（AD-18）。
- 错误码封闭为八个：`OMW_DB_OPEN` / `OMW_SNAPSHOT_VERIFY` / `OMW_DIM_MISMATCH` / `OMW_EMBED_AUTH` / `OMW_EMBED_QUOTA` / `OMW_EMBED_TIMEOUT` / `OMW_EXTRACT_FAIL` / `OMW_DREAM_BUDGET`；新增或改名都算破坏兼容。
- 恢复需要重载插件，不在进程内自愈重试。

### FR-19 备份与恢复可预期（AD-14）

- 每次启动检查「今天有没有已校验快照」，缺则补做；重复运行最多多一份，不视为错误。
- 迁移前强制快照；保留最近 7 份。
- 恢复必须先停库再恢复（Windows 句柄锁）。
- 迁移先 dry-run。

### FR-20 成本有上限且可看（AD-23、AD-26）

- 四类日上限各自可配：抽取调用、向量调用、重排调用、固化 token。
- 命中后各自降级而非报错：抽取只记不抽、向量停止补写、重排降级为候选顺序、固化停在段边界。
- 审计报告可按时间窗口输出 p50/p95 与降级计数。

## CAP-6 迁移（AD-2 / AD-3 / AD-5 / AD-16）

替代而非共存：一次性把旧文件转成断言与偏好，不删源文件，留回滚开关。

### FR-21 迁移幂等且可回退（AD-2、AD-3、AD-5、AD-16）

- 重复运行不产生重复节点（以迁移标识判定「这行迁过」）。
- 迁移用业务身份，不用行哈希冒充身份。
- 迁移完成后，一次会话的注入快照里 mnemon 段落出现次数 = 0，身份段唯一；两套插件同时安装时仍只有一条注入路径。
- 迁移前必须先禁用或卸载 dsh-mnemon（否则报错退出，不半途迁）。
- 迁移的产物是一份**迁移报告**：迁入 N 条 / 跳过 M 条（逐条原因）/ 去重合并 K 条 / 失败 0 条，落 `migrations/<ts>-report.md`；用户第一眼看到的是它，而不是一个空荡荡的会话。
- 迁移前先落一份**迁移前快照**（`snapshots/pre-migration-<ts>`）；迁移失败自动回滚到该快照——失败不改变任何东西：不留半迁节点、不删源文件、不改配置。
- 回滚与重跑是同一件事：回滚后再跑一次，结果与首次成功迁移逐条等价；报告追加而非覆盖。
- 回滚开关打开并重启后只恢复本插件的 legacy 注入行为，不自动重新启用 mnemon；迁移节点按「置失效 + 导出后卸载清理」处理（见 FR-3 的豁免）。

## 横切非功能要求（NFR-1…NFR-10）

这些是上文的约束面，不是额外功能。

- **NFR-1** 注入组装 p95 ≤30ms（`compose()` 同步段 ≤20ms）。
- **NFR-2** 召回 p95 ≤900ms（含重排）；`rerank_unavailable` 比例 <5%；候选真空比例 <1%。
- **NFR-3** 写事务 p95 ≤10ms。
- **NFR-4** 任一降级路径不得产生幽灵状态（注入了却不写、工具半可用）。
- **NFR-5** 不复制宿主消息全文；引文 ≤200 字符且可脱敏；导出默认不含敏感引文。
- **NFR-6** 全量数据可导出为纯文本 + JSONL，且不含节点 id。
- **NFR-7** 注入、召回、固化、写入各留审计行；按天切分、保留 30 天、只落文件。
- **NFR-8** 单进程插件形态：不监听端口、不起后台服务、不 spawn 子进程。
- **NFR-9** 常驻注入预算 ≤ 身份段 1200 字符 + 状态尾巴 30 token + 召回 ≤5 条。
- **NFR-10** Windows 单文件库的句柄锁语义：恢复必须先停库；快照目录创建撞名属预期分支。
